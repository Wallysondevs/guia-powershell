Internet (Invoke-WebRequest e Invoke-RestMethod)

Muitos serviços da internet têm uma API: um endereço que devolve dados em vez de uma página bonita. O Invoke-RestMethod busca esses dados e já entrega um objeto pronto. O Invoke-WebRequest traz a resposta completa, com código de status e cabeçalhos.

Você vai aprender
  • A consultar uma API com Invoke-RestMethod (o CEP, pelo ViaCEP).
  • A montar a URL com variáveis e parâmetros.
  • A ver o status e os cabeçalhos com Invoke-WebRequest.
  • A enviar dados (POST) em JSON.
  • A tratar erros de rede com try/catch.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: o balcão de informações

Você vai ao balcão e pergunta "qual o endereço do CEP 01310-100?". A atendente consulta e entrega um papel com a resposta organizada. A API é o balcão; o Invoke-RestMethod faz a pergunta e entrega o papel já como objeto.

1. Consultando um CEP

O ViaCEP é um serviço gratuito: você coloca o CEP na URL e ele devolve JSON.

PS> $cep = Invoke-RestMethod "https://viacep.com.br/ws/01310100/json/"
PS> $cep.logradouro
Avenida Paulista
PS> $cep.bairro
Bela Vista
PS> "$($cep.localidade)/$($cep.uf)"
São Paulo/SP
Invoke-RestMethod
Faz a requisição e, se a resposta for JSON, já converte para objeto (como o ConvertFrom-Json).
"https://viacep.com.br/ws/01310100/json/"
A URL: o CEP vai no meio, sem traço.
$cep.logradouro
Cada campo do JSON vira uma propriedade.

Veja só os campos principais:

PS> $cep | Select-Object cep, logradouro, bairro, localidade, uf

cep        : 01310-100
logradouro : Avenida Paulista
bairro     : Bela Vista
localidade : São Paulo
uf         : SP

2. Montando a URL com variáveis

PS> function Get-Cep { param([string]$Numero)
>>   $limpo = $Numero -replace '\D', ''
>>   Invoke-RestMethod "https://viacep.com.br/ws/$limpo/json/"
>> }
PS> (Get-Cep "20040-020").localidade
Rio de Janeiro

Quando a URL tem parâmetros depois do ?, use o -Body com uma hashtable num GET: o PowerShell monta o ?chave=valor&... para você, com os acentos e espaços codificados.

3. A resposta completa: Invoke-WebRequest

PS> $r = Invoke-WebRequest "https://viacep.com.br/ws/01310100/json/"
PS> $r.StatusCode
200
PS> $r.Headers["Content-Type"]
application/json; charset=utf-8
PS> $r.Content.Length -gt 0
True
PS> ($r.Content | ConvertFrom-Json).uf
SP
PropriedadeO que tem
StatusCodeO código da resposta: 200 é sucesso, 404 é "não encontrado", 500 é erro no servidor.
HeadersOs cabeçalhos (tipo do conteúdo, tamanho...).
ContentO corpo da resposta como texto.

Para baixar um arquivo, use Invoke-WebRequest URL -OutFile nome.ext.

4. Enviando dados (POST)

Para criar algo numa API, você envia um corpo em JSON com o método POST. O site httpbin.org devolve o que recebeu, ótimo para testar:

PS> $dados = @{ nome = "Ana"; curso = "PowerShell" } | ConvertTo-Json
PS> $resp = Invoke-RestMethod "https://httpbin.org/post" -Method Post -Body $dados -ContentType "application/json"
PS> $resp.json.nome
Ana
PS> $resp.json.curso
PowerShell

5. Quando dá erro na rede

Um CEP inexistente no ViaCEP não dá erro de rede: a API responde com o campo erro. Já uma URL errada dá erro HTTP, que você trata com try/catch:

PS> (Invoke-RestMethod "https://viacep.com.br/ws/99999999/json/").erro
true
PS> try { Invoke-RestMethod "https://httpbin.org/status/404" } catch { "Falhou com status $($_.Exception.Response.StatusCode.value__)" }
Falhou com status 404

Experimente: no seu terminal, consulte o CEP 01310100 no ViaCEP e mostre só o logradouro. (Aqui no navegador a internet é simulada e devolve o mesmo resultado.)

$url = "https://viacep.com.br/ws/01310100/json/"

$url = "https://viacep.com.br/ws/01310100/json/"
(Invoke-RestMethod $url).logradouro

Quando dá errado

Firewall, proxy ou sem internet

Se o computador não alcança o site, o erro fala de nome não resolvido ou de tempo esgotado. Teste o endereço no navegador e veja a aula de Rede.

Esquecer o -ContentType no POST

Muitas APIs só entendem o corpo se você disser que ele é JSON: -ContentType "application/json". Sem isso, a API pode responder que os campos vieram vazios.

Resumo

  • Invoke-RestMethod consulta APIs e já converte o JSON em objeto.
  • Invoke-WebRequest traz status, cabeçalhos e conteúdo; -OutFile baixa arquivos.
  • POST: -Method Post -Body (ConvertTo-Json) -ContentType "application/json".
  • Erros de rede e HTTP: try/catch.

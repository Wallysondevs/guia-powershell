ForEach-Object -Parallel

O ForEach-Object comum trata um item de cada vez. Com -Parallel, o PowerShell 7 trata vários ao mesmo tempo, cada um numa thread. Para tarefas que passam o tempo esperando (rede, disco, APIs), isso pode deixar o script muitas vezes mais rápido.

Você vai aprender
  • A usar ForEach-Object -Parallel.
  • A medir o ganho com Measure-Command.
  • A limitar quantos rodam juntos com -ThrottleLimit.
  • A levar variáveis para dentro com $using:.
  • Que a ordem do resultado pode mudar, e como lidar com isso.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: os caixas do supermercado

Com um caixa só, a fila anda de um em um. Abrindo quatro caixas, quatro clientes são atendidos ao mesmo tempo. O -ThrottleLimit é quantos caixas estão abertos.

1. Comparando o tempo

Cada item "espera" 1 segundo (como uma consulta a um site):

PS> (Measure-Command { 1..5 | ForEach-Object { Start-Sleep -Seconds 1 } }).Seconds
5
PS> (Measure-Command { 1..5 | ForEach-Object -Parallel { Start-Sleep -Seconds 1 } }).Seconds
1

Em sequência, 5 segundos. Em paralelo (até 5 de uma vez, o padrão), cerca de 1 segundo.

-Parallel { }
Roda o bloco para cada item, vários ao mesmo tempo. Dentro, $_ é o item, como sempre.
-ThrottleLimit
Quantos ao mesmo tempo. O padrão é 5.

2. A ordem pode mudar

PS> 1..6 | ForEach-Object -Parallel { Start-Sleep -Milliseconds (Get-Random -Minimum 10 -Maximum 300); "item $_" } | Sort-Object
item 1
item 2
item 3
item 4
item 5
item 6

Cada item termina quando termina, então a ordem de chegada varia a cada vez. Se a ordem importa, devolva objetos com um campo para ordenar e use Sort-Object no fim, como acima.

3. Variáveis de fora: $using:

Cada thread tem o seu próprio espaço de variáveis. Para usar uma variável da sua sessão, use $using::

PS> $fator = 3
PS> 10, 20, 30 | ForEach-Object -Parallel { [pscustomobject]@{ Valor = $_; Triplo = $_ * $using:fator } } | Sort-Object Valor

Valor Triplo
----- ------
   10     30
   20     60
   30     90

Experimente: use -Parallel com $using:saudacao para mostrar Olá, + cada nome.

$saudacao = "Olá"
"Ana", "Beto" | ForEach-Object { "$saudacao, $_" }

$saudacao = "Olá"
"Ana", "Beto" | ForEach-Object -Parallel { "$using:saudacao, $_" }

4. Limitando com -ThrottleLimit

PS> (Measure-Command { 1..6 | ForEach-Object -Parallel { Start-Sleep -Seconds 1 } -ThrottleLimit 2 }).Seconds
3

Com 2 de cada vez, 6 itens levam cerca de 3 segundos. Use um limite baixo quando cada tarefa pesa muito (disco, memória) ou quando um site limita quantas consultas você pode fazer.

5. Quando NÃO compensa

Criar threads tem um custo. Para tarefas rápidas, de pura conta, o paralelo fica mais lento:

PS> (Measure-Command { 1..200 | ForEach-Object { $_ * 2 } }).TotalMilliseconds -lt (Measure-Command { 1..200 | ForEach-Object -Parallel { $_ * 2 } }).TotalMilliseconds
True

Regra prática: paralelo para tarefas que esperam (rede, download, consulta remota). Para contas simples, o ForEach-Object comum ou o foreach são melhores.

Quando dá errado

Somar numa variável de fora

$total = 0; 1..10 | ForEach-Object -Parallel { $total += $_ } não funciona: cada thread tem a sua cópia. Devolva os valores e some depois: (1..10 | ForEach-Object -Parallel { $_ } | Measure-Object -Sum).Sum.

Funções da sessão não existem lá dentro

Uma função que você criou não está disponível dentro do -Parallel. Defina a função dentro do bloco, ou carregue de um módulo.

Resumo

  • -Parallel processa vários itens ao mesmo tempo (padrão: 5).
  • Compensa em tarefas que esperam; atrapalha em contas rápidas.
  • A ordem do resultado varia: ordene no fim se precisar.
  • Variáveis de fora entram com $using:; não some em variáveis compartilhadas.

Parâmetros dos Comandos

Na primeira aula você já usou um parâmetro: o -Format do Get-Date. Parâmetro é o “ajuste fino” do comando: a mesma ferramenta, com um detalhe a mais. Nesta aula você vai ver os três jeitos de passar esses ajustes — pelo nome, pela posição e como interruptor — e o que o PowerShell responde quando o nome sai errado, curto demais ou com o tipo errado.

Você vai aprender
  • O que é um parâmetro e como ele se escreve: um hífen, um nome, às vezes um valor.
  • Parâmetros nomeados, como -Path e -Filter.
  • Parâmetros posicionais: o mesmo comando, sem o nome, na ordem certa.
  • O switch (“interruptor”): um parâmetro que não leva valor, como o -Name.
  • Que o PowerShell aceita abreviações (-Pa, -Fi), desde que não sejam ambíguas.
  • Por que valor com espaço vai entre aspas.
  • Como ver a lista de parâmetros de um cmdlet, e a ler três erros reais de parâmetro.

As listas desta aula foram colhidas no PowerShell 7.7, numa pasta de teste C:\Users\ana\guia-ps-teste, com três arquivos vazios: a.txt, b.log e c.txt. A pasta foi apagada no fim. Quando o Windows PowerShell 5.1 responde diferente, a aula avisa.

A ideia: um pedido no balcão, com os detalhes

Volte ao balcão da aula anterior. “Eu quero um café” já é um pedido. Mas quase sempre você completa: “médio, com leite, sem açúcar”. O café é o comando; médio, com leite e sem açúcar são os parâmetros.

Alguns detalhes precisam de um valor (“médio”, “com leite”). Outros são só um sim ou não: “sem açúcar” — ou o açúcar vai, ou não vai. No PowerShell, esse sim-ou-não se chama switch (interruptor).

“Médio” (um detalhe com valor)Parâmetro nomeado: -Filter *.txt
O primeiro detalhe dito sem rótulo, na ordemParâmetro posicional: Get-ChildItem . *.txt

1. Pelo nome: -Path e -Filter

O Get-ChildItem lista o que tem numa pasta (aula completa em Listando (Get-ChildItem)). Aqui ele serve de exemplo de parâmetros. Estamos na pasta de teste, que tem a.txt, b.log e c.txt. Pedimos só os .txt:

PS C:\Users\ana\guia-ps-teste> Get-ChildItem -Path . -Filter *.txt

    Diretório: C:\Users\ana\guia-ps-teste

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a---          20/11/2026    17:13              0 a.txt
-a---          20/11/2026    17:13              0 c.txt
Get-ChildItem
O cmdlet: “obter os itens filhos”, ou seja, listar o conteúdo da pasta.
-Path .
O parâmetro -Path (“caminho”) e o valor ., que no PowerShell quer dizer a pasta onde você está agora.
-Filter *.txt
O parâmetro -Filter (“filtro”) e o valor *.txt: só os nomes que terminam com .txt. O * é o “qualquer coisa”.

Saíram a.txt e c.txt. O b.log existe na pasta, mas o filtro deixou ele de fora. A linha Diretório: C:\Users\ana\guia-ps-teste confirma onde a listagem foi feita. A hora 17:13 é a de quando os arquivos de teste foram criados; o Length 0 quer dizer que estão vazios.

Experimente: os três arquivos já estão sendo criados. Complete a segunda linha para listar só os nomes, com o switch -Name.

New-Item a.txt, b.log, c.txt -ItemType File | Out-Null
Get-ChildItem

New-Item a.txt, b.log, c.txt -ItemType File | Out-Null
Get-ChildItem -Name

2. Pela posição: o mesmo pedido, sem o rótulo

Muitos parâmetros aceitam ir sem o nome, desde que você respeite a ordem que o cmdlet espera. No Get-ChildItem, o primeiro valor é o caminho e o segundo é o filtro. As duas linhas abaixo pedem a mesma coisa:

Get-ChildItem -Path . -Filter *.txt
Get-ChildItem . *.txt

A segunda é a forma posicional: o ponto entra como caminho, o *.txt entra como filtro. A saída, nesta pasta de teste, é igual à do comando nomeado:

PS C:\Users\ana\guia-ps-teste> Get-ChildItem . *.txt

    Diretório: C:\Users\ana\guia-ps-teste

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a---          20/11/2026    17:13              0 a.txt
-a---          20/11/2026    17:13              0 c.txt

Os dois jeitos são certos. Nos scripts deste guia preferimos os nomes (-Path, -Filter): daqui a três meses, você (ou outra pessoa) lê e entende na hora. No terminal do dia a dia, a forma curta é prática.

3. O interruptor: -Name

Alguns parâmetros não levam valor. Só de aparecerem, ligam um modo. Isso é um switch. O -Name do Get-ChildItem pede “me dê só os nomes, sem a tabela”:

PS C:\Users\ana\guia-ps-teste> Get-ChildItem -Name
a.txt
b.log
c.txt

Agora saíram os três arquivos, um por linha, inclusive o b.log: não havia filtro. Sem o -Name, viria aquela tabela com modo, data, tamanho e nome. Com o -Name, só o nome. Você não escreve -Name $true nem -Name sim: o nome do parâmetro, sozinho, já liga o interruptor.

4. Abreviando o nome

O PowerShell deixa cortar o nome do parâmetro, desde que o pedaço não se confunda com outro. -Path pode virar -Pa, -Filter pode virar -Fi:

PS C:\Users\ana\guia-ps-teste> Get-ChildItem -Pa . -Fi *.txt

    Diretório: C:\Users\ana\guia-ps-teste

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a---          20/11/2026    17:13              0 a.txt
-a---          20/11/2026    17:13              0 c.txt

A saída é a mesma do comando com os nomes completos: só a.txt e c.txt. Nos scripts, escreva o nome inteiro. A abreviação é atalho de quem está digitando na hora — e, se for curta demais, o PowerShell reclama. Isso a gente vê daqui a pouco, no erro do -P.

5. Valor com espaço: use aspas

Se o valor de um parâmetro tem espaço, ponha-o entre aspas. Sem aspas, o PowerShell corta no espaço e entende como dois valores. O exemplo clássico no Windows é a pasta C:\Program Files:

Get-ChildItem -Path "C:\Program Files"
-Path
O parâmetro do caminho, pelo nome — aqui é ainda mais importante, para não haver dúvida.
"C:\Program Files"
O valor, entre aspas, vira um caminho só. Sem aspas, o PowerShell leria C:\Program e ainda Files como outra coisa.

Nesta aula a gente não lista o conteúdo dessa pasta: o exemplo é só para o papel das aspas. Caminhos com espaço voltam com mais calma em Caminhos no Windows e no Linux.

6. Como ver os parâmetros de um cmdlet

Você não precisa decorar a lista. Dá para perguntar quais parâmetros um comando aceita. A linha abaixo pede as chaves (os nomes) dos parâmetros do Get-ChildItem e mostra os 15 primeiros:

PS C:\Users\ana\guia-ps-teste> (Get-Command Get-ChildItem).Parameters.Keys | Select-Object -First 15

Filter
Include

Nessa lista aparecem os que você já usou (Path, Filter, Name) e outros que virão depois (Recurse, Force, LiteralPath…). Os últimos (Verbose, Debug, ErrorAction…) são parâmetros comuns: quase todo cmdlet os tem. O jeito mais amigável de ler a ficha de um parâmetro é o Get-Help da próxima aula, com -Parameter.

No Windows PowerShell 5.1 os 14 primeiros nomes desta lista são os mesmos, mas o 15º é ErrorVariable. O ProgressAction é parâmetro comum do PowerShell 7 e não existe no 5.1. Por isso ele também entra na briga do erro -P, logo abaixo.

Quando dá errado

O nome do parâmetro em português

O filtro se chama -Filter, em inglês. Se sair -Filtro:

PS C:\Users\ana\guia-ps-teste> Get-ChildItem -Filtro *.txt
Get-ChildItem: Não foi possível encontrar um parâmetro correspondente ao nome de parâmetro 'Filtro'.
Get-ChildItem:
Qual comando está reclamando.
Não foi possível encontrar um parâmetro correspondente ao nome de parâmetro 'Filtro'.
Não existe parâmetro chamado Filtro neste cmdlet. O nome oficial é -Filter.

Como resolver: use o nome em inglês, ou confira a lista com (Get-Command Get-ChildItem).Parameters.Keys ou com o Get-Help. Como no erro do cmdlet inventado, nada quebrou: é só corrigir e rodar de novo.

No Windows PowerShell 5.1 a mensagem é a mesma ideia, com outra frase (“Não é possível localizar um parâmetro que coincida com o nome de parâmetro 'Filtro'.”) e a ficha técnica comprida, com “No linha:1” e os tils embaixo do -Filtro.
Abreviação ambígua

Cortar demais também atrapalha. O -P sozinho serve para mais de um parâmetro:

PS C:\Users\ana\guia-ps-teste> Get-ChildItem -P .
Get-ChildItem: O parâmetro não pode ser processado porque o nome do parâmetro 'P' é ambíguo. As possíveis correspondências incluem: -Path -ProgressAction -PipelineVariable -LiteralPath.
O parâmetro não pode ser processado porque o nome do parâmetro 'P' é ambíguo.
“Ambíguo” quer dizer “pode ser mais de uma coisa”. O PowerShell não arrisca adivinhar.
As possíveis correspondências incluem: -Path -ProgressAction -PipelineVariable -LiteralPath.
Os quatro parâmetros que começam com P. Qualquer um poderia ser o -P. Por isso -Pa funciona para -Path: já não há empate.

Como resolver: escreva mais algumas letras (-Pa ou, melhor, -Path) até o nome ficar único.

No Windows PowerShell 5.1 a lista do mesmo erro é menor: -Path -PipelineVariable -LiteralPath. Não aparece o -ProgressAction, que é do PowerShell 7.
O valor do tipo errado

Alguns parâmetros só aceitam um tipo de valor. O -Year do Get-Date quer um número (o ano). Se vier um texto:

PS C:\Users\ana\guia-ps-teste> Get-Date -Year abc
Get-Date: Não é possível associar o parâmetro 'Year'. Cannot convert value "abc" to type "System.Int32". Error: "The input string 'abc' was not in a correct format."
Não é possível associar o parâmetro 'Year'.
O PowerShell entendeu o nome do parâmetro, mas não conseguiu usar o valor que você passou.
Cannot convert value "abc" to type "System.Int32".
Em inglês: não deu para converter abc para número inteiro (Int32). No PowerShell 7, este pedaço da mensagem veio em inglês, mesmo no Windows em português.
The input string 'abc' was not in a correct format.
A confirmação: abc não está num formato de número.

Como resolver: passe um ano de verdade, por exemplo Get-Date -Year 2026. O parâmetro estava certo; o valor é que não servia.

No Windows PowerShell 5.1 a mesma reclamação sai toda em português: “Não é possível converter o valor "abc" para o tipo "System.Int32". Erro: "A cadeia de caracteres de entrada não estava em um formato correto."”

Resumo

  • Parâmetro é o ajuste fino do cmdlet: um hífen, um nome e, na maior parte das vezes, um valor.
  • Na forma nomeada, o nome vai junto: Get-ChildItem -Path . -Filter *.txt.
  • Na forma posicional, o valor entra na ordem que o cmdlet espera: Get-ChildItem . *.txt. Nos scripts, prefira o nome completo.
  • Um switch (como o -Name) não leva valor: só de aparecer, liga um modo.
  • Dá para abreviar (-Pa, -Fi) enquanto o pedaço for único. -P é ambíguo.
  • Valor com espaço vai entre aspas: -Path "C:\Program Files".
  • Três erros comuns: nome inventado (-Filtro), abreviação ambígua (-P) e valor do tipo errado (-Year abc). Os três se resolvem corrigindo e rodando de novo.

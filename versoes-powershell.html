Windows PowerShell 5.1 × PowerShell 7

No Windows costumam existir dois PowerShell. O Windows PowerShell 5.1 já vem instalado e abre com o comando powershell. O PowerShell 7 (neste guia, a versão 7.7) é o atual, abre com pwsh e é o que este guia ensina. Os dois se parecem; esta aula mostra onde eles se diferenciam, com as saídas reais dos dois.

Você vai aprender
  • A distinguir o 5.1 (powershell, edição Desktop) do 7 (pwsh, edição Core).
  • A ler a tabela $PSVersionTable e o campo PSEdition.
  • Que a política de execução pode ser diferente em cada escopo (CurrentUser × LocalMachine) nos dois programas.
  • Três novidades que só existem no 7: Join-Path com 3 pastas, Split-Path -Extension e o cd -.
  • O que acontece no 5.1 se o pwsh ainda não estiver instalado.

As saídas do 7.7 e as do 5.1.19041 foram colhidas no mesmo Windows em português, na pasta da usuária fictícia ana. Quando uma linha muda de um para o outro, a aula mostra os dois.

A ideia: dois programas, o mesmo ofício

Pense em duas edições de um mesmo aplicativo de mensagens no celular: a que já veio de fábrica e a versão nova, que você instala depois. As duas enviam recado, mas a nova tem atalhos que a antiga não tem, e os menus não são idênticos.

Aqui é igual. O 5.1 é o que já veio no Windows. O 7 é a edição atual, feita para Windows, Linux e macOS. Este guia escreve para o 7. O 5.1 aparece nas notas, sempre que a resposta for diferente.

1. Quem está atendendo? $PSVersionTable

A variável automática $PSVersionTable é a ficha de identidade de quem está na janela. No PowerShell 7.7:

PS C:\Users\ana> $PSVersionTable

Name                           Value
----                           -----
PSVersion                      7.7.0
PSEdition                      Core
GitCommitId                    7.7.0
OS                             Microsoft Windows 10.0.19045
Platform                       Win32NT
PSCompatibleVersions           {1.0, 2.0, 3.0, 4.0…}
PSRemotingProtocolVersion      2.4
SerializationVersion           1.1.0.1
WSManStackVersion              3.0

Os campos que mais importam agora:

PSVersion 7.7.0
A versão. Se aparecer 7.7 (ou outra 7.x), você está no PowerShell 7.
PSEdition Core
A edição “Core”: é o PowerShell 7. No 5.1 este campo diz Desktop.
OS e Platform
Só o 7 traz esses dois na tabela: aqui, Windows. No editor deste guia, que roda um PowerShell 7 de Linux, o sistema aparece diferente — e tudo bem.

Dá para pedir só a edição:

PS C:\Users\ana> $PSVersionTable.PSEdition
Core

A mesma ficha, no Windows PowerShell 5.1 (versão 5.1.19041.6456):

PS C:\Users\ana> $PSVersionTable

Name                           Value
----                           -----
PSVersion                      5.1.19041.6456
PSEdition                      Desktop
PSCompatibleVersions           {1.0, 2.0, 3.0, 4.0...}
BuildVersion                   10.0.19041.6456
CLRVersion                     4.0.30319.42000
WSManStackVersion              3.0
PSRemotingProtocolVersion      2.3
SerializationVersion           1.1.0.1


PS C:\Users\ana> $PSVersionTable.PSEdition
Desktop
Repare no que muda na tabela: o 5.1 tem CLRVersion e BuildVersion, e não tem GitCommitId, OS nem Platform. O número da versão começa com 5.1, e a edição é Desktop. Se a sua janela mostrar isso, você não está no 7: feche e abra o PowerShell 7 (comando pwsh). Como instalar está na aula Instalar o PowerShell 7.

O 5.1 mora neste caminho, no Windows:

PS C:\Users\ana> (Get-Command powershell).Source
C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe

O 7 é o programa pwsh. O caminho exato depende de como ele foi instalado (Microsoft Store ou winget, por exemplo); o que importa é abrir pelo nome pwsh ou pelo atalho “PowerShell 7”.

Experimente: no editor (que é PowerShell 7), mostre só a edição, para conferir que é Core.

Write-Output "Qual é a edição?"

$PSVersionTable.PSEdition

2. A política de execução, por escopo

A política de execução (execution policy) diz se o PowerShell aceita rodar scripts .ps1 naquela máquina. Ela é definida em vários escopos (scope): da máquina, do seu usuário, só deste processo… O comando para ver todos é Get-ExecutionPolicy -List.

No PowerShell 7.7:

PS C:\Users\ana> Get-ExecutionPolicy -List

        Scope ExecutionPolicy
        ----- ---------------
MachinePolicy       Undefined
   UserPolicy       Undefined
      Process          Bypass
  CurrentUser       Undefined
 LocalMachine    RemoteSigned

No Windows PowerShell 5.1, no mesmo computador:

PS C:\Users\ana> Get-ExecutionPolicy -List

        Scope ExecutionPolicy
        ----- ---------------
MachinePolicy       Undefined
   UserPolicy       Undefined
      Process          Bypass
  CurrentUser    RemoteSigned
 LocalMachine       Undefined
CurrentUser
A política da sua conta. No 7 desta máquina estava Undefined (“não definido”). No 5.1 estava RemoteSigned (scripts baixados da internet precisam ser assinados; os que você mesmo escreveu rodam).
LocalMachine
A política da máquina toda. Aqui é o contrário: no 7 estava RemoteSigned; no 5.1, Undefined. Os dois programas não compartilham essa configuração: mudar no 7 não muda no 5.1.
Process Bypass
Vale só para o processo que estava rodando a coleta, e veio do jeito como ela foi chamada. Não é o padrão de uma janela que você abre no menu Iniciar: nessa janela, o Process costuma aparecer como Undefined. Olhe sobretudo CurrentUser e LocalMachine.
MachinePolicy e UserPolicy
Reservados para políticas de grupo da empresa. Undefined quer dizer que não há uma regra nesse nível.
Os valores acima são os desta máquina de laboratório. No seu computador os escopos podem estar diferentes, e tudo bem. O ponto da aula é: o 5.1 e o 7 têm listas próprias, e CurrentUser e LocalMachine podem não coincidir entre os dois.

3. Três coisas que só o 7 faz

A maior parte dos comandos desta escola funciona nos dois. Estas três, não: existem só no PowerShell 7. Por isso o guia ensina o 7.

Join-Path com três partes 7.7

Join-Path monta um caminho de pasta. No 5.1 ele aceita só duas partes (a base e um filho). No 7 você pode passar três ou mais de uma vez: a pasta, a subpasta e o arquivo, por exemplo. No editor deste guia (PowerShell 7 de Linux) o separador sai como /; no Windows sai como \. A ideia é a mesma.

Experimente: junte três partes de uma vez, docs, fotos e capa.jpg, com um único Join-Path.

Join-Path "docs" "fotos"

Join-Path "docs" "fotos" "capa.jpg"

Split-Path -Extension 7.7

Split-Path quebra um caminho e devolve um pedaço (o nome do arquivo, a pasta pai…). O parâmetro -Extension, que devolve só a extensão (.txt, .jpg…), existe só no 7. No 5.1 esse parâmetro não é aceito.

Missão: use Split-Path com -Extension para mostrar a extensão de nota.txt.

Split-Path "nota.txt"

Split-Path "nota.txt" -Extension

cd - 7.7

No 7, cd - (o cd é apelido de Set-Location) volta para a pasta anterior, como no Linux. No 5.1 esse atalho não existe: o - não é entendido como “a pasta de onde eu vim”. Se você precisa desse vai-e-volta, use o 7.

Quando dá errado

Você pediu o pwsh numa janela que só tem o 5.1

Se o PowerShell 7 ainda não está instalado (ou você abriu o 5.1 sem querer) e pede o caminho do pwsh, o 5.1 responde assim:

PS C:\Users\ana> (Get-Command pwsh).Source
Get-Command : O termo 'pwsh' não é reconhecido como nome de cmdlet, função, arquivo de script ou programa operável.
Verifique a grafia do nome ou, se um caminho tiver sido incluído, veja se o caminho está correto e tente novamente.
No linha:1 caractere:2
+ (Get-Command pwsh).Source
+  ~~~~~~~~~~~~~~~~
    + CategoryInfo          : ObjectNotFound: (pwsh:String) [Get-Command], CommandNotFoundException
    + FullyQualifiedErrorId : CommandNotFoundException,Microsoft.PowerShell.Commands.GetCommandCommand
O termo 'pwsh' não é reconhecido…
O 5.1 procurou um programa chamado pwsh e não achou. Ou o 7 não está instalado, ou esta janela não o enxerga.
No linha:1 caractere:2
Onde está o pedido: o Get-Command pwsh dentro dos parênteses. Os tils sublinham esse pedaço.
CommandNotFoundException
O nome técnico: “comando não encontrado”. Útil se você for pesquisar a mensagem.

Como resolver: instale o PowerShell 7 (aula Instalar o PowerShell 7), feche a janela e abra o atalho PowerShell 7. Confira com $PSVersionTable.PSVersion: tem que começar com 7.

Resumo

  • Existem dois programas: o Windows PowerShell 5.1 (powershell, edição Desktop) e o PowerShell 7 (pwsh, edição Core). Este guia ensina o 7.7.
  • $PSVersionTable mostra a versão. Se PSVersion começa com 5.1, você não está no 7.
  • A política de execução é por programa e por escopo: no laboratório, o 7 tinha LocalMachine = RemoteSigned e CurrentUser = Undefined; o 5.1 era o contrário. O Process = Bypass da coleta não é o padrão da sua janela.
  • Join-Path com 3 partes, Split-Path -Extension e cd - existem só no 7.
  • Se o 5.1 diz que pwsh “não é reconhecido”, instale o 7 e abra a janela certa.

Existe? Test-Path

Antes de ler, copiar ou apagar, vale a pergunta mais simples do guia: isso existe? O Test-Path ("teste o caminho") não mostra o conteúdo e não altera nada. Ele só responde True (verdadeiro, existe) ou False (falso, não existe). É o olho mágico da porta, não a chave.

Você vai aprender
  • A perguntar se um arquivo ou uma pasta existe, e a ler o True / False.
  • O parâmetro -PathType, para distinguir pasta (Container) de arquivo (Leaf).
  • A testar um padrão com *, a pasta pessoal $HOME, uma variável de ambiente e uma chave do Registro.
  • A usar o resultado num if, para o script decidir o que fazer.
  • Que um caminho inválido ou vazio, neste comando, também responde False — e não explode.

Todas as saídas desta aula foram colhidas no PowerShell 7.7 de um Windows em português, na pasta de teste da usuária fictícia ana. Antes dos testes, a pasta tinha o arquivo nota.txt e a pasta docs.

Pratique numa pasta de teste. Todos os exemplos desta aula foram rodados dentro de C:\Users\ana\guia-ps-teste. No seu computador, crie uma pasta só para treinar e trabalhe nela. Um jeito seguro: New-Item -ItemType Directory -Path (Join-Path $HOME 'guia-ps-teste') e depois Set-Location (Join-Path $HOME 'guia-ps-teste'). Assim você não mexe nas suas fotos, documentos ou no Windows. No fim da prática, apague só essa pasta.

A ideia: o olho mágico

Antes de abrir a porta, você olha pelo olho mágico: tem alguém do lado de fora, ou não? Você não abre, não conversa, não empurra. Só recebe um sim ou um não.

O Test-Path é esse olhar. Ele não lê o arquivo, não cria e não apaga. A resposta cabe numa palavra: True ou False.

1. Existe ou não existe

O nota.txt está na pasta de teste:

PS C:\Users\ana\guia-ps-teste> Test-Path nota.txt
True

Um nome que não está lá responde False, sem mensagem de erro:

PS C:\Users\ana\guia-ps-teste> Test-Path naoexiste.txt
False
Test-Path
Verbo Test ("teste") + Path ("caminho"): "esse caminho existe?".
nota.txt
O caminho a testar, aqui um arquivo na pasta atual.
True / False
True é "sim, existe". False é "não existe". Não é uma mensagem vermelha.

Essa diferença importa: o Get-Content naoexiste.txt reclama em vermelho; o Test-Path naoexiste.txt só diz False. Por isso ele é o guarda da porta nas outras aulas — você pergunta antes de ler ou apagar.

Experimente: o arquivo nota.txt já existe. Pergunte se ele existe com Test-Path.

Set-Content nota.txt "oi"
# teste se nota.txt existe

Set-Content nota.txt "oi"
Test-Path nota.txt

2. É pasta ou arquivo? -PathType

Às vezes existe um item com aquele nome, mas você quer saber de que tipo. O parâmetro -PathType filtra: Container é pasta (um "recipiente"); Leaf é arquivo (uma "folha" da árvore).

A pasta docs é um recipiente:

PS C:\Users\ana\guia-ps-teste> Test-Path docs -PathType Container
True

O nota.txt não é pasta:

PS C:\Users\ana\guia-ps-teste> Test-Path nota.txt -PathType Container
False

Mas ele é uma folha:

PS C:\Users\ana\guia-ps-teste> Test-Path nota.txt -PathType Leaf
True
PerguntaResposta no laboratório
Test-Path docs -PathType ContainerTrue — docs é pasta
Test-Path nota.txt -PathType ContainerFalse — arquivo não é pasta
Test-Path nota.txt -PathType LeafTrue — nota.txt é arquivo

Se o caminho não existe, as duas formas também respondem False.

3. Padrão, pasta pessoal e outros "drives"

O asterisco também vale aqui: *.txt pergunta se algum arquivo .txt existe na pasta atual.

PS C:\Users\ana\guia-ps-teste> Test-Path *.txt
True

A variável $HOME é a pasta pessoal de quem está logado (no laboratório, C:\Users\ana). Ela existe:

PS C:\Users\ana\guia-ps-teste> Test-Path $HOME
True

O mesmo comando testa coisas que não são arquivo de disco. Env:PATH é a variável de ambiente PATH; HKCU:\Software é uma chave do Registro do usuário atual. Os dois existiam no laboratório. Drives como Env: e HKCU: têm a aula Drives e Provedores.

PS C:\Users\ana\guia-ps-teste> Test-Path Env:PATH
True

PS C:\Users\ana\guia-ps-teste> Test-Path HKCU:\Software
True
O Test-Path Env:PATH não lista o valor da variável — só diz se ela existe. Isso é proposital: uma listagem aberta de Env: pode mostrar dados que não devem ir para um guia. Para ver um valor específico, use o nome completo (Env:PATH, Env:OS), nunca um "me mostra tudo".

4. Decidir com if

A resposta True ou False serve para o script escolher um caminho. A forma é: se existir, faça uma coisa; senão, faça outra. No laboratório, o nota.txt existia:

PS C:\Users\ana\guia-ps-teste> if (Test-Path nota.txt) { "Achei!" } else { "Não achei" }
Achei!
if (Test-Path nota.txt)
A pergunta entre parênteses. Se a resposta for True, o primeiro bloco roda.
{ "Achei!" }
O que fazer quando existe. As chaves delimitam o bloco.
else { "Não achei" }
O plano B, quando a resposta é False. Aqui ele não rodou.

As decisões e as chaves têm um grupo de aulas no Nível 1 (if). Por enquanto, basta ver que o Test-Path é a pergunta que alimenta o if.

Missão: se nota.txt existir, mostre Achei!; senão, mostre Não achei. Use if e Test-Path.

Set-Content nota.txt "oi"
# se o arquivo existir, escreva Achei!

Set-Content nota.txt "oi"
if (Test-Path nota.txt) { "Achei!" } else { "Não achei" }

Quando o caminho é estranho

Caminho inválido, caminho vazio

O Test-Path é manso: em vez de uma mensagem vermelha, ele costuma só responder False. Um nome com o caractere <, que o Windows não aceita em arquivo, veio False:

PS C:\Users\ana\guia-ps-teste> Test-Path 'C:\nome<invalido>.txt'
False

Uma string vazia (duas aspas sem nada no meio) também respondeu False, sem erro na tela:

PS C:\Users\ana\guia-ps-teste> Test-Path ''
False

Não é um "sim" disfarçado: o caminho vazio não aponta para arquivo nenhum. Se você esperava um True e veio False, confira se a variável que monta o caminho não chegou vazia, e se o nome não tem caractere proibido.

Formas diferentes de testar um caminho

FormaQuando usar
Test-Path -Path nota.txtO jeito deste guia nos scripts: o caminho com o nome do parâmetro.
Test-Path nota.txtA mesma pergunta, com o caminho na posição.
Test-Path nota.txt -PathType LeafTrue só se for um arquivo (não uma pasta).
Test-Path docs -PathType ContainerTrue só se for uma pasta (não um arquivo).
Test-Path Env:PATHConfere se a variável de ambiente PATH existe, sem listar o valor.

Missão final: teste se nota.txt é um arquivo com -PathType Leaf (deve ser True) e se ele é uma pasta com -PathType Container (deve ser False).

Set-Content nota.txt "oi"
# dois Test-Path: Leaf e Container

Set-Content nota.txt "oi"
Test-Path nota.txt -PathType Leaf
Test-Path nota.txt -PathType Container

Resumo

  • Test-Path só responde True ou False: existe ou não existe. Não lê e não altera.
  • -PathType Container pergunta se é pasta; Leaf, se é arquivo.
  • Dá para testar padrão (*.txt), $HOME, uma variável Env:NOME e uma chave do Registro.
  • O resultado alimenta um if: "se existir, faça isto".
  • Caminho inválido ou vazio, no PowerShell 7, veio False — não uma mensagem vermelha. Pratique numa pasta de teste.

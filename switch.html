PowerShell switch

Com if e elseif e else, a Ana já consegue decidir entre caminhos. Quando as opções se acumulam — sábado ou domingo, .jpg ou .txt, um, dois ou três — a cadeia de elseif fica longa. O switch (“chaveiro”, “seletor”) lista os casos num bloco só. Nesta aula você vai montar esse chaveiro e ver um detalhe importante: no PowerShell, todos os casos que combinam podem rodar, a menos que você peça para parar.

Você vai aprender
  • A forma básica do switch, com default para o que não combinou.
  • Que, sem break, todos os casos que combinam rodam — e como o break para no primeiro.
  • Que o switch não diferencia maiúsculas por padrão, e o -CaseSensitive que diferencia.
  • Os parâmetros -Wildcard (curinga, como *.jpg) e -Regex (expressão regular).
  • A passar uma lista na entrada: o switch olha item por item.
  • Os erros de sintaxe reais: bloco de ação faltando e parênteses faltando.

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows em português, na pasta pessoal da usuária fictícia ana.

A ideia: as gavetas do correio

Imagine o escaninho dos Correios. Cada carta é olhada e vai para a gaveta certa: “sábado”, “domingo”, ou a gaveta “outros” (o default). A diferença para uma bifurcação de estrada (if / elseif) é esta: no switch do PowerShell, uma carta pode combinar com mais de uma gaveta, e as duas recebem o recado, a menos que você diga “pode parar” com break.

No correioNo PowerShell
A carta da vezO valor entre parênteses: switch ($dia)
A etiqueta de uma gavetaUm caso: "sab" { ... }
O que fazer nessa gavetaO bloco entre chaves
A gaveta “outros”default { ... }
“Pode parar, já achou”break (aula break e continue)

1. O básico: casos e default

A Ana quer saber se o dia é fim de semana. No terminal, um bloco que ainda não fechou a chave { ganha linhas de continuação com >>:

PS C:\Users\ana> $dia = "sab"
PS C:\Users\ana> switch ($dia) {
>>     "sab" { "Fim de semana" }
>>     "dom" { "Fim de semana" }
>>     default { "Dia útil" }
>> }
Fim de semana
$dia = "sab"
A variável com o valor da vez. Aqui, sábado abreviado.
switch ($dia)
O seletor. O valor a comparar vai entre parênteses.
"sab" { "Fim de semana" }
Se o valor for sab, mostra Fim de semana. Cada caso é um valor (ou um teste) seguido de um bloco { }.
"dom" { "Fim de semana" }
O mesmo texto para domingo. Dois casos podem fazer a mesma coisa.
default { "Dia útil" }
A gaveta “outros”: só roda se nenhum caso combinou. Como “sab” combinou, este bloco não rodou.
>>
A continuação do console: o PowerShell espera o } que fecha o switch. Não faça parte do comando; some quando o bloco está num arquivo.

Experimente: troque o valor de $dia para um dia útil (por exemplo seg) e confira se o default mostra Dia útil.

$dia = "sab"
switch ($dia) {
    "sab" { "Fim de semana" }
    "dom" { "Fim de semana" }
    default { "Dia útil" }
}

$dia = "seg"
switch ($dia) {
    "sab" { "Fim de semana" }
    "dom" { "Fim de semana" }
    default { "Dia útil" }
}

2. Sem break, todos os que combinam rodam

Aqui está a diferença mais importante para quem vem de outras linguagens. O valor é 5. Há um caso literal 5 e um teste { $_ -gt 3 } (“o item da vez é maior que 3”). Os dois combinam, e os dois rodam. O default não roda, porque alguém já combinou.

PS C:\Users\ana> switch (5) { 5 { "cinco" } { $_ -gt 3 } { "maior que 3" } default { "outro" } }
cinco
maior que 3
PS C:\Users\ana> switch (5) { 5 { "cinco"; break } { $_ -gt 3 } { "maior que 3" } }
cinco
switch (5)
O valor da vez é o número 5. Também pode ser uma variável, como $dia.
5 { "cinco" }
Caso literal: combina porque o valor é 5.
{ $_ -gt 3 }
Caso em forma de teste: um bloco entre chaves no lugar do valor. O $_ é o item da vez (aula Variáveis Automáticas). Se o teste for verdadeiro, o bloco seguinte roda.
{ "cinco"; break }
Depois de mostrar cinco, o break (“pare”) encerra o switch. O teste $_ -gt 3 nem é olhado, e maior que 3 não aparece.
Se você esperava “só o primeiro caso”, coloque break no fim do bloco. Sem ele, o PowerShell continua testando os próximos.

3. Maiúsculas: o padrão e o -CaseSensitive

Por padrão, o switch não diferencia maiúsculas de minúsculas: "SAB" combina com "sab". Para diferenciar, use o parâmetro -CaseSensitive (“sensível a maiúsculas”).

PS C:\Users\ana> switch ("SAB") { "sab" { "casou sem diferenciar" } }
casou sem diferenciar
PS C:\Users\ana> switch -CaseSensitive ("SAB") { "sab" { "casou" } default { "não casou" } }
não casou

No segundo comando, "SAB" e "sab" já não são a mesma coisa, então o default mostrou não casou.

4. Curinga e expressão regular: -Wildcard e -Regex

Com -Wildcard, cada caso é um padrão com curingas, no estilo do -like (aula Comparando Textos): * é “qualquer sequência”. Assim a Ana classifica um arquivo pelo final do nome.

PS C:\Users\ana> switch -Wildcard ("foto.jpg") { "*.jpg" { "imagem" } "*.txt" { "texto" } }
imagem

Com -Regex, cada caso é uma expressão regular. No pedido pedido-2026-123, o padrão ^\w+-(\d{4}) pega as quatro letras do ano, e $Matches[1] devolve o que ficou entre parênteses:

PS C:\Users\ana> switch -Regex ("pedido-2026-123") { '^\w+-(\d{4})' { "ano: $($Matches[1])" } }
ano: 2026
-Regex
Pede para tratar cada caso como expressão regular, não como texto exato.
'^\w+-(\d{4})'
O padrão, em aspas simples (para a barra invertida não ser interpretada antes). ^ é o começo, \w+ é uma palavra, - é o hífen, e (\d{4}) captura quatro dígitos — o ano.
$($Matches[1])
O primeiro grupo capturado. Aqui, 2026. A variável automática $Matches é preenchida quando o padrão combina.

Missão: o switch abaixo compara o nome com o texto literal *.jpg, então não combina. Acrescente -Wildcard para foto.jpg ser classificado como imagem.

switch ("foto.jpg") { "*.jpg" { "imagem" } "*.txt" { "texto" } }

switch -Wildcard ("foto.jpg") { "*.jpg" { "imagem" } "*.txt" { "texto" } }

5. Uma lista na entrada

Se você passa vários valores, o switch percorre cada um, como um foreach embutido. O $_ é o item da vez. O 1 e o 2 têm caso próprio; o 3 cai no default:

PS C:\Users\ana> switch (1, 2, 3) { 1 { "um" } 2 { "dois" } default { "outro: $_" } }
um
dois
outro: 3

Formas diferentes de decidir

FormaQuando usar
if / elseif / elsePoucos caminhos, ou condições bem diferentes umas das outras. Roda um bloco só.
switch ($valor) { ... }Vários casos sobre o mesmo valor. Lembre do break se quiser parar no primeiro que combinar.
switch -WildcardPadrões de nome de arquivo, como *.jpg.
switch -RegexQuando você precisa extrair um pedaço (um ano, um código) com um padrão.
switch (1, 2, 3) { ... }A mesma tabela de casos, aplicada a cada item de uma lista.

Quando dá errado

Os dois erros abaixo são ParserError: erros de leitura do código. O PowerShell recusa a linha antes de rodar qualquer coisa, mostra a linha (Line | 1) e aponta o problema com um tracinho ~. Esses erros saem em inglês no PowerShell 7.7, mesmo num Windows em português.

Faltou o bloco de ação

O caso "sab" veio seguido de um texto, e não de um { ... }:

PS C:\Users\ana> switch ($dia) { "sab" "Fim de semana" }
ParserError:
Line |
   1 |  switch ($dia) { "sab" "Fim de semana" }
     |                       ~
     | Missing statement block in switch statement clause.
ParserError
Erro de leitura do código: o PowerShell recusou a linha antes de rodar qualquer coisa.
Line | 1
A linha com o problema, repetida ao lado.
~
O tracinho aponta logo depois de "sab", onde o PowerShell esperava o bloco { }.
Missing statement block in switch statement clause
Quer dizer que falta um bloco de comandos na cláusula do switch. Cada caso precisa de um bloco entre chaves: "sab" { "Fim de semana" }, não "sab" "Fim de semana".

Como resolver: coloque a ação entre { }.

Faltaram os parênteses do valor

O valor foi escrito sem ( ), como switch $dia { ... }:

PS C:\Users\ana> switch $dia { "sab" { "x" } }
ParserError:
Line |
   1 |  switch $dia { "sab" { "x" } }
     |        ~
     | A switch statement must have one of the following:  '-file file_name' or '( expression )'.
~
O tracinho aponta logo depois da palavra switch, onde deveriam começar os parênteses.
A switch statement must have one of the following: '-file file_name' or '( expression )'
Quer dizer que um switch precisa de uma destas formas: -file e o nome de um arquivo, ou ( expressão ). O valor a comparar vai entre parênteses: switch ($dia) { ... }.

Como resolver: escreva switch ($dia), com parênteses. (O -file lê os casos de um arquivo; não foi coletado nesta aula.)

Referência rápida

Você digitaO que faz
switch ($dia) { "sab" { ... } default { ... } }Compara $dia com cada caso; o default pega o que não combinou.
break dentro de um casoPara o switch naquele caso, e não testa os seguintes.
switch -CaseSensitive ("SAB") { "sab" { ... } }Diferencia maiúsculas. Sem o parâmetro, "SAB" combina com "sab".
switch -Wildcard ("foto.jpg") { "*.jpg" { ... } }Compara com curingas.

foreach ($dia in "sab", "seg") {
    # complete com switch
}

foreach ($dia in "sab", "seg") {

}

Resumo

  • switch ($valor) { "caso" { ... } default { ... } } compara o valor com cada caso. O valor vai entre parênteses; a ação, entre chaves.
  • Sem break, todos os casos que combinam rodam. Com break, para no primeiro.
  • Por padrão não diferencia maiúsculas. Use -CaseSensitive quando importar a diferença.
  • -Wildcard aceita curingas (*.jpg); -Regex aceita expressão regular e preenche $Matches.
  • Uma lista na entrada (switch (1, 2, 3)) aplica os mesmos casos a cada item.
  • Erros de sintaxe no 7.7 saem em inglês: bloco de ação faltando, ou parênteses faltando em volta do valor.

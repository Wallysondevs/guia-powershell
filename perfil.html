O Perfil ($PROFILE)

Toda vez que você abre o PowerShell, ele procura um arquivo chamado perfil e roda o que estiver lá dentro. É onde você guarda seus apelidos, funções favoritas e ajustes, para não ter que digitar tudo de novo a cada janela.

Você vai aprender
  • Onde fica o perfil ($PROFILE).
  • A criar o arquivo se ele não existir.
  • O que vale a pena colocar no perfil.
  • A recarregar o perfil sem fechar a janela.
  • A abrir o PowerShell sem o perfil (-NoProfile).

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: arrumar a mesa de trabalho

Quem chega no escritório e sempre arruma a mesa do mesmo jeito ganharia tempo se a mesa já estivesse arrumada. O perfil é isso: o PowerShell "arruma a mesa" para você toda vez que abre.

1. Onde fica o perfil

PS> $PROFILE
C:\Users\ana\Documents\PowerShell\Microsoft.PowerShell_profile.ps1
PS> Test-Path $PROFILE
False
$PROFILE
Caminho do perfil do usuário atual para este programa (o "CurrentUserCurrentHost").
Test-Path
True se o arquivo existe; numa instalação nova, normalmente False.

O perfil do PowerShell 7 fica em Documentos\PowerShell. O do Windows PowerShell 5.1 fica em Documentos\WindowsPowerShell: são arquivos diferentes.

2. Os quatro perfis

Existem quatro perfis, do mais geral ao mais específico:

PS> $PROFILE | Select-Object AllUsersAllHosts, AllUsersCurrentHost, CurrentUserAllHosts, CurrentUserCurrentHost | Format-List

AllUsersAllHosts       : C:\Program Files\WindowsApps\Microsoft.PowerShell_7.7.0.0_x64__8wekyb3d8bbwe\profile.ps1
AllUsersCurrentHost    : C:\Program Files\WindowsApps\Microsoft.PowerShell_7.7.0.0_x64__8wekyb3d8bbwe\Microsoft.PowerSh
                         ell_profile.ps1
CurrentUserAllHosts    : C:\Users\ana\Documents\PowerShell\profile.ps1
CurrentUserCurrentHost : C:\Users\ana\Documents\PowerShell\Microsoft.PowerShell_profile.ps1

Para uso pessoal, use o $PROFILE (o último). Os de "AllUsers" ficam na pasta de instalação e exigem administrador.

3. Criando o perfil

if (-not (Test-Path $PROFILE)) {
    New-Item -ItemType File -Path $PROFILE -Force
}
notepad $PROFILE      # ou: code $PROFILE
-Force
Cria também as pastas que faltarem no caminho.
notepad $PROFILE
Abre o perfil no Bloco de Notas para editar.

4. O que colocar no perfil

Um exemplo de perfil simples:

# Apelidos
Set-Alias -Name np -Value notepad

# Funções
function cdp { Set-Location "$HOME\Projetos" }
function ll { Get-ChildItem -Force @args }

# Prompt mais curto: só o nome da pasta
function prompt { "PS $(Split-Path -Leaf (Get-Location))> " }

# Histórico com sugestões em lista
Set-PSReadLineOption -PredictionViewStyle ListView
  • Apelidos e funções curtas que você usa todo dia.
  • Ajustes do PSReadLine (cores, previsão, teclas).
  • Import-Module de módulos que você sempre usa.
Perfil lento = terminal lento Tudo no perfil roda a cada janela aberta. Evite comandos demorados (consultas de rede, listar pastas enormes). Se o PowerShell começou a demorar para abrir, o perfil é o primeiro suspeito.

5. Recarregando sem fechar a janela

Depois de editar, carregue o perfil de novo com dot-source:

. $PROFILE

O ponto e o espaço na frente rodam o arquivo na sessão atual, então as funções e apelidos passam a existir aqui. Veja a aula Dot-source.

6. Abrindo sem o perfil

Para testar se um problema vem do perfil, ou para rodar scripts de forma previsível:

PS> pwsh -NoProfile -Command '"Sem perfil: rápido e limpo"'
Sem perfil: rápido e limpo

Experimente: o arquivo perfil-teste.ps1 define a função oi. Carregue-o com dot-source (. .\perfil-teste.ps1) e chame oi.

Set-Content perfil-teste.ps1 'function oi { "Olá do perfil" }'
oi

Set-Content perfil-teste.ps1 'function oi { "Olá do perfil" }'
. .\perfil-teste.ps1
oi

Quando dá errado

"não pode ser carregado porque a execução de scripts foi desabilitada"

O perfil é um script e obedece à política de execução. Veja Política de Execução.

Editei o perfil e nada mudou

O perfil só roda ao abrir o PowerShell. Rode . $PROFILE ou abra uma janela nova. Confira também se você editou o perfil do PowerShell 7 e não o do 5.1.

A pasta Documentos está no OneDrive

Com o OneDrive ligado, o $PROFILE pode apontar para OneDrive\Documentos\PowerShell. Use sempre $PROFILE em vez de escrever o caminho na mão.

Resumo

  • O perfil é um script que roda toda vez que o PowerShell abre.
  • O caminho está em $PROFILE; crie com New-Item -Force.
  • Coloque apelidos, funções e ajustes, nada demorado.
  • . $PROFILE recarrega; pwsh -NoProfile abre sem ele.

Rede (Test-Connection e Test-NetConnection)

"A internet caiu ou é só aquele site?" O PowerShell responde com comandos de diagnóstico: o ping (Test-Connection), o teste de porta (Test-NetConnection), a consulta de DNS e as informações das placas de rede.

Você vai aprender
  • A fazer um ping com Test-Connection e responder sim/não com -Quiet.
  • A testar se uma porta está aberta.
  • A consultar o DNS com Resolve-DnsName.
  • A ver as placas de rede e a configuração de IP.
  • Um roteiro de diagnóstico passo a passo.

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: bater na porta

Para saber se alguém está em casa você bate na porta (ping). Para saber se a loja está aberta, você tenta entrar pela porta certa (teste de porta). Rede é isso: perguntar e ver se alguém responde.

1. O ping: Test-Connection

PS> Test-Connection learn.microsoft.com -Count 2 | Select-Object Ping, Status, Latency

Ping  Status Latency
----  ------ -------
   1 Success      51
   2 Success      51
PS> Test-Connection learn.microsoft.com -Count 1 -Quiet
True
PS> Test-Connection endereco-que-nao-existe.invalid -Count 1 -Quiet
False
-Count 2
Quantas tentativas (o padrão é 4).
Latency
Tempo de resposta em milissegundos.
-Quiet
Responde só True ou False: ótimo para if.
Ping bloqueado não é site fora do ar Muitos servidores ignoram ping de propósito. Se o ping falha, teste a porta antes de concluir que o site caiu.

2. Testando uma porta

Sites usam a porta 443 (HTTPS). Teste se ela responde:

PS> Test-NetConnection learn.microsoft.com -Port 443 -InformationLevel Quiet
True
PS> Test-Connection learn.microsoft.com -TcpPort 443
True
Test-NetConnection -Port
Tenta abrir uma conexão naquela porta. True se conseguiu.
-InformationLevel Quiet
Só True/False. Sem isso, mostra um relatório com endereços.
Test-Connection -TcpPort
O mesmo teste, só no PowerShell 7.

3. DNS: nome para endereço

PS> (Resolve-DnsName learn.microsoft.com -Type A -ErrorAction SilentlyContinue | Measure-Object).Count -gt 0
True
PS> Resolve-DnsName nao-existe.invalid -ErrorAction SilentlyContinue
PS> $?
True

Se o DNS não resolve, nada funciona pelo nome, mesmo com a internet ligada.

4. As placas de rede

PS> Get-NetAdapter | Select-Object Name, Status, LinkSpeed

Name     Status       LinkSpeed
----     ------       ---------
Ethernet Disconnected 0 bps
Wi-Fi    Up           260 Mbps

Get-NetIPConfiguration           # IP, gateway e DNS de cada placa
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias, IPAddress
Privacidade Esses comandos mostram os endereços da sua rede. Cuidado ao colar a saída em fóruns.

5. Roteiro de diagnóstico

function Test-Internet {
    [pscustomobject]@{
        Placa   = [bool](Get-NetAdapter | Where-Object Status -eq 'Up')
        DNS     = [bool](Resolve-DnsName learn.microsoft.com -ErrorAction SilentlyContinue)
        HTTPS   = Test-NetConnection learn.microsoft.com -Port 443 -InformationLevel Quiet
    }
}
Test-Internet

Se Placa é False, o problema é o cabo ou o Wi-Fi. Se só DNS falha, troque o servidor DNS. Se só HTTPS falha, pode ser firewall ou o site fora do ar.

Experimente: escreva, numa string, o comando que faz um ping com uma tentativa em learn.microsoft.com e responde só True ou False. O simulador do guia não imita esse comando; depois, rode-o de verdade no seu Windows.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = 'Test-Connection learn.microsoft.com -Count 1 -Quiet'
Write-Output $comando

Quando dá errado

"Não foi possível resolver o nome"

O DNS não achou o endereço: nome digitado errado ou problema de DNS. Teste com Resolve-DnsName.

Ping falha, mas o site abre no navegador

O servidor bloqueia ping. Use Test-NetConnection -Port 443.

Test-NetConnection demora muito

Quando a porta está fechada, ele espera o tempo limite. No PowerShell 7, Test-Connection -TcpPort com -TimeoutSeconds é mais rápido.

Resumo

  • Test-Connection é o ping; -Quiet responde True/False.
  • Test-NetConnection -Port testa se um serviço responde.
  • Resolve-DnsName confere o DNS.
  • Get-NetAdapter e Get-NetIPConfiguration mostram a rede local.

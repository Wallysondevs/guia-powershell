Política de Execução (Execution Policy)

Na primeira vez que você tenta rodar um script no Windows, pode aparecer um erro dizendo que a execução de scripts está desabilitada. Isso é a política de execução: uma trava de segurança que decide quais scripts podem rodar. Aqui você entende o que ela faz e como liberar do jeito certo.

Você vai aprender
  • A ver a política atual com Get-ExecutionPolicy.
  • O que significam Restricted, RemoteSigned, AllSigned, Unrestricted e Bypass.
  • Os escopos (CurrentUser, LocalMachine, Process).
  • A liberar scripts só para você, sem ser administrador.
  • A desbloquear um arquivo baixado com Unblock-File.

só Windows As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. A ideia: o porteiro do prédio

A política de execução é um porteiro. Ele não impede você de fazer nada que você realmente queira (não é uma barreira de segurança contra quem já tem acesso ao computador), mas evita que um script baixado sem querer rode sozinho. Você escolhe o quão rigoroso o porteiro é.

Só no Windows A política de execução existe no Windows. No Linux e no macOS o PowerShell 7 sempre usa Unrestricted e ela não pode ser mudada.

1. Vendo a política atual

PS> Get-ExecutionPolicy
Bypass
PS> Get-ExecutionPolicy -List

        Scope ExecutionPolicy
        ----- ---------------
MachinePolicy       Undefined
   UserPolicy       Undefined
      Process          Bypass
  CurrentUser       Undefined
 LocalMachine    RemoteSigned
Get-ExecutionPolicy
A política que vale agora (a "vencedora").
-List
Mostra a política de cada escopo, do mais forte (em cima) para o mais fraco.
Undefined
Nada definido naquele escopo; vale o de baixo.

Na saída acima, a política vencedora é Bypass porque aquela janela foi aberta com pwsh -ExecutionPolicy Bypass, o que vale só para ela (escopo Process, veja a seção 5). Sem isso, valeria o RemoteSigned do escopo LocalMachine, o padrão do PowerShell 7 no Windows.

2. Os níveis

PolíticaO que permite
RestrictedNenhum script roda; só comandos digitados. Padrão do Windows PowerShell em máquinas cliente.
RemoteSignedScripts seus rodam; scripts baixados da internet precisam de assinatura digital. Padrão do PowerShell 7 no Windows.
AllSignedTodo script precisa ser assinado, até os seus.
UnrestrictedTudo roda; avisa antes de rodar algo baixado.
BypassNada é bloqueado e não há aviso. Usado por programas que chamam o PowerShell.
UndefinedSem política naquele escopo.

3. Os escopos

EscopoVale paraPrecisa de administrador?
MachinePolicy / UserPolicyDefinidos por Política de Grupo (empresa)Não dá para mudar pelo PowerShell
ProcessSó esta janela do PowerShellNão
CurrentUserVocê, em todas as janelasNão
LocalMachineTodos os usuários do computadorSim

4. Liberando scripts só para você

O jeito recomendado para estudar e para o dia a dia: RemoteSigned no escopo CurrentUser. Não precisa de administrador e não afeta outros usuários:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

O PowerShell pede confirmação. Para só testar sem mudar nada, use -WhatIf:

PS> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -WhatIf
What If: Executando a operação "Set-ExecutionPolicy" no destino "RemoteSigned".

5. Só nesta janela: -Scope Process

Quer rodar um script uma vez, sem mudar nada permanente? Use o escopo Process. Quando a janela fecha, a mudança some:

Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process

Ou chame o PowerShell já com a política:

pwsh -ExecutionPolicy Bypass -File .\meu-script.ps1

6. Arquivos baixados da internet

O Windows marca arquivos baixados com uma "etiqueta" escondida (a Zone.Identifier). Com RemoteSigned, um script com essa etiqueta não roda. Se você confia no arquivo, tire a etiqueta:

PS> Set-Content baixado.ps1 '"Rodei!"'
PS> Get-Item baixado.ps1 -Stream * | Select-Object Stream, Length

Stream Length
------ ------
:$DATA     10

Unblock-File .\script-baixado.ps1
-Stream *
Mostra os "fluxos" do arquivo. Um arquivo baixado tem o fluxo Zone.Identifier além do :$DATA.
Unblock-File
Remove a marca de "veio da internet". Só faça isso com arquivos de origem confiável.

Como o baixado.ps1 do exemplo foi criado ali mesmo, e não baixado, só aparece o fluxo :$DATA (os 10 bytes do texto). Faça o teste com um arquivo baixado pelo navegador para ver a linha Zone.Identifier.

Experimente: escreva, numa string, o comando que mostra a política de execução que vale agora. O simulador do guia não imita esse comando; depois, rode-o de verdade no seu Windows.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = 'Get-ExecutionPolicy'
Write-Output $comando

Quando dá errado

"a execução de scripts foi desabilitada neste sistema"

A política é Restricted (comum no Windows PowerShell 5.1). Rode Set-ExecutionPolicy RemoteSigned -Scope CurrentUser.

"não está assinado digitalmente"

O script veio da internet e a política é RemoteSigned. Se confia na origem, rode Unblock-File nele.

"A configuração foi substituída por uma política definida em um escopo mais específico"

Um escopo mais forte (por exemplo Process ou uma Política de Grupo) está vencendo. Veja com Get-ExecutionPolicy -List.

Acesso negado ao mudar LocalMachine

Mudar o escopo LocalMachine exige abrir o PowerShell como administrador. Para uso pessoal, prefira -Scope CurrentUser.

Resumo

  • A política de execução decide quais scripts podem rodar no Windows.
  • RemoteSigned no escopo CurrentUser é a escolha recomendada.
  • -Scope Process vale só para a janela atual.
  • Unblock-File libera um arquivo baixado em que você confia.

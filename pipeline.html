O Pipeline (|)

O sinal | (a "barra em pé", chamada de pipe) liga comandos: o que sai de um entra no próximo. É como uma linha de montagem. No PowerShell, o que corre pela esteira são objetos inteiros, e não pedaços de texto.

Você vai aprender
  • O que o | faz: entrega a saída de um comando ao próximo.
  • A montar uma "linha de montagem" com dois, três ou mais comandos.
  • Que cada objeto passa pela esteira um de cada vez.
  • O que é o $_: o objeto da vez dentro de um bloco { }.
  • A quebrar um pipeline comprido em várias linhas.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional. Os quadros marcados Saída no Windows (PowerShell 7.7) foram colhidos num Windows 10 em português, com o nome do computador e o da usuária trocados por exemplos (NOTEBOOK e ana).

A ideia: a linha de montagem

Numa fábrica de sucos, as laranjas passam por uma esteira: a primeira máquina lava, a segunda corta, a terceira espreme. Cada máquina recebe o que a anterior soltou. O pipeline é essa esteira: cada comando é uma máquina, e o | é o pedaço de esteira entre elas.

1. Dois comandos ligados

O 1..10 solta os números de 1 a 10. O Where-Object (aula Where-Object) deixa passar só os que cumprem uma condição:

PS> 1..10 | Where-Object { $_ -gt 7 }
8
9
10
1..10
A primeira máquina: solta os números de 1 a 10, um por um.
|
O pipe: entrega cada número para o próximo comando.
Where-Object { ... }
A segunda máquina: um filtro. Só deixa passar quem cumpre a condição entre chaves.
$_
"O objeto da vez". A cada número que chega, $_ vale esse número.
$_ -gt 7
A condição: maior que 7 (aula Comparações).

2. Três máquinas: filtrar, ordenar, pegar os primeiros

Você pode emendar quantos comandos quiser. Aqui: notas da turma, só as aprovadas (7 ou mais), da maior para a menor, e as duas primeiras:

PS> $notas = 6.5, 9, 7, 4, 10, 8.5
PS> $notas | Where-Object { $_ -ge 7 } | Sort-Object -Descending | Select-Object -First 2
10
9

Leia da esquerda para a direita: pegue as notas → deixe só as maiores ou iguais a 7 → ordene da maior para a menor → fique com as 2 primeiras.

3. Objetos correndo pela esteira

O que passa pelo pipe são objetos com campos. Por isso a máquina seguinte pode olhar um campo pelo nome:

PS> $produtos = @(
>>   [pscustomobject]@{ Nome = "Arroz"; Preco = 25.9 }
>>   [pscustomobject]@{ Nome = "Café"; Preco = 18.5 }
>>   [pscustomobject]@{ Nome = "Azeite"; Preco = 42 }
>> )
PS> $produtos | Where-Object { $_.Preco -lt 30 } | ForEach-Object { $_.Nome }
Arroz
Café
$_.Preco
O campo Preco do produto da vez. Não é preciso recortar texto: o campo tem nome.
ForEach-Object { $_.Nome }
Para cada produto que passou no filtro, solta só o nome (aula ForEach-Object).

Experimente: complete o pipeline para mostrar só os nomes dos produtos que custam menos de 30 (Arroz e Café).

$produtos = @(
    [pscustomobject]@{ Nome = "Arroz"; Preco = 25.9 }
    [pscustomobject]@{ Nome = "Café"; Preco = 18.5 }
    [pscustomobject]@{ Nome = "Azeite"; Preco = 42 }
)
$produtos | ForEach-Object { $_.Nome }

$produtos = @(
    [pscustomobject]@{ Nome = "Arroz"; Preco = 25.9 }
    [pscustomobject]@{ Nome = "Café"; Preco = 18.5 }
    [pscustomobject]@{ Nome = "Azeite"; Preco = 42 }
)
$produtos | Where-Object { $_.Preco -lt 30 } | ForEach-Object { $_.Nome }

4. Um de cada vez

O pipeline não espera a primeira máquina terminar tudo para começar a segunda. Cada objeto atravessa a esteira inteira antes do próximo entrar. Dá para ver isso mostrando uma mensagem em cada etapa (o Write-Host escreve direto na tela, sem mandar nada pela esteira):

PS> 1..3 | ForEach-Object { Write-Host "saiu $_"; $_ } | ForEach-Object { "chegou $_" }
saiu 1
chegou 1
saiu 2
chegou 2
saiu 3
chegou 3

Primeiro o 1 sai e chega, depois o 2, depois o 3. Isso economiza memória quando a lista é enorme.

5. Pipeline comprido: quebre a linha depois do |

Se a linha ficar grande, termine a linha com o | e continue embaixo. O PowerShell entende que o comando não acabou (o >> é o prompt de continuação):

PS> 1..20 |
>>   Where-Object { $_ % 5 -eq 0 } |
>>   ForEach-Object { $_ * 10 }
50
100
150
200

Quando dá errado

$_ fora do bloco 
PS> 1..3 | Where-Object $_ -gt 1
Where-Object: Não é possível validar o argumento no parâmetro 'Property'. The argument is null or empty. Provide an argument that is not null or empty, and then try the command again.

O $_ só existe dentro das chaves { } do bloco. Fora delas ele está vazio, e o Where-Object recebe um nome de propriedade vazio: o PowerShell recusa o comando com um erro dizendo que o argumento do parâmetro Property está vazio. Escreva sempre Where-Object { $_ -gt 1 }.

Referência rápida

Você digitaO que faz

1..30

1..30 | Where-Object { $_ % 15 -eq 0 } | ForEach-Object { $_ }

Resumo

  • O | entrega a saída de um comando ao próximo, como uma esteira.
  • Pelo pipe correm objetos, e cada comando pode olhar os campos deles.
  • Dentro de { }, $_ é o objeto da vez.
  • Os objetos passam um de cada vez pela esteira inteira.
  • Para quebrar a linha, termine com | e continue embaixo.

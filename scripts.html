Scripts (.ps1)

Até aqui você digitou um comando de cada vez. Um script é um arquivo de texto com extensão .ps1 que guarda vários comandos para rodar de uma vez, quantas vezes quiser. É a receita de bolo escrita: em vez de lembrar cada passo, você só manda executar.

Você vai aprender
  • A criar um arquivo .ps1 e rodar com .\nome.ps1.
  • Por que o .\ na frente é obrigatório.
  • A usar comentários e $PSScriptRoot.
  • A passar valores para o script.
  • A rodar um script de outra pasta e pelo pwsh -File.

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: a receita escrita

Quem faz bolo toda semana não decora a receita: escreve num papel. O script é esse papel. Você escreve os comandos uma vez e o PowerShell lê o arquivo de cima para baixo, executando linha por linha.

1. Criando o primeiro script

Vamos criar uma pasta de testes e, nela, um arquivo ola.ps1. Você pode usar o Bloco de Notas, o VS Code ou o próprio PowerShell:

PS> New-Item -ItemType Directory -Path scripts-teste -Force | Out-Null
PS> Set-Location scripts-teste
PS> Set-Content ola.ps1 @'
>> # Meu primeiro script
>> "Olá! Hoje é $((Get-Date).ToString('dddd'))."
>> "Você está na pasta: $(Split-Path -Leaf (Get-Location))"
>> '@
PS> Get-Content ola.ps1
# Meu primeiro script
"Olá! Hoje é $((Get-Date).ToString('dddd'))."
"Você está na pasta: $(Split-Path -Leaf (Get-Location))"
Set-Content ola.ps1
Grava o texto no arquivo ola.ps1 (cria se não existir).
@' ... '@
Texto de várias linhas, guardado exatamente como está (sem trocar variáveis).
#
Começa um comentário: o PowerShell ignora o resto da linha.

2. Rodando com .\

PS> .\ola.ps1
Olá! Hoje é sábado.
Você está na pasta: scripts-teste
.\
"Nesta pasta". O PowerShell não roda scripts da pasta atual só pelo nome, por segurança.

Se você digitar só ola.ps1, sem o .\, o PowerShell procura um comando com esse nome nas pastas do sistema e não acha:

PS> ola.ps1
ola.ps1: O termo "ola.ps1" não é reconhecido como um nome de um cmdlet, função, arquivo de script ou programa executável.
Verifique a ortografia do nome ou, se um caminho foi incluído, verifique se o caminho está correto e tente novamente.

Isso é proposital: impede que um arquivo malicioso com nome de comando (por exemplo dir.ps1) seja executado sem querer.

Política de execução No Windows, a primeira tentativa de rodar um script pode ser bloqueada pela política de execução. Veja a aula Política de Execução para entender e liberar com segurança.

3. Comentários

# Comentário de uma linha

<#
  Comentário de várias linhas.
  Ótimo para explicar o que o script faz.
#>
"O código continua aqui"

Comente o porquê, não o óbvio. # soma 1 em cima de $i++ não ajuda ninguém; # o sistema conta a partir de 1 ajuda.

4. $PSScriptRoot: a pasta do script

Um script costuma ler arquivos que ficam ao lado dele. Se você usar caminhos relativos, eles dependem de onde o terminal está, não de onde o script está. A variável $PSScriptRoot resolve isso:

PS> Set-Content dados.txt "maçã`nbanana`nuva"
PS> Set-Content contar.ps1 @'
>> $arquivo = Join-Path $PSScriptRoot "dados.txt"
>> $linhas = Get-Content $arquivo
>> "O arquivo tem $($linhas.Count) linhas."
>> '@
PS> Set-Location ..
PS> .\scripts-teste\contar.ps1
O arquivo tem 3 linhas.
PS> Set-Location scripts-teste
$PSScriptRoot
A pasta onde o script está gravado. Só tem valor dentro de um script.
Join-Path
Junta pasta e arquivo com a barra certa.

5. Passando valores para o script

Os valores digitados depois do nome do script chegam na variável $args. O jeito profissional é um bloco param(), que você conhece em detalhes na aula Parâmetros de Script:

PS> Set-Content saudar.ps1 @'
>> param([string]$Nome = "mundo", [int]$Vezes = 1)
>> 1..$Vezes | ForEach-Object { "Olá, $Nome!" }
>> '@
PS> .\saudar.ps1
Olá, mundo!
PS> .\saudar.ps1 -Nome Ana -Vezes 2
Olá, Ana!
Olá, Ana!

6. Rodando de fora: pwsh -File

Para rodar um script a partir do Prompt de Comando, do Agendador de Tarefas ou de um atalho, chame o PowerShell 7 com -File:

PS> pwsh -NoProfile -File .\saudar.ps1 -Nome Carla
Olá, Carla!
pwsh
O PowerShell 7.
-NoProfile
Não carrega o seu perfil (fica mais rápido e previsível).
-File
Roda o script e repassa os parâmetros.

Experimente: o script saudar.ps1 já está gravado. Rode-o passando o nome Ana.

Set-Content saudar.ps1 'param($Nome = "mundo") "Olá, $Nome!"'

Set-Content saudar.ps1 'param($Nome = "mundo") "Olá, $Nome!"'
.\saudar.ps1 -Nome Ana

Quando dá errado

"O termo 'ola.ps1' não é reconhecido"

Faltou o .\ na frente, ou você não está na pasta do script. Confira com Get-Location e rode .\ola.ps1.

"não pode ser carregado porque a execução de scripts foi desabilitada"

É a política de execução. Veja a aula Política de Execução; o comum é Set-ExecutionPolicy RemoteSigned -Scope CurrentUser.

Acentos aparecendo errado

O PowerShell 7 grava e lê UTF-8 por padrão. Se o arquivo foi salvo em outra codificação por um editor antigo, salve de novo como UTF-8. Se o script também vai rodar no Windows PowerShell 5.1, prefira "UTF-8 com BOM".

Caminho com espaço

.\Meus Scripts\a.ps1 quebra no espaço. Use aspas e o operador de chamada: & ".\Meus Scripts\a.ps1".

Referência rápida

Você digitaO que faz
.\script.ps1Roda o script da pasta atual.
& "C:\caminho com espaço\s.ps1"Roda um caminho entre aspas.
. .\funcoes.ps1Dot-source: carrega o script na sessão atual.
pwsh -File s.ps1 -Param valorRoda de fora do PowerShell.
$PSScriptRootPasta do script.
$PSCommandPathCaminho completo do script.

Missão final: crie conta.ps1 que lê lista.txt usando $PSScriptRoot e mostra 3 linhas. Depois rode o script.

Set-Content lista.txt "a`nb`nc"
Set-Content conta.ps1 '"$((Get-Content lista.txt).Count) linhas"'
.\conta.ps1

Set-Content lista.txt "a`nb`nc"
Set-Content conta.ps1 '"$((Get-Content (Join-Path $PSScriptRoot lista.txt)).Count) linhas"'
.\conta.ps1

Resumo

  • Um script é um arquivo .ps1 com comandos.
  • Rode com .\nome.ps1; o .\ é obrigatório por segurança.
  • $PSScriptRoot aponta para a pasta do script.
  • param() recebe valores; pwsh -File roda de fora.

Lendo uma Mensagem de Erro

Erro em vermelho assusta, mas ele é um bilhete do PowerShell explicando o que deu errado. Nesta aula você aprende a ler esse bilhete em partes e a descobrir, com calma, o que ele quer dizer.

Você vai aprender
  • As partes de uma mensagem de erro do PowerShell 7.
  • A diferença entre erro que para tudo e erro que deixa seguir.
  • Onde o PowerShell guarda o último erro ($Error[0]).
  • Como pegar só o texto do erro e o tipo dele.
  • Os erros mais comuns e como resolver cada um.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: o bilhete do mecânico

Quando você deixa o carro na oficina, o mecânico entrega um bilhete: "Peça: freio. Problema: pastilha gasta." A mensagem de erro do PowerShell é igual: primeiro vem a categoria do problema, depois dos dois-pontos vem a explicação.

1. Um erro de verdade

Tente transformar a palavra abc num número inteiro:

PS> [int]"abc"
InvalidArgument: Cannot convert value "abc" to type "System.Int32". Error: "The input string 'abc' was not in a correct format."
InvalidArgument
A categoria do erro: um argumento (valor) inválido.
Cannot convert value "abc" to type "System.Int32"
O que aconteceu: não deu para converter abc em Int32 (o [int]).
Error: "The input string 'abc' was not in a correct format."
O detalhe: o texto não está num formato de número.

Algumas mensagens ficam em inglês mesmo com o Windows em português, porque vêm de partes do .NET que não são traduzidas. Outras, como "O termo ... não é reconhecido", aparecem em português. Nos dois casos a leitura é a mesma: categoria, dois-pontos, explicação.

2. Outros erros comuns

PS> 10 / 0
RuntimeException: Attempted to divide by zero.

PS> "Ana".Maiusculas()
InvalidOperation: Method invocation failed because [System.String] does not contain a method named 'Maiusculas'.

PS> Set-StrictMode -Version Latest
PS> $frutas = "maçã", "uva"
PS> $frutas[5]
OperationStopped: Index was outside the bounds of the array.
PS> Set-StrictMode -Off
CategoriaO que costuma ser
InvalidArgumentUm valor que não serve: texto onde precisava de número, data inválida.
RuntimeExceptionAlgo impossível na hora de rodar, como dividir por zero.
InvalidOperationVocê pediu algo que aquele objeto não sabe fazer (um método que não existe).
OperationStoppedA operação parou no meio, por exemplo uma posição fora do array.
ParserErrorO PowerShell nem conseguiu entender a linha: faltou fechar } ou ), ou um operador está escrito errado.

Experimente: o código abaixo divide por zero e o erro aparece. Troque o divisor por 2 para dar 5, e depois volte para 0 e veja a mensagem. Para a missão, deixe a linha que mostra a mensagem guardada em $Error[0] funcionando: a saída precisa mostrar Attempted to divide by zero.

$resultado = 10 / 2
$resultado

try { 10 / 0 } catch { }
$Error[0].Exception.Message

4. O último erro fica guardado

Todo erro vai para a variável automática $Error. O mais recente é sempre o $Error[0]:

PS> $Error.Clear()
PS> [int]"doze"
InvalidArgument: Cannot convert value "doze" to type "System.Int32". Error: "The input string 'doze' was not in a correct format."
PS> $Error.Count
1
PS> $Error[0].Exception.Message
Cannot convert value "doze" to type "System.Int32". Error: "The input string 'doze' was not in a correct format."
$Error.Clear()
Esvazia a lista (só para o exemplo ficar limpo).
$Error.Count
Quantos erros estão guardados.
$Error[0]
O erro mais recente. É um objeto ErrorRecord.
.Exception.Message
Só o texto da mensagem, sem a categoria.

Quer saber o tipo exato? Peça o tipo da exceção:

PS> $Error[0].Exception.GetType().FullName
System.Management.Automation.RuntimeException

Quando dá errado

Achar que o erro é "do computador"

Quase sempre o erro aponta exatamente o problema. Leia a categoria, depois a frase até o fim. Cannot convert value "abc" to type "System.Int32" está dizendo: "você me deu abc e eu precisava de um número".

Ler só a primeira linha de um erro grande

Em erros de sintaxe (ParserError) o PowerShell mostra a linha do problema e marca a posição com ~~~~. A dica de verdade fica embaixo das marcas. Leia o quadro inteiro antes de mudar o código.

Resumo

  • Mensagem de erro = categoria + dois-pontos + explicação.
  • Há erros que encerram e erros que deixam o comando seguir.
  • $Error[0] é o último erro; .Exception.Message é só o texto dele.
  • Leia a mensagem até o fim: ela quase sempre diz o que corrigir.

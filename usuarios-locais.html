Usuários e Grupos Locais

Até aqui a Ana mexia em arquivos, pastas e texto. Agora o assunto muda de tamanho: vamos falar das contas que existem neste computador — quem pode entrar, se a conta está ligada e em que grupo ela está. Os cmdlets desta aula alteram o Windows e pedem uma sessão de administrador. Por isso a prática usa um usuário descartável, criado e apagado no mesmo roteiro, e nunca toca nas contas reais.

Você vai aprender
  • A família de cmdlets do módulo Microsoft.PowerShell.LocalAccounts só Windows.
  • A criar o usuário descartável guia-teste com New-LocalUser e consultá-lo só pelo nome com Get-LocalUser.
  • A alterar a descrição (Set-LocalUser), desativar e ativar (Disable-LocalUser / Enable-LocalUser) e renomear (Rename-LocalUser).
  • A colocar a conta só no grupo Usuários — nunca em Administradores — e a consultar o membro pelo nome.
  • A apagar a conta no fim e conferir que ela sumiu.
  • Os erros reais em português: conta que já existe, nome que não existe e nome inválido.

Todas as saídas desta aula foram colhidas no PowerShell 7.7 de um Windows em português, na pasta pessoal da usuária fictícia ana, no computador NOTEBOOK, em uma sessão de administrador. O editor do guia é um PowerShell 7 de Linux: esses cmdlets não existem lá. As missões desta aula pedem que você escreva o comando certo, sem tentá-lo no editor.

Esses comandos pedem administrador e mudam o sistema. Pratique somente com um usuário descartável, com um nome combinado — nesta aula, guia-teste. Antes de criar, confira se esse nome ainda não existe. Nunca rode Get-LocalUser ou Get-LocalGroup sem -Name, nem Get-LocalGroupMember sem -Member: isso lista as contas reais do computador. Nunca adicione ninguém ao grupo Administradores. No fim, apague o que criou e confira que sumiu.

A ideia: um crachá de visitante

Pense na portaria de um prédio. Cada pessoa ganha um crachá com nome, se está válido e a que grupo pertence: moradores, visitantes, administração. Você não imprime um crachá de administrador para treinar, nem pede a lista de todos os moradores. Você faz um crachá temporário de visitante, confere só esse nome, e no fim devolve e rasga o crachá.

No PowerShell é igual. O crachá é a conta local. O grupo permitido nesta aula é Usuários. O crachá temporário se chama guia-teste.

1. A família de comandos

Esses cmdlets vêm do módulo Microsoft.PowerShell.LocalAccounts, que existe só no Windows. Pedimos só os nomes:

PS C:\Users\ana> Get-Command -Module Microsoft.PowerShell.LocalAccounts | Select-Object -ExpandProperty Name
Add-LocalGroupMember
Disable-LocalUser
Enable-LocalUser
Get-LocalGroup

Remove-LocalGroup

Remove-LocalUser

Rename-LocalUser

A regra de sempre: Verbo-Substantivo. Get consulta, New cria, Set altera, Remove apaga, Rename troca o nome, Enable / Disable ligam e desligam a conta, Add coloca no grupo. Nesta aula a gente usa só o usuário guia-teste e o grupo Usuários. Os cmdlets de criar ou apagar grupo ficam de fora de propósito.

2. Criar o usuário descartável

O New-LocalUser cria a conta. No laboratório ela nasceu com o nome guia-teste, sem senha, com uma descrição e um nome completo:

PS C:\Users\ana> New-LocalUser -Name "guia-teste" -NoPassword -Description "Usuário de teste do guia" -FullName "Guia Teste"

Name       Enabled Description
----       ------- -----------
guia-teste True    Usuário de teste do guia
New-LocalUser
"Novo usuário local." Só existe no Windows e pede administrador.
-Name "guia-teste"
O nome da conta, entre aspas. Use um nome combinado, que ninguém mais use neste computador.
-NoPassword
"Sem senha." Serve só para uma conta de teste que você vai apagar no mesmo roteiro. Não é prática para uma conta de verdade.
-Description
Um recado curto, para você reconhecer a conta depois.
-FullName
O nome completo que aparece em algumas telas do Windows. Aqui: Guia Teste.
Enabled True
A conta nasceu ativada. Sem senha e ativada é arriscado: no laboratório ela foi desativada mais abaixo, ainda no mesmo roteiro. Não deixe uma conta de teste assim no seu computador.

3. Consultar só pelo nome

O Get-LocalUser -Name devolve uma conta. Sem -Name, ele listaria todas as contas locais — inclusive as reais. Esta aula nunca faz isso.

PS C:\Users\ana> Get-LocalUser -Name "guia-teste"

Name       Enabled Description
----       ------- -----------
guia-teste True    Usuário de teste do guia

A tabelinha padrão mostra só nome, se está ativada e a descrição. Para ver mais campos, peça pelo nome com Select-Object:

PS C:\Users\ana> Get-LocalUser -Name "guia-teste" | Select-Object Name, Enabled, Description, FullName, PasswordRequired, LastLogon

Name             : guia-teste
Enabled          : True
Description      : Usuário de teste do guia
FullName         : Guia Teste
PasswordRequired : False
LastLogon        :
PasswordRequired : False
Não há senha obrigatória, por causa do -NoPassword.
LastLogon
Veio vazio: essa conta ainda não fez logon.

Nenhum identificador interno da conta (o SID) aparece aqui, e não deve aparecer na sua prática também: não peça essa propriedade.

Experimente: o editor do guia não tem contas do Windows, então não rode o cmdlet. Escreva, numa string, o comando que consulta somente o usuário guia-teste pelo nome, e deixe o Write-Output mostrar a string.

Atenção: rodar este script no seu PowerShell só imprime um texto: ele não cria, não altera e não apaga conta nenhuma. Não copie o texto da string para executar. Para praticar de verdade, use o roteiro completo da aula (cria, usa, apaga e confere, com finally), num PowerShell de administrador.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = 'Get-LocalUser -Name "guia-teste"'
Write-Output $comando

4. Alterar, desativar e renomear

O Set-LocalUser muda um dado da conta. A descrição foi trocada, e a consulta seguinte (só o campo Description) confirma:

PS C:\Users\ana> Set-LocalUser -Name "guia-teste" -Description "Descrição alterada"
PS C:\Users\ana> (Get-LocalUser -Name "guia-teste").Description
Descrição alterada

Os parênteses pegam o objeto daquela conta; o ponto .Description lê só a descrição. O Set-LocalUser em si não escreve nada na tela quando dá certo.

Desativar a conta é o jeito de invalidar o crachá sem apagá-lo. Ativar recoloca. O campo Enabled vira False ou True:

PS C:\Users\ana> Disable-LocalUser -Name "guia-teste"
PS C:\Users\ana> (Get-LocalUser -Name "guia-teste").Enabled
False
PS C:\Users\ana> Enable-LocalUser -Name "guia-teste"
PS C:\Users\ana> (Get-LocalUser -Name "guia-teste").Enabled
True
PS C:\Users\ana> Disable-LocalUser -Name "guia-teste"

No fim desse bloco a conta voltou a ficar desativada, que é o estado mais seguro enquanto o teste continua.

O Rename-LocalUser troca o nome. No laboratório o nome virou guia-teste2 e, na hora seguinte, voltou a ser guia-teste — para o resto da aula usar o nome combinado:

PS C:\Users\ana> Rename-LocalUser -Name "guia-teste" -NewName "guia-teste2"
PS C:\Users\ana> Get-LocalUser -Name "guia-teste2" | Select-Object Name

Name
----
guia-teste2

PS C:\Users\ana> Rename-LocalUser -Name "guia-teste2" -NewName "guia-teste"

5. Só o grupo Usuários

Um grupo é um conjunto de contas com a mesma permissão. Nesta aula a conta de teste entra somente no grupo Usuários. Nunca use Administradores: isso daria à conta o mesmo poder de quem administra o computador.

PS C:\Users\ana> Add-LocalGroupMember -Group 'Usuários' -Member 'guia-teste'
PS C:\Users\ana> Get-LocalGroupMember -Group 'Usuários' -Member 'guia-teste'

ObjectClass Name                       PrincipalSource
----------- ----                       ---------------
Usuário     NOTEBOOK\guia-teste Local

PS C:\Users\ana> Remove-LocalGroupMember -Group 'Usuários' -Member 'guia-teste'
Add-LocalGroupMember
"Adicionar membro ao grupo local." -Group é o grupo; -Member é a conta. Os dois vêm pelo nome, literal.
Get-LocalGroupMember -Member
Consulta só aquele membro. Sem -Member, o comando listaria o grupo inteiro — e aí apareceriam contas reais. Não faça isso.
NOTEBOOK\guia-teste
O computador do laboratório se chama NOTEBOOK; a conta é guia-teste. A origem Local quer dizer que a conta mora neste computador, não num domínio.
Remove-LocalGroupMember
Tira a conta do grupo, ainda pelo nome literal. Também não escreve nada quando dá certo.

Quando dá errado

A conta já existe

Tentamos criar de novo o guia-teste, que ainda estava no computador:

PS C:\Users\ana> New-LocalUser -Name "guia-teste" -NoPassword
New-LocalUser: O usuário guia-teste já existe.
New-LocalUser:
Qual comando reclamou.
O usuário guia-teste já existe.
A mensagem veio em português. Nada foi sobrescrito: a conta antiga continuou lá.

Como resolver: use outro nome, ou trabalhe com a conta que já existe — e, se ela for a de teste, apague-a no fim. Antes de criar, consulte com Get-LocalUser -Name "guia-teste".

O nome não existe

Pedimos uma conta que nunca foi criada, e depois tentamos apagá-la:

PS C:\Users\ana> Get-LocalUser -Name "nao-existe"
Get-LocalUser: Usuário nao-existe não encontrado.
PS C:\Users\ana> Remove-LocalUser -Name "nao-existe"
Remove-LocalUser: Usuário nao-existe não encontrado.

A grafia é a mesma nos dois: Usuário <nome> não encontrado. Confira se o nome está certo (incluindo hífen) antes de criar ou de apagar.

O nome é inválido

Uma barra não pode entrar no nome de uma conta:

PS C:\Users\ana> New-LocalUser -Name "nome/invalido" -NoPassword
New-LocalUser: O nome nome/invalido é inválido.

O Windows recusou o nome e não criou conta nenhuma. Evite caracteres como /, \, colchetes e espaços no começo ou no fim. Um nome simples, com letras, números e hífen, como guia-teste, funciona.

6. Apagar no fim e conferir

O Remove-LocalUser apaga a conta. No laboratório, depois de tirar a conta do grupo, ela foi removida pelo nome literal, sem curinga:

PS C:\Users\ana> Remove-LocalUser -Name "guia-teste"

Quando dá certo, não aparece mensagem. O próximo passo é conferir que a conta sumiu, com o mesmo Get-LocalUser -Name "guia-teste".

Saída ilustrativa. Essa conferência final foi rodada no laboratório, mas a mensagem não foi capturada nesta rodada. O bloco abaixo não é uma saída colhida. O texto segue o padrão real já colhido nesta aula, no erro com o nome nao-existe: Get-LocalUser: Usuário <nome> não encontrado. 
PS C:\Users\ana> Get-LocalUser -Name "guia-teste"
Get-LocalUser: Usuário guia-teste não encontrado. « ilustrativo
Ensaiar antes de apagar: -WhatIf. Quase todo cmdlet que muda o sistema aceita -WhatIf ("e se?"): ele conta o que faria e não faz. É um hábito seguro, principalmente com Remove-LocalUser. Nesta aula não há uma saída colhida desse ensaio, então pratique o parâmetro no seu Windows, só com a conta de teste, e veja a frase "What If" antes de apagar de verdade.

Formas diferentes de consultar um usuário

Get-CimInstance Win32_UserAccount -Filter "Name='guia-teste'"só Windows A mesma conta, via CIM, já filtrada pelo nome. Também é só leitura.
net user guia-testesó Windows A consulta clássica daquela conta. Também é só leitura, e também exige o nome.

Resumo

  • Os cmdlets de contas locais são só Windows, pedem administrador e mudam o sistema. Pratique só com um usuário descartável, como guia-teste, e apague-o no fim.
  • Consulte sempre pelo nome: Get-LocalUser -Name. Sem -Name, a lista mostra as contas reais.
  • New-LocalUser cria, Set-LocalUser altera, Disable-LocalUser / Enable-LocalUser desativam e ativam, Rename-LocalUser troca o nome, Remove-LocalUser apaga.
  • A conta de teste entra só no grupo Usuários. Nunca use Administradores. Get-LocalGroupMember também vai com -Member, para não listar o grupo inteiro.
  • Os erros desta aula saíram em português: conta que já existe, nome não encontrado e nome inválido.
  • -WhatIf ensaia uma remoção sem apagar. É um hábito seguro antes de qualquer Remove.

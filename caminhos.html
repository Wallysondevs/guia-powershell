Caminhos no Windows e no Linux

Um caminho é o endereço de um arquivo ou de uma pasta. No Windows ele usa a barra invertida (\) e uma letra de disco (C:); no Linux, a barra comum (/) e um começo em /. O PowerShell 7 roda nos dois, e por isso esta aula ensina a montar e a desmontar caminhos com comandos que funcionam nos dois sistemas — em vez de colar as barras na mão.

Você vai aprender
  • A diferença entre caminho absoluto e caminho relativo.
  • O . (pasta atual) e o .. (pasta de cima).
  • O Resolve-Path, que transforma um caminho relativo no endereço completo.
  • Que no Windows a barra comum / também funciona.
  • O Join-Path, que junta pedaços no separador certo — no 7, com três (ou mais) partes de uma vez.
  • O Split-Path, que devolve o nome (-Leaf), a pasta (-Parent) ou a extensão (-Extension, só no 7).
  • O $HOME e o $env:USERPROFILE, que apontam para a pasta pessoal no Windows.

Todas as saídas desta aula foram colhidas no PowerShell 7.7 de um Windows em português, na pasta de teste C:\Users\ana\guia-ps-teste, que tinha a subpasta docs e o arquivo docs\a.txt. Não temos saídas de um laboratório Linux nesta aula: a diferença do Linux fica explicada no texto, sem inventar um prompt.

A ideia: endereço completo × "dois quarteirões à frente"

Se você manda uma carta, escreve o endereço inteiro: cidade, rua, número. Isso é um caminho absoluto: começa no disco (C:\) e não depende de onde você está. Se você diz "a padaria, dois quarteirões à frente", a pessoa precisa saber onde você está para entender. Isso é um caminho relativo.

No dia a diaNo PowerShell (Windows)
O endereço completo da cartaC:\Users\ana\guia-ps-teste\docs\a.txt (absoluto)
"A padaria, dois quarteirões à frente"docs\a.txt (relativo à pasta atual)
"Aqui mesmo". — a pasta atual
"Um andar acima".. — a pasta-mãe

No Linux, o mesmo arquivo numa pasta de teste da Ana teria um endereço no estilo /home/ana/guia-ps-teste/docs/a.txt, com barra comum e sem letra de disco. O jeito de pensar (absoluto × relativo, . e ..) é o mesmo.

1. Do relativo para o absoluto: Resolve-Path

Estando em guia-ps-teste, o caminho relativo docs\a.txt vira o endereço completo:

PS C:\Users\ana\guia-ps-teste> Resolve-Path docs\a.txt

Path
----
C:\Users\ana\guia-ps-teste\docs\a.txt
Resolve-Path
"Resolva o caminho": tome este endereço (relativo ou com . e ..) e me devolva o absoluto, já conferido no disco.
docs\a.txt
O caminho relativo: a pasta docs, dentro da atual, e o arquivo a.txt dentro dela.
C:\Users\ana\guia-ps-teste\docs\a.txt
A resposta: o mesmo arquivo, com o endereço completo a partir do disco C:.

O Resolve-Path só funciona se o caminho já existe. Se o arquivo ainda não foi criado, ele dá erro (você vê isso no fim da aula). Para montar o endereço de um arquivo novo, use o Join-Path.

2. O vai-e-volta do . e do ..

Dá para escrever um caminho "andando" pelas pastas: . é "aqui", .. é "sobe um nível". Este aqui parece uma volta desnecessária, mas o PowerShell desembaraça e chega no mesmo arquivo:

PS C:\Users\ana\guia-ps-teste> Resolve-Path .\docs\..\docs\a.txt

Path
----
C:\Users\ana\guia-ps-teste\docs\a.txt
.
A pasta atual, guia-ps-teste.
docs
Desce para docs.
..
Sobe de volta para guia-ps-teste.
docs\a.txt
Desce de novo para docs e pega o a.txt.

É o mesmo endereço de antes. No dia a dia você não escreve uma volta dessas de propósito, mas ela aparece quando um script junta pedaços e você quer conferir "isso cai onde, afinal?".

3. A barra comum também vale no Windows

O Windows prefere a barra invertida \, mas o PowerShell aceita a barra comum / nos caminhos. O Get-Item ("obter o item") pega o arquivo e o Select-Object FullName mostra o nome completo:

PS C:\Users\ana\guia-ps-teste> Get-Item docs/a.txt | Select-Object FullName

FullName
--------
C:\Users\ana\guia-ps-teste\docs\a.txt

Pedimos docs/a.txt (barra comum) e a resposta veio no jeito do Windows, com \. Nos scripts, o mais seguro ainda é deixar o Join-Path escolher o separador: o mesmo script roda no Windows e no Linux.

Experimente: use o Join-Path e o Split-Path -Leaf para obter só o nome do arquivo a.txt, sem depender da barra do sistema.

Join-Path 'docs' 'a.txt'

Split-Path (Join-Path 'docs' 'a.txt') -Leaf

4. Juntando pedaços: Join-Path 7.7

O Join-Path ("juntar caminho") recebe as partes e coloca o separador certo entre elas. No PowerShell 7 ele aceita três ou mais pedaços de uma vez:

PS C:\Users\ana\guia-ps-teste> Join-Path $HOME 'docs' 'a.txt'
C:\Users\ana\docs\a.txt
Join-Path
O montador de endereços.
$HOME
A pasta pessoal (aqui, C:\Users\ana).
'docs' e 'a.txt'
Os pedaços seguintes. O PowerShell 7 encaixa os três, com \ no Windows.

O resultado foi C:\Users\ana\docs\a.txt — a pasta docs da Ana, não a da pasta de teste. É isso mesmo: o Join-Path junta o que você passou, sem olhar se o arquivo existe. Por isso ele é o comando certo para montar o caminho de um arquivo que você ainda vai criar.

Se você estiver no 5.1, ou quiser um jeito que funciona nas duas versões, junte de dois em dois:

PS C:\Users\ana\guia-ps-teste> Join-Path (Join-Path $HOME 'docs') 'a.txt'
C:\Users\ana\docs\a.txt

O resultado, no 7.7, é o mesmo. No 5.1, o de três partes não roda:

No Windows PowerShell 5.1 o Join-Path só aceita dois pedaços. O terceiro vira um argumento a mais, e aparece o erro de parâmetro posicional: 
PS C:\Users\ana\guia-ps-teste> Join-Path $HOME 'docs' 'a.txt'
Join-Path : Não é possível localizar um parâmetro posicional que aceite o argumento 'a.txt'.
Use o jeito aninhado, Join-Path (Join-Path $HOME 'docs') 'a.txt', que funciona nos dois.

5. Desmontando: Split-Path

O contrário do Join-Path é o Split-Path ("dividir caminho"): ele devolve um pedaço. Nos exemplos abaixo, $T é a pasta de teste, C:\Users\ana\guia-ps-teste.

O -Leaf ("folha") é o nome no fim, o arquivo ou a última pasta:

PS C:\Users\ana\guia-ps-teste> Split-Path "$T\docs\a.txt" -Leaf
a.txt

O -Parent ("pai") é a pasta que contém esse item:

PS C:\Users\ana\guia-ps-teste> Split-Path "$T\docs\a.txt" -Parent
C:\Users\ana\guia-ps-teste\docs

O -Extension ("extensão") devolve o .txt, o .csv e companhia. Este parâmetro é do PowerShell 7:

PS C:\Users\ana\guia-ps-teste> Split-Path "$T\docs\a.txt" -Extension
.txt
No Windows PowerShell 5.1 o parâmetro -Extension não existe: 
PS C:\Users\ana\guia-ps-teste> Split-Path "$T\docs\a.txt" -Extension
Split-Path : Não é possível localizar um parâmetro que coincida com o nome de parâmetro 'Extension'.
No 5.1, uma saída é pegar o -Leaf e ler a extensão no próprio texto, mais à frente, com métodos de string.

Missão: use Split-Path -Extension para mostrar a extensão do caminho montado com Join-Path.

Split-Path (Join-Path 'docs' 'a.txt') -Leaf

Split-Path (Join-Path 'docs' 'a.txt') -Extension

6. O separador e a pasta pessoal

Se você quiser ver o separador que o sistema está usando, o .NET guarda isso em [System.IO.Path]::DirectorySeparatorChar (é um pedaço mais técnico; por enquanto, leia como "o caractere que separa pastas neste computador"):

PS C:\Users\ana\guia-ps-teste> [System.IO.Path]::DirectorySeparatorChar
\

No Windows é a barra invertida. No Linux seria a barra comum. É exatamente por isso que a gente deixa o Join-Path escolher, em vez de escrever a barra na mão.

A pasta pessoal aparece em dois lugares, no Windows:

PS C:\Users\ana\guia-ps-teste> $HOME
C:\Users\ana
PS C:\Users\ana\guia-ps-teste> $env:USERPROFILE
C:\Users\ana

O $HOME é a variável automática do PowerShell, e funciona também no Linux (lá ela aponta para /home/ana). O $env:USERPROFILE é a variável de ambiente do Windows com o mesmo valor neste computador. Pedimos o nome USERPROFILE direto, sem listar todas as variáveis de ambiente.

Formas diferentes de montar um caminho

Quando dá errado

O Resolve-Path de um arquivo que não existe

Na pasta docs havia só o a.txt. Pedimos o b.txt:

PS C:\Users\ana\guia-ps-teste> Resolve-Path docs\b.txt
Resolve-Path: Não é possível localizar o caminho 'C:\Users\ana\guia-ps-teste\docs\b.txt' porque ele não existe.
Resolve-Path:
Quem está reclamando.
Não é possível localizar o caminho '…\docs\b.txt' porque ele não existe.
O comando não monta um endereço imaginário: ele confirma no disco, e o b.txt não estava lá. A mensagem traz o caminho absoluto que ele tentou, para você conferir.

Como resolver: confira o nome (é a.txt, não b.txt) ou, se a ideia era só montar o endereço de um arquivo novo, troque para o Join-Path, que não exige que o caminho exista.

Resumo

  • Caminho absoluto começa no disco (ou em /, no Linux) e não depende da pasta atual; o relativo, sim.
  • . é a pasta atual; .. é a de cima. Resolve-Path desembaraça e confirma no disco.
  • Join-Path monta o endereço no separador certo. No 7 dá para passar três ou mais pedaços; no 5.1, só dois.
  • Split-Path devolve o nome (-Leaf), a pasta (-Parent) ou, no 7, a extensão (-Extension).
  • $HOME é a pasta pessoal nos dois sistemas; $env:USERPROFILE é o nome do Windows para a mesma pasta.
  • Se o Resolve-Path não acha o arquivo, confira o nome ou monte o caminho novo com Join-Path.

Do cmd para o PowerShell

Se você já usou o Prompt de Comando (o cmd.exe), boa parte vai parecer familiar: dir, cd, copy e del funcionam no PowerShell porque são apelidos de cmdlets. Mas há diferenças importantes: variáveis, parâmetros com /, e o fato de o PowerShell trabalhar com objetos, não com texto.

Você vai aprender
  • Os equivalentes no PowerShell dos comandos mais usados do cmd.
  • Como variáveis de ambiente mudam (%PATH% vira $env:PATH).
  • Por que dir /s não funciona e o que usar no lugar.
  • Como rodar um .bat e comandos do cmd quando precisar.
  • O que muda em &&, ||, redirecionamento e aspas.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional. Os quadros marcados Saída no Windows (PowerShell 7.7) foram colhidos num Windows 10 em português, com o nome do computador e o da usuária trocados por exemplos (NOTEBOOK e ana).

A ideia: mudar de carro

Quem dirigia um carro manual e passa para um automático já sabe dirigir: volante, freio e pisca estão no mesmo lugar. Só o câmbio muda. Do cmd para o PowerShell é igual: os nomes básicos funcionam, mas o "câmbio" (objetos e parâmetros) é diferente.

2. Parâmetros: / vira -

No cmd, as opções usam barra: dir /s /b. No PowerShell, os parâmetros usam hífen e nome: Get-ChildItem -Recurse -Name. Como dir é só um apelido de Get-ChildItem, dir /s procura uma pasta chamada s e dá erro de caminho.

PS> dir /s
Get-ChildItem: Não é possível localizar o caminho 'C:\s' porque ele não existe.

4. Encadeando: && e ||

O PowerShell 7 aceita && (rode o próximo se deu certo) e || (rode se deu errado), como o cmd:

PS> Write-Output "primeiro" && Write-Output "segundo"
primeiro
segundo
PS> Get-Item "nao-existe.txt" 2>$null || Write-Output "o primeiro falhou"
o primeiro falhou
&&
Só roda o segundo se o primeiro deu certo.
||
Só roda o segundo se o primeiro falhou.
2>$null
Joga fora a mensagem de erro (o fluxo 2), como no cmd.

6. Rodando .bat e comandos do cmd

Arquivos .bat e .cmd rodam direto: .\instalar.bat. Os programas .exe (como ipconfig, ping, robocopy) também funcionam normalmente. E, se um comando só existe dentro do cmd (como mklink ou assoc), chame o cmd para rodá-lo:

cmd /c mklink /J atalho C:\pasta-real

7. A grande diferença: objetos

No cmd, dir devolve texto, e para filtrar você corta o texto. No PowerShell, Get-ChildItem devolve objetos com propriedades (Name, Length, LastWriteTime), e você filtra pelo nome da propriedade:

Get-ChildItem -File | Where-Object Length -gt 1MB | Sort-Object Length -Descending | Select-Object Name, Length

Leia a aula Tudo É Objeto para entender por que isso muda tudo.

Quando dá errado

copy *.txt pasta e a pasta não existe

No PowerShell, o Copy-Item não cria a pasta: ele grava cada .txt num arquivo chamado pasta, um por cima do outro, e no fim sobra só o conteúdo do último. Crie a pasta antes com New-Item -ItemType Directory pasta.

Aspas e espaços

No PowerShell, um caminho com espaço precisa de aspas, e para rodar um programa num caminho entre aspas use o & na frente: & "C:\Program Files\App\app.exe". Sem o &, o PowerShell só mostra o texto.

Resumo

  • dir, cd, copy, del, type funcionam: são apelidos de cmdlets.
  • Opções com / viram parâmetros com - (-Recurse, -Force).
  • %VAR% vira $env:VAR; %ERRORLEVEL% vira $LASTEXITCODE.
  • &&, || e redirecionamentos funcionam no PowerShell 7.
  • A grande mudança: o PowerShell trabalha com objetos.

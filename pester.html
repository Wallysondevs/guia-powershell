Testes com Pester

Você escreveu uma função, ela funciona... até alguém mudar uma linha e quebrar tudo sem perceber. Testes automatizados são pequenos scripts que conferem se o seu código continua fazendo o que deveria. O Pester é a ferramenta de testes do PowerShell.

Você vai aprender
  • A instalar o Pester 5.
  • A escrever um teste com Describe, It e Should.
  • A rodar os testes com Invoke-Pester.
  • A testar erros com Should -Throw.
  • A organizar com BeforeAll e Context.

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows. Exceção: nas seções 4 e 5, os quadros mostram o Pester 5.9.1 rodando no PowerShell 7.7 no Linux (na pasta da usuária fictícia, /home/ana), porque o Windows da coleta só tinha o Pester 3.4.0 que vem de fábrica. O Pester escreve o mesmo texto nos dois sistemas; só o caminho do arquivo muda.

A ideia: a lista de conferência

Antes de decolar, o piloto passa por uma lista: "combustível? ok. Flaps? ok.". Os testes são a lista de conferência do seu código, e o Pester confere tudo em segundos, sempre que você pedir.

1. Instalando

O Windows vem com o Pester 3, antigo. Veja qual você tem:

PS> Get-Module Pester -ListAvailable | Select-Object Name, Version

Name   Version
----   -------
Pester 3.4.0

No Windows da coleta só havia o 3.4.0, que não entende a sintaxe usada hoje (a desta aula). Pedir o Pester 5 sem ter instalado dá erro:

PS> Import-Module Pester -MinimumVersion 5.0
Import-Module: O módulo especificado "Pester" com a versão "5.0" não foi carregado porque nenhum arquivo de módulo válido foi encontrado em nenhum diretório de módulo.

Então instale o 5 só para você (não precisa de administrador):

Install-PSResource -Name Pester -Scope CurrentUser

2. A função a testar

Crie uma pasta com a função e o arquivo de testes. O arquivo de testes termina em .Tests.ps1:

PS> New-Item -ItemType Directory pester-teste -Force | Out-Null
PS> Set-Location pester-teste
PS> Set-Content Calculo.ps1 @'
>> function Get-Desconto {
>>     param([decimal]$Preco, [int]$Porcento)
>>     if ($Porcento -lt 0 -or $Porcento -gt 100) { throw "Porcentagem inválida: $Porcento" }
>>     $Preco - ($Preco * $Porcento / 100)
>> }
>> '@

3. O arquivo de testes

PS> Set-Content Calculo.Tests.ps1 @'
>> BeforeAll {
>>     . $PSScriptRoot\Calculo.ps1
>> }
>> Describe "Get-Desconto" {
>>     It "aplica 10% em 200" {
>>         Get-Desconto -Preco 200 -Porcento 10 | Should -Be 180
>>     }
>>     It "não muda o preço com 0%" {
>>         Get-Desconto -Preco 50 -Porcento 0 | Should -Be 50
>>     }
>>     It "recusa porcentagem maior que 100" {
>>         { Get-Desconto -Preco 50 -Porcento 150 } | Should -Throw "*inválida*"
>>     }
>> }
>> '@
BeforeAll
Roda antes dos testes: aqui, carrega a função com dot-source.
Describe
Agrupa os testes de um assunto.
It
Um teste: uma frase dizendo o que deveria acontecer.
Should -Be
Confere o valor. Se for diferente, o teste falha.
Should -Throw
Confere que o bloco dá erro (com a mensagem parecida com o padrão).

5. Quando um teste falha

Vamos simular um erro na função (trocar - por +) e rodar de novo:

PS> (Get-Content Calculo.ps1) -replace '\$Preco - \(', '$Preco + (' | Set-Content Calculo.ps1
PS> Invoke-Pester -Path .\Calculo.Tests.ps1 -Output Normal

Starting discovery in 1 files.
Discovery found 3 tests in 2ms.
Running tests.
[-] Get-Desconto.aplica 10% em 200 18ms (17ms|1ms)
 Expected 180, but got 220.
 at Get-Desconto -Preco 200 -Porcento 10 | Should -Be 180, /home/ana/pester-teste/Calculo.Tests.ps1:6
 at <ScriptBlock>, /home/ana/pester-teste/Calculo.Tests.ps1:6
Tests completed in 82ms
Tests Passed: 2, Failed: 1, Skipped: 0, Inconclusive: 0, NotRun: 0

O Pester diz qual teste falhou, o valor esperado e o valor recebido. É exatamente o aviso que você quer ter antes de publicar o script. Agora desfaça a troca e confira que tudo volta a passar:

PS> (Get-Content Calculo.ps1) -replace '\$Preco \+ \(', '$Preco - (' | Set-Content Calculo.ps1
PS> (Invoke-Pester -Path .\Calculo.Tests.ps1 -PassThru -Output None).Result
Passed

6. Outros Should

Você escreveConfere
Should -Be 5Igual a 5.
Should -BeExactly "Ana"Igual, diferenciando maiúsculas.
Should -BeGreaterThan 0Maior que.
Should -BeLike "*.txt"Combina com o curinga.
Should -Match '^\d+$'Combina com a regex.
Should -Contain 3A lista contém 3.
Should -BeNullOrEmptyVazio.
Should -Not -Be 0O contrário de qualquer Should.
Should -ThrowDá erro.

Experimente: escreva, numa string, o comando que roda os testes de Calculo.Tests.ps1 com -PassThru e mostra o Result. O simulador do guia não tem o Pester; depois, rode o comando de verdade no seu terminal, com o Pester 5 instalado.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = '(Invoke-Pester -Path .\Calculo.Tests.ps1 -PassThru -Output None).Result'
Write-Output $comando

Quando dá errado

"Describe não é reconhecido" ou mensagens estranhas

O PowerShell carregou o Pester 3. No Windows da coleta, o Invoke-Pester -Output Detailed com o Pester 3 respondeu: O parâmetro não pode ser processado porque o nome do parâmetro 'Output' é ambíguo. Instale o 5 (seção 1), rode Import-Module Pester -MinimumVersion 5.0 ou remova o antigo da sessão com Remove-Module Pester.

A função não existe dentro do teste

No Pester 5, carregue os arquivos dentro de BeforeAll, não solto no topo do arquivo.

Should -Throw não pega o erro

O código precisa estar dentro de chaves: { Get-Desconto ... } | Should -Throw. Sem as chaves, o erro acontece antes do Should.

Referência rápida

Você digitaO que faz
Install-PSResource Pester -Scope CurrentUserInstala o Pester 5.
Describe "x" { It "y" { ... } }Estrutura dos testes.
BeforeAll { . $PSScriptRoot\x.ps1 }Carrega o código.
Invoke-Pester -Output DetailedRoda e mostra cada teste.
Invoke-Pester -PassThruDevolve o resultado como objeto.

Missão final: escreva, numa string, um It que confere que Get-Desconto -Preco 80 -Porcento 25 dá 60. Depois, coloque esse It dentro do Describe do seu Calculo.Tests.ps1 e rode o Pester no seu terminal.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = 'It "25% de 80" { Get-Desconto -Preco 80 -Porcento 25 | Should -Be 60 }'
Write-Output $comando

Resumo

  • O Pester roda testes automatizados de código PowerShell.
  • Describe agrupa, It é um teste, Should confere.
  • Invoke-Pester roda e diz o que passou e o que falhou.
  • Teste também os erros com Should -Throw.

-ErrorAction e $ErrorActionPreference

Cada cmdlet aceita o parâmetro -ErrorAction, que diz o que fazer quando ele encontra um erro que não encerra: mostrar e seguir, calar e seguir, ou parar tudo. A variável $ErrorActionPreference muda o padrão para tudo de uma vez.

Você vai aprender
  • Os valores de -ErrorAction e o que cada um faz.
  • O apelido curto -EA.
  • Como -ErrorAction Stop deixa o catch funcionar.
  • A variável $ErrorActionPreference.
  • Quando usar (e quando não usar) SilentlyContinue.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: o aviso no GPS

O GPS pode reagir a uma rua fechada de três jeitos: avisar e recalcular (Continue), recalcular sem dizer nada (SilentlyContinue) ou parar a viagem e pedir ajuda (Stop). O -ErrorAction escolhe qual desses comportamentos o comando vai ter.

1. Os valores

ValorO que acontece com o erro
Continue(padrão) Mostra o erro e segue em frente.
SilentlyContinueNão mostra, mas guarda em $Error, e segue.
IgnoreNão mostra e nem guarda. Segue.
StopVira um erro que encerra: o comando para e o catch consegue pegar.
InquirePergunta o que fazer (útil para testar, ruim em script automático).
BreakEntra no depurador (veja a aula de depuração).

2. Vendo na prática

Para não depender de arquivos do seu computador, vamos usar uma função que gera um erro que não encerra, igual a um cmdlet faria:

PS> function Testar-Item { [CmdletBinding()] param($nome)
>>   if ($nome -eq "ruim") { Write-Error "Item '$nome' com problema." } else { "Item '$nome' ok" }
>> }

Com SilentlyContinue, o erro some da tela e o resto continua:

PS> "bom", "ruim", "outro" | ForEach-Object { Testar-Item $_ -ErrorAction SilentlyContinue }
Item 'bom' ok
Item 'outro' ok

Com o padrão (Continue), o erro apareceria em vermelho entre as duas linhas:

"bom", "ruim", "outro" | ForEach-Object { Testar-Item $_ }
[CmdletBinding()]
Faz a sua função ganhar os parâmetros comuns, como -ErrorAction (veja funções avançadas).
Write-Error
Gera um erro que não encerra.
-ErrorAction SilentlyContinue
Esconde o erro desta chamada.

3. Stop + try/catch

Com Stop, o erro vira um que encerra, e o catch pega:

PS> try { Testar-Item "ruim" -ErrorAction Stop; "não chega aqui" }
>> catch { "Capturado: $($_.Exception.Message)" }
Capturado: Item 'ruim' com problema.

Esse é o par mais usado em scripts: -ErrorAction Stop no comando e try/catch em volta.

Experimente: o catch abaixo não roda porque o erro não encerra. Acrescente -ErrorAction Stop na chamada para o catch mostrar a mensagem.

function Testar-Item { [CmdletBinding()] param($nome) Write-Error "Item '$nome' com problema." }
try { Testar-Item "x" } catch { "Capturado: $($_.Exception.Message)" }

function Testar-Item { [CmdletBinding()] param($nome) Write-Error "Item '$nome' com problema." }
try { Testar-Item "x" -ErrorAction Stop } catch { "Capturado: $($_.Exception.Message)" }

4. O padrão para tudo: $ErrorActionPreference

Em vez de escrever -ErrorAction Stop em cada linha, você pode mudar o padrão da sessão (ou do script):

PS> $ErrorActionPreference
Continue
PS> $ErrorActionPreference = "Stop"
PS> try { Testar-Item "ruim" } catch { "Parou no primeiro erro." }
Parou no primeiro erro.
PS> $ErrorActionPreference = "Continue"

Muitos scripts começam com $ErrorActionPreference = "Stop": assim nenhum erro passa despercebido e o script não continua com dados pela metade.

5. O apelido -EA

-EA é o apelido de -ErrorAction. E os valores podem ser escritos por número (0 = SilentlyContinue), mas use o nome: é muito mais fácil de ler.

PS> Testar-Item "ruim" -EA SilentlyContinue
PS> "seguiu"
seguiu

Quando dá errado

SilentlyContinue em tudo

Esconder todos os erros faz o script "funcionar" mostrando um resultado errado. Use SilentlyContinue só quando você sabe que o erro é esperado (por exemplo, testar se algo existe) e trata a falta do resultado logo depois.

-ErrorAction não muda erros de sintaxe nem o throw

-ErrorAction controla os erros que o comando gera. Um erro de digitação no código (ParserError) ou um throw não são afetados por ele.

Resumo

  • -ErrorAction decide o que fazer com erros que não encerram.
  • Stop + try/catch é a dupla de todo script cuidadoso.
  • $ErrorActionPreference muda o padrão de uma vez.
  • SilentlyContinue só quando o erro é esperado e tratado.

Permissões (Get-Acl)

No Windows, cada arquivo e pasta tem uma lista de quem pode fazer o quê: ler, gravar, apagar. Essa lista se chama ACL (lista de controle de acesso). É o que aparece na aba "Segurança" das propriedades de um arquivo. O PowerShell lê e altera essas listas com Get-Acl e Set-Acl.

Você vai aprender
  • A ver o dono e as permissões com Get-Acl.
  • A ler cada regra: quem, o quê, permitir ou negar, herdada ou não.
  • A dar permissão de leitura a alguém com Set-Acl.
  • O atalho icacls do Windows.

só Windows As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: a lista do porteiro

Na portaria de um prédio há uma lista: "Ana pode entrar em todos os andares; Beto só no térreo; visitantes não entram". Cada arquivo tem uma lista assim.

Pasta de teste Os exemplos usam uma pasta criada só para a aula. Nunca mude permissões de pastas do sistema para testar.

1. Vendo a ACL

PS> New-Item -ItemType Directory acl-teste -Force | Out-Null
PS> Set-Content acl-teste\segredo.txt "conteúdo"
PS> $acl = Get-Acl acl-teste\segredo.txt
PS> $acl.Owner -replace '^.*\\', '...\'
...\Administradores
PS> $acl.Access | Select-Object IdentityReference, FileSystemRights, AccessControlType, IsInherited

IdentityReference       FileSystemRights AccessControlType IsInherited
-----------------       ---------------- ----------------- -----------
AUTORIDADE NT\SISTEMA        FullControl             Allow        True
BUILTIN\Administradores      FullControl             Allow        True
NOTEBOOK\ana                 FullControl             Allow        True
Owner
O dono do arquivo (pode sempre mudar as permissões).
IdentityReference
Quem: um usuário ou grupo (BUILTIN\Administradores, AUTORIDADE NT\SISTEMA...).
FileSystemRights
O quê: FullControl, Modify, ReadAndExecute, Read, Write...
AccessControlType
Allow (permite) ou Deny (nega). Negar vence permitir.
IsInherited
True quando a regra veio da pasta de cima.

Na coleta, o dono saiu como Administradores porque o PowerShell estava aberto como administrador: num Windows em português, arquivos criados assim ficam com esse grupo como dono. Numa janela comum, o dono é você (aqui, NOTEBOOK\ana). Note também que os nomes de grupo saem traduzidos: AUTORIDADE NT\SISTEMA é o NT AUTHORITY\SYSTEM dos Windows em inglês.

2. Herança

Arquivos novos herdam as regras da pasta onde estão. Por isso quase todas as regras aparecem com IsInherited = True. Mudar a pasta muda tudo o que está dentro.

3. Adicionando uma regra

Vamos dar permissão de leitura ao grupo "Usuários" (identificado pelo SID S-1-5-32-545, que funciona em qualquer idioma do Windows):

$acl = Get-Acl acl-teste\segredo.txt
$grupo = [System.Security.Principal.SecurityIdentifier]::new('S-1-5-32-545')
$regra = [System.Security.AccessControl.FileSystemAccessRule]::new($grupo, 'Read', 'Allow')
$acl.AddAccessRule($regra)
Set-Acl -Path acl-teste\segredo.txt -AclObject $acl
(Get-Acl acl-teste\segredo.txt).Access | Where-Object { -not $_.IsInherited } | Select-Object FileSystemRights, AccessControlType
FileSystemAccessRule
Uma regra: quem, qual direito, permitir ou negar.
AddAccessRule
Acrescenta a regra à ACL na memória.
Set-Acl
Grava a ACL no arquivo de verdade.

Este bloco e o do icacls abaixo aparecem sem saída de propósito: na coleta desta aula, o guia não mudou nenhuma permissão no computador de teste. Rode-os no seu Windows, sempre no arquivo de teste acl-teste\segredo.txt. No fim, o último comando deve mostrar uma regra nova, não herdada (IsInherited falso), com Read em FileSystemRights e Allow em AccessControlType.

4. O atalho icacls

O Windows tem o programa icacls, mais curto para tarefas comuns:

icacls acl-teste\segredo.txt /remove '*S-1-5-32-545'

icacls pasta /grant "Ana:(OI)(CI)M"    # Ana pode modificar a pasta e tudo dentro
icacls pasta /inheritance:d             # desliga a herança, copiando as regras

Experimente: escreva, numa string, o comando que mostra o AccessControlType das regras da ACL de teste.txt. O simulador do guia não imita esse comando; depois, rode-o de verdade no seu Windows.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = '(Get-Acl teste.txt).Access.AccessControlType'
Write-Output $comando

Quando dá errado

"Tentativa de executar uma operação não autorizada"

Você não é dono nem tem permissão de alterar a ACL. Pastas do sistema e de outros usuários exigem administrador.

"Não é possível converter algumas ou todas as referências de identidade"

O nome do usuário ou grupo está errado ou em outro idioma (Users × Usuários). Use o SID, como no exemplo.

Dei permissão e a pessoa continua sem acesso

Uma regra Deny vence Allow. Confira também a permissão do compartilhamento, se o acesso for pela rede.

Missão final: escreva, numa string, o comando que mostra quem (IdentityReference) tem quais direitos (FileSystemRights) na pasta atual. O simulador do guia não imita esse comando; depois, rode-o de verdade no seu Windows.

Resumo

  • A ACL diz quem pode fazer o quê num arquivo ou pasta.
  • Get-Acl lê; .Access traz as regras; .Owner, o dono.
  • Crie regras com FileSystemAccessRule e grave com Set-Acl.
  • Deny vence Allow; use SIDs para não depender do idioma.

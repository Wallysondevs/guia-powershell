Senhas e Credenciais (SecureString)

Muitos scripts precisam de uma senha: para entrar num servidor, mandar e-mail, acessar uma API. Escrever a senha no meio do script é o erro mais comum (e mais perigoso). Nesta aula você aprende a pedir, guardar e usar senhas sem deixá-las expostas.

Você vai aprender
  • Por que nunca escrever senhas no script.
  • A pedir senhas com Read-Host -AsSecureString e Get-Credential.
  • O que é um PSCredential.
  • A guardar uma credencial protegida com Export-Clixml.
  • O módulo SecretManagement para cofres de senha.

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: o cofre

Senha escrita no script é como chave debaixo do tapete: qualquer um que abrir o arquivo (ou o histórico, ou o repositório no GitHub) encontra. O PowerShell oferece cofres: a senha fica cifrada e só você, no seu usuário do Windows, consegue abrir.

1. O jeito errado

$senha = "MinhaSenha123"   # NÃO faça isso

Essa linha fica no arquivo, no histórico do PSReadLine e em qualquer cópia do script.

2. Pedindo a senha

$senha = Read-Host "Senha" -AsSecureString
Senha: ********
-AsSecureString
Mostra asteriscos e guarda a senha como SecureString, cifrada na memória.
PS> $s = ConvertTo-SecureString "exemplo-de-aula" -AsPlainText -Force
PS> $s
System.Security.SecureString
PS> $s.Length
15

Um SecureString não mostra o conteúdo quando você imprime. (ConvertTo-SecureString -AsPlainText só aparece aqui para a aula funcionar sem digitar; em scripts reais, a senha vem de Read-Host ou de um cofre.)

3. PSCredential: usuário + senha

Muitos comandos pedem uma credencial (-Credential), que junta o nome do usuário e a senha:

$cred = Get-Credential -UserName "ana" -Message "Senha do servidor"

PS> $cred = [pscredential]::new("ana", $s)
PS> $cred

UserName                     Password
--------                     --------
ana      System.Security.SecureString
PS> $cred.GetNetworkCredential().Password.Length
15
[pscredential]
new :: Monta a credencial a partir de um nome e um SecureString.
GetNetworkCredential().Password
Recupera a senha em texto. Use só no último momento, quando uma API exigir texto puro.

4. Guardando para usar depois

No Windows, Export-Clixml grava a senha cifrada com a sua conta (DPAPI). Só o seu usuário, neste computador, consegue ler:

PS> $cred | Export-Clixml credencial.xml
PS> (Get-Content credencial.xml -Raw) -match 'exemplo-de-aula'
False
PS> $lida = Import-Clixml credencial.xml
PS> $lida.UserName
ana
PS> $lida.GetNetworkCredential().Password -eq 'exemplo-de-aula'
True

O arquivo não contém a senha em texto (False), mas a credencial volta inteira com Import-Clixml.

Só no Windows, só para você Copiar credencial.xml para outro computador ou usuário não funciona: a chave é da sua conta. E no Linux e macOS essa proteção não existe; lá, use um cofre (próxima seção).

5. Cofres: SecretManagement

O módulo oficial Microsoft.PowerShell.SecretManagement guarda segredos num cofre e os scripts só pedem pelo nome:

Install-PSResource Microsoft.PowerShell.SecretManagement, Microsoft.PowerShell.SecretStore -Scope CurrentUser
Register-SecretVault -Name Cofre -ModuleName Microsoft.PowerShell.SecretStore -DefaultVault
Set-Secret -Name ApiToken -Secret "valor-do-token"
$token = Get-Secret -Name ApiToken -AsPlainText

Experimente: escreva, numa string, o comando que cria um SecureString a partir de abc (só para teste) e confere com -is [securestring]. O simulador do guia não imita esse comando; depois, rode-o de verdade no seu Windows.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = '(ConvertTo-SecureString "abc" -AsPlainText -Force) -is [securestring]'
Write-Output $comando

Quando dá errado

"A chave não é válida para uso no estado especificado"

O credencial.xml foi criado por outro usuário ou em outro computador. Crie de novo com a sua conta.

Senha aparecendo no histórico

Se você digitou a senha num comando, ela foi para o histórico do PSReadLine. Apague o arquivo indicado em (Get-PSReadLineOption).HistorySavePath ou a linha específica.

"Não é possível associar o parâmetro 'Credential'"

O comando espera um PSCredential, não um texto. Monte com Get-Credential ou [pscredential]::new().

Resumo

  • Nunca escreva senhas no script.
  • Read-Host -AsSecureString e Get-Credential pedem sem mostrar.
  • PSCredential junta usuário e senha para os comandos.
  • Export-Clixml guarda cifrado para o seu usuário; SecretManagement guarda em cofres.

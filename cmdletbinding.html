Funções Avançadas ([CmdletBinding()])

Basta uma linha, [CmdletBinding()], para a sua função ganhar os poderes de um cmdlet: os parâmetros comuns (-Verbose, -ErrorAction…), a recusa de parâmetros desconhecidos e, se você quiser, o -WhatIf e o -Confirm.

Você vai aprender
  • A transformar uma função em avançada com [CmdletBinding()].
  • A usar Write-Verbose e ligar as mensagens com -Verbose.
  • A configurar parâmetros com [Parameter(Mandatory, Position = 0)].
  • A aceitar -WhatIf com SupportsShouldProcess.
  • Que a função avançada recusa parâmetros que não existem.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: o crachá de funcionário

Uma função simples é um visitante: entra, faz o serviço, mas não tem acesso às portas internas. Com [CmdletBinding()], ela ganha o crachá: passa a ter os mesmos recursos que os cmdlets oficiais.

1. A linha mágica

PS> function Get-Soma {
>>   [CmdletBinding()]
>>   param([int]$A, [int]$B)
>>   Write-Verbose "Somando $A e $B"
>>   $A + $B
>> }
PS> Get-Soma 2 3
5

Get-Soma 2 3 -Verbose

Com -Verbose, antes do 5 aparece a mensagem Somando 2 e 3, com o prefixo de detalhe na frente (DETALHADO: num Windows em português, como na aula Write-Warning, Write-Verbose e Companhia).

[CmdletBinding()]
Fica antes do param(). Liga os recursos de cmdlet.
Write-Verbose "..."
Uma mensagem de bastidor: só aparece se quem chamar usar -Verbose.
-Verbose
Parâmetro comum que a função ganhou de graça. Você não declarou, mas ele existe.

2. Parâmetros comuns de graça

PS> (Get-Command Get-Soma).Parameters.Keys -join ", "
A, B, Verbose, Debug, ErrorAction, WarningAction, InformationAction, ProgressAction, ErrorVariable, WarningVariable, InformationVariable, OutVariable, OutBuffer, PipelineVariable

Além de A e B, apareceram Verbose, Debug, ErrorAction, WarningAction… Veja as aulas Write-Verbose e -ErrorAction.

3. Nome errado agora é erro

Get-Soma -A 1 -C 2

Na função simples, o -C iria parar em $args sem aviso. Na avançada, o PowerShell recusa e diz que não existe parâmetro chamado C.

4. [Parameter()]: obrigatório, posição, ajuda

PS> function New-Usuario {
>>   [CmdletBinding()]
>>   param(
>>     [Parameter(Mandatory, Position = 0, HelpMessage = "Nome de login")]
>>     [string]$Login,
>>     [Parameter(Position = 1)]
>>     [string]$Grupo = "Usuarios"
>>   )
>>   "Criaria $Login no grupo $Grupo"
>> }
PS> New-Usuario ana
Criaria ana no grupo Usuarios
PS> New-Usuario beto Admins
Criaria beto no grupo Admins
Mandatory
Obrigatório.
Position = 0
O primeiro valor sem nome vai para este parâmetro.
HelpMessage
Um texto de ajuda que o PowerShell mostra se perguntar o valor.

Experimente: a função tem um Write-Verbose, mas a mensagem não aparece. Transforme em função avançada com [CmdletBinding()] e chame com -Verbose.

function Get-Dobro {
    param([int]$N)
    Write-Verbose "Calculando o dobro de $N"
    $N * 2
}
Get-Dobro 4

function Get-Dobro {
    [CmdletBinding()]
    param([int]$N)
    Write-Verbose "Calculando o dobro de $N"
    $N * 2
}
Get-Dobro 4 -Verbose

5. -WhatIf: "e se eu rodasse?"

Para funções que mudam alguma coisa, SupportsShouldProcess dá ao usuário o -WhatIf (só mostra o que faria) e o -Confirm. Dentro, você pergunta $PSCmdlet.ShouldProcess(...) antes de agir:

PS> function Remove-Tarefa {
>>   [CmdletBinding(SupportsShouldProcess)]
>>   param([string]$Nome)
>>   if ($PSCmdlet.ShouldProcess($Nome, "Apagar tarefa")) { "Tarefa $Nome apagada" }
>> }
PS> Remove-Tarefa "lavar louça"
Tarefa lavar louça apagada

Remove-Tarefa "lavar louça" -WhatIf

Com -WhatIf, o ShouldProcess devolve False e só mostra uma frase dizendo qual operação seria feita (Apagar tarefa) em qual alvo (lavar louça). A tarefa não é apagada.

Quando dá errado

[CmdletBinding()] fora do lugar 
PS> function F { param($x) [CmdletBinding()] $x }
PS> F 1
1

Fora do lugar, o [CmdletBinding()] não liga nada: a função continua simples. Ele precisa vir logo antes do param().

3. Para a sua função aceitar -WhatIf, você usa:

Missão final: faça a função aceitar -WhatIf: acrescente SupportsShouldProcess ao [CmdletBinding()] e coloque a ação dentro de if ($PSCmdlet.ShouldProcess($Nome, "Apagar")). Com -WhatIf, a nota não pode ser apagada.

function Remove-Nota {
    [CmdletBinding()]
    param([string]$Nome)
    "Nota $Nome apagada"
}
Remove-Nota "compras" -WhatIf

function Remove-Nota {
    [CmdletBinding(SupportsShouldProcess)]
    param([string]$Nome)
    if ($PSCmdlet.ShouldProcess($Nome, "Apagar")) { "Nota $Nome apagada" }
}
Remove-Nota "compras" -WhatIf

Resumo

  • [CmdletBinding()] antes do param() cria uma função avançada.
  • Ela ganha os parâmetros comuns (-Verbose, -ErrorAction…) e recusa nomes errados.
  • [Parameter(Mandatory, Position = 0)] configura cada parâmetro.
  • SupportsShouldProcess + $PSCmdlet.ShouldProcess() dão -WhatIf e -Confirm.

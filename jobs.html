Tarefas em Segundo Plano (Start-Job)

Alguns comandos demoram: copiar muitos arquivos, consultar vários sites, gerar um relatório grande. Um job roda esse trabalho em segundo plano enquanto você continua usando o terminal, e depois você busca o resultado.

Você vai aprender
  • A iniciar um job com Start-Job.
  • A ver o estado com Get-Job e esperar com Wait-Job.
  • A buscar o resultado com Receive-Job.
  • A passar valores para dentro do job.
  • O Start-ThreadJob (mais leve) e o & no fim da linha.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: a máquina de lavar

Você liga a máquina de lavar e vai fazer outra coisa. Quando ela apita, você volta e tira a roupa. O Start-Job liga a máquina; o Receive-Job tira a roupa.

1. O primeiro job

PS> $job = Start-Job -ScriptBlock { Start-Sleep -Seconds 2; "Relatório pronto: $(1..100 | Measure-Object -Sum | ForEach-Object Sum)" }
PS> $job.State
Running
PS> $job | Wait-Job | Out-Null
PS> $job.State
Completed
PS> Receive-Job $job
Relatório pronto: 5050
Start-Job -ScriptBlock { }
Roda o bloco num processo separado do PowerShell, em segundo plano.
.State
Running (rodando), Completed (terminou), Failed (deu erro)...
Wait-Job
Espera o job terminar (trava o terminal até lá).
Receive-Job
Entrega o que o job produziu.

O job é um processo separado: ele não enxerga as variáveis da sua sessão, e o que ele mostra só aparece quando você pede com Receive-Job.

2. Vários jobs ao mesmo tempo

PS> $jobs = 1..3 | ForEach-Object { Start-Job -ScriptBlock { param($n) Start-Sleep -Seconds 1; "Tarefa ${n}: ok" } -ArgumentList $_ }
PS> $jobs | Wait-Job | Receive-Job
Tarefa 1: ok
Tarefa 2: ok
Tarefa 3: ok
PS> $jobs | Select-Object Name, State, HasMoreData

Name State     HasMoreData
---- -----     -----------
Job3 Completed       False
Job5 Completed       False
Job7 Completed       False
-ArgumentList $_
Passa valores para o param() do bloco. É o jeito de levar dados da sua sessão para o job.
HasMoreData
False depois do Receive-Job: o resultado foi entregue e saiu do job.

3. $using: em vez de -ArgumentList

PS> $cidade = "Recife"
PS> Start-Job { "Previsão para $using:cidade" } | Receive-Job -Wait -AutoRemoveJob
Previsão para Recife
$using:cidade
Leva o valor da variável $cidade da sua sessão para dentro do job.
-Wait -AutoRemoveJob
Espera, entrega o resultado e já remove o job da lista. Ótimo para scripts.

4. Limpando

Jobs terminados continuam na lista até você remover:

PS> (Get-Job).Count
4
PS> Get-Job | Remove-Job
PS> (Get-Job).Count
0

5. Start-ThreadJob e o & no fim

O Start-Job cria um processo novo do PowerShell, o que é pesado. O Start-ThreadJob roda numa thread do mesmo processo: começa muito mais rápido e funciona com os mesmos Wait-Job e Receive-Job.

PS> Start-ThreadJob { 21 * 2 } | Receive-Job -Wait -AutoRemoveJob
42

Atalho: um & no fim de um comando vira um job, como no Bash:

Get-ChildItem C:\ -Recurse -Filter *.log &

Experimente: inicie um job que devolve Tarefa pronta e busque o resultado com Receive-Job -Wait.

$job = $null

$job = Start-Job { "Tarefa pronta" }
Receive-Job $job -Wait

Quando dá errado

A variável vazia dentro do job

$x = 5; Start-Job { $x * 2 } não devolve nada, porque lá dentro o $x está vazio: o job não vê a sua sessão. Use $using:x ou -ArgumentList.

Receive-Job duas vezes

O resultado sai do job na primeira leitura. Um segundo Receive-Job volta vazio. Guarde numa variável: $r = Receive-Job $job, ou use -Keep.

O erro "sumiu"

Se o job der erro, o estado fica Failed (ou Completed com erros que não encerram) e a mensagem só aparece no Receive-Job. Sempre receba o resultado e confira o State.

Referência rápida

Você digitaO que faz
Start-Job { ... }Inicia em segundo plano (processo separado).
Start-ThreadJob { ... }Inicia numa thread (mais leve).
Get-JobLista os jobs.
Wait-Job $jEspera terminar.
Receive-Job $jPega o resultado (-Wait espera antes).
Remove-Job $jRemove da lista.
$using:var / -ArgumentListLeva valores para o job.

Missão final: num job, use $using:n para devolver Dobro: + o dobro de $n, e receba com -Wait -AutoRemoveJob.

$n = 21
Start-Job { "Dobro: $($n * 2)" } | Receive-Job -Wait -AutoRemoveJob

$n = 21
Start-Job { "Dobro: $($using:n * 2)" } | Receive-Job -Wait -AutoRemoveJob

Resumo

  • Start-Job roda em segundo plano; Receive-Job traz o resultado.
  • Get-Job, Wait-Job e Remove-Job controlam a lista.
  • O job não vê suas variáveis: use $using: ou -ArgumentList.
  • Start-ThreadJob é a opção leve.

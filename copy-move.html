Copiando e movendo (Copy-Item e Move-Item)

Criar arquivo é o começo. O dia a dia pede duas coisas a mais: copiar (ficar com o original e uma cópia) e mover (o item muda de lugar, ou de nome, e some da origem). Os comandos são o Copy-Item ("copie o item") e o Move-Item ("mova o item"). Os dois, por padrão, não escrevem nada na tela quando dão certo: o silêncio é o "ok".

Você vai aprender
  • A copiar um arquivo para outra pasta, ou para um nome novo na mesma pasta.
  • A diferença enorme de copiar uma pasta com e sem o -Recurse.
  • O -PassThru, que pede o comprovante (a tabelinha) depois de copiar.
  • A mover um arquivo de pasta e, se quiser, já trocar o nome no mesmo comando.
  • Os erros reais de caminho que não existe e de destino que já está ocupado.
  • O ensaio -WhatIf, para ver a cópia antes de ela acontecer.

Todas as saídas desta aula foram colhidas no PowerShell 7.7 de um Windows em português, na pasta de teste da usuária fictícia ana. Antes dos comandos abaixo, a pasta de teste já tinha nota.txt, a pasta backup e a pasta docs com um a.txt dentro.

Pratique numa pasta de teste. Todos os exemplos desta aula foram rodados dentro de C:\Users\ana\guia-ps-teste. No seu computador, crie uma pasta só para treinar e trabalhe nela. Um jeito seguro: New-Item -ItemType Directory -Path (Join-Path $HOME 'guia-ps-teste') e depois Set-Location (Join-Path $HOME 'guia-ps-teste'). Assim você não mexe nas suas fotos, documentos ou no Windows. No fim da prática, apague só essa pasta.

A ideia: xerox e mudança de gaveta

Copiar é fazer um xerox: o original continua onde estava e nasce uma folha igual em outro lugar (ou com outro nome). Mover é tirar a folha de uma gaveta e colocar em outra: ela não fica nos dois lugares. Se no caminho você ainda trocar o rótulo, é mover e renomear ao mesmo tempo.

No dia a diaNo PowerShell
Xerox da folha, original no lugarCopy-Item
Tirar a folha de uma gaveta e pôr em outraMove-Item
Xerox de uma pasta inteira, com o que tem dentroCopy-Item … -Recurse
"Me mostra o comprovante da cópia"-PassThru

1. Copiar um arquivo

O primeiro nome é a origem; o segundo é o destino. Se o destino é uma pasta (e termina com \, para ficar claro), a cópia entra lá com o mesmo nome:

PS C:\Users\ana\guia-ps-teste> Copy-Item nota.txt backup\

Não apareceu nada. No Copy-Item, silêncio quer dizer sucesso. A cópia está em backup\nota.txt e o original nota.txt continua na pasta de teste.

Se o destino é um nome de arquivo, você aproveita para batizar a cópia:

PS C:\Users\ana\guia-ps-teste> Copy-Item nota.txt nota-copia.txt

De novo, silêncio. Agora existem nota.txt e nota-copia.txt lado a lado.

Copy-Item
Verbo Copy ("copiar") + Item: "copie o item".
nota.txt
A origem: o arquivo que já existe.
backup\
O destino: a pasta backup. A barra invertida no fim ajuda a ler "é uma pasta".
nota-copia.txt
Outro tipo de destino: um nome novo, na pasta atual.

Experimente: o arquivo nota.txt já está criado. Copie-o para nota-copia.txt com Copy-Item.

Set-Content nota.txt "oi"
# copie nota.txt para nota-copia.txt

Set-Content nota.txt "oi"
Copy-Item nota.txt nota-copia.txt

2. Copiar pasta: o -Recurse faz toda a diferença

Sem -Recurse ("recursivo": desça o que tiver dentro), o PowerShell cria no destino uma pasta vazia com o nome que você deu. O conteúdo fica para trás. Veja o laboratório: copiamos docs (que tem um a.txt) para backup\docs-copia e depois listamos o que há em backup:

PS C:\Users\ana\guia-ps-teste> Copy-Item docs backup\docs-copia
PS C:\Users\ana\guia-ps-teste> Get-ChildItem backup -Recurse -Name
docs-copia
nota.txt

docs-copia apareceu, nota.txt já estava no backup da seção anterior… e não há docs-copia\a.txt. A pasta chegou oca.

Com -Recurse, ele copia a pasta e o que está dentro:

PS C:\Users\ana\guia-ps-teste> Copy-Item docs backup\docs-rec -Recurse
PS C:\Users\ana\guia-ps-teste> Get-ChildItem backup -Recurse -Name
docs-copia
docs-rec
nota.txt
docs-rec\a.txt
-Recurse
Desça a árvore: copie também os arquivos e as subpastas.
docs-rec\a.txt
Agora sim: o a.txt veio junto. A lista -Name mostra o caminho relativo de cada item.
Sem -Recurse, a "cópia" de uma pasta não leva o conteúdo. Se a ideia é um backup de verdade, não esqueça desse parâmetro. E ensaie com -WhatIf antes, principalmente se o destino já tiver coisas.

3. Ver o comprovante: -PassThru

Por padrão o Copy-Item não devolve a tabelinha. O parâmetro -PassThru ("deixe passar") pede esse comprovante, no mesmo formato do New-Item:

PS C:\Users\ana\guia-ps-teste> Copy-Item nota.txt backup\ -PassThru

    Diretório: C:\Users\ana\guia-ps-teste\backup

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a---          20/11/2026    17:12              4 nota.txt

O Diretório: é o destino (…\backup). O Length 4 é o tamanho do nota.txt (no laboratório ele tinha o texto oi e a quebra de linha). A hora é a do arquivo de origem.

4. Mover: o original sai do lugar

O Move-Item tira o item da origem. Movemos nota-copia.txt para dentro de docs e listamos essa pasta:

PS C:\Users\ana\guia-ps-teste> Move-Item nota-copia.txt docs\
PS C:\Users\ana\guia-ps-teste> Get-ChildItem docs -Name
a.txt
nota-copia.txt

Lá estão o a.txt que já existia e o nota-copia.txt que acabou de chegar. Na pasta de teste, o nota-copia.txt não está mais na raiz.

O destino também pode ser um nome novo: aí você move e renomeia no mesmo comando. Tiremos o arquivo de docs de volta para a pasta atual, já com o nome renomeada.txt:

PS C:\Users\ana\guia-ps-teste> Move-Item docs\nota-copia.txt .\renomeada.txt
PS C:\Users\ana\guia-ps-teste> Get-ChildItem -Name
backup
docs
nota.txt
renomeada.txt
Move-Item
Verbo Move ("mover") + Item.
docs\nota-copia.txt
A origem, com o caminho da pasta onde o arquivo está agora.
.\renomeada.txt
O destino: . é a pasta atual, e renomeada.txt é o nome novo.

A listagem da pasta de teste mostra backup, docs, o nota.txt original e o renomeada.txt. O nota-copia.txt não aparece mais: ele foi movido, não copiado.

Só trocar o nome, deixando o arquivo na mesma pasta, é trabalho do Rename-Item. O Move-Item também consegue, mas o nome dele pede "mudança de lugar".

Missão: o arquivo nota-copia.txt já existe. Mova-o para renomeada.txt com Move-Item.

Set-Content nota-copia.txt "oi"
# mova nota-copia.txt para renomeada.txt

Set-Content nota-copia.txt "oi"
Move-Item nota-copia.txt renomeada.txt

Quando dá errado

A origem não existe

Tentamos copiar um arquivo que não está na pasta:

PS C:\Users\ana\guia-ps-teste> Copy-Item naoexiste.txt backup\
Copy-Item: Não é possível localizar o caminho 'C:\Users\ana\guia-ps-teste\naoexiste.txt' porque ele não existe.

A mensagem veio em português, em vermelho. Linha por linha:

Copy-Item:
Qual comando reclamou.
Não é possível localizar o caminho '…\naoexiste.txt'
Ele procurou esse caminho e não achou o arquivo.
porque ele não existe.
A causa: o nome está errado, ou o arquivo está em outra pasta.

Como resolver: confira o nome com Get-ChildItem ou Test-Path e rode de novo. Nada foi copiado.

O destino já está ocupado

Tentamos mover renomeada.txt para cima de backup\nota.txt, que já existia:

PS C:\Users\ana\guia-ps-teste> Move-Item renomeada.txt backup\nota.txt
Move-Item: Não é possível criar um arquivo já existente.

Não é possível criar um arquivo já existente. O PowerShell se recusou a esmagar o arquivo que já estava no destino. Os dois arquivos continuam onde estavam.

Como resolver: escolha outro nome, apague o destino só se for isso mesmo que você quer, ou copie/mova para uma pasta vazia. Não existe, neste comando, um "juntar os dois".

Ensaiar: -WhatIf

Antes de uma cópia que você não quer repetir à toa, ensaie. O -WhatIf conta a operação e os dois caminhos, e não copia nada:

PS C:\Users\ana\guia-ps-teste> Copy-Item nota.txt backup\ -WhatIf
What If: Executando a operação "Copiar Arquivo" no destino "Item: C:\Users\ana\guia-ps-teste\nota.txt Destino: C:\Users\ana\guia-ps-teste\backup\nota.txt".

Ele diria "Copiar Arquivo", da origem nota.txt para backup\nota.txt. Como já tínhamos essa cópia, o ensaio é só uma confirmação visual — e é o hábito que vai te salvar quando o destino for outro.

Exercícios

1. Complete o comando

Complete para copiar nota.txt para dentro da pasta backup, com o mesmo nome:

Copy-Item nota.txt

2. O que faltou?

Qual parâmetro faz o Copy-Item levar também o que está dentro da pasta?

Copy-Item docs backup\docs-rec -

3. Qual é a diferença?

Depois de um Move-Item bem-sucedido, o arquivo continua na origem? Responda sim ou nao.

4. Você rodou Copy-Item nota.txt backup\ e a tela não mostrou nada. O que isso (quase sempre) quer dizer?

5. Sem -Recurse, o que o Copy-Item docs backup\docs-copia fez no laboratório?

6. O Move-Item renomeada.txt backup\nota.txt respondeu "Não é possível criar um arquivo já existente." O que fazer?

Missão final: crie a pasta backup, copie nota.txt para dentro dela e copie a pasta docs para backup/docs-rec com o conteúdo (use -Recurse).

New-Item -ItemType Directory backup, docs | Out-Null
Set-Content nota.txt "oi"
Set-Content docs/a.txt "x"
# copie nota.txt para backup e a pasta docs para backup/docs-rec

New-Item -ItemType Directory backup, docs | Out-Null
Set-Content nota.txt "oi"
Set-Content docs/a.txt "x"
Copy-Item nota.txt backup/
Copy-Item docs backup/docs-rec -Recurse

Resumo

  • Copy-Item faz uma cópia e deixa o original. Move-Item tira o item do lugar.
  • Os dois são silenciosos quando dão certo; -PassThru pede o comprovante.
  • Copiar pasta sem -Recurse cria uma pasta vazia. Com -Recurse, o conteúdo vai junto.
  • O destino pode ser uma pasta (mesmo nome) ou um nome novo (copiar/mover e já batizar).
  • Origem inexistente e destino ocupado geram erro em português; nada é destruído por causa disso.
  • -WhatIf ensaia a cópia. Pratique sempre numa pasta de teste.

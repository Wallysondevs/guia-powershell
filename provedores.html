Drives e provedores (Env:, HKCU:)

Até aqui, quase tudo aconteceu no disco: pastas e arquivos em C:. O PowerShell usa a mesma família de comandos — Get-ChildItem, Get-Item, Test-Path — para olhar outras "gavetas": variáveis de ambiente, o Registro, apelidos, funções. Quem apresenta essas gavetas são os provedores, e cada gaveta aparece como um drive, com um nome e dois-pontos: C:, Env:, HKCU:.

Você vai aprender
  • O que é um provedor e o que é um drive, com o Get-PSProvider e o Get-PSDrive.
  • A ler variáveis de ambiente pelo drive Env: (só pelo nome, uma de cada vez) e pelo atalho $env:OS.
  • A olhar o Registro do usuário atual em HKCU:, só leitura, como se fosse uma pasta.
  • Que funções, apelidos e variáveis da sessão também moram em drives.
  • O erro real de pedir um drive que não existe (Z:).

Todas as saídas desta aula foram colhidas no PowerShell 7.7 de um Windows em português, na pasta pessoal da usuária fictícia ana. Alguns drives (HKCU:, HKLM:, Cert:, WSMan:) existem só no Windows; no editor do guia, que roda um PowerShell 7 de Linux, eles não aparecem. Os exemplos de arquivo desta aula são só de leitura: nada é criado nem apagado no Registro.

A ideia: o mesmo chaveiro, prédios diferentes

Você tem um chaveiro com uma chave só, no mesmo formato, que abre o armário do escritório, a caixa de correio e a gaveta das ferramentas. O movimento da mão é o mesmo; o que tem dentro de cada móvel é que muda.

No PowerShell, os comandos Get-ChildItem, Get-Item e Test-Path são essa chave. O provedor é o prédio (sistema de arquivos, ambiente, Registro). O drive é a porta com plaquinha: C:, Env:, HKCU:.

No prédioNo PowerShell
O tipo de prédio (arquivo, ambiente, Registro)O provedor (FileSystem, Environment, Registry)
A porta com plaquinhaO drive (C:, Env:, HKCU:)
A mesma chave nas três portasGet-ChildItem, Get-Item, Test-Path

1. Quem são os provedores: Get-PSProvider

PS C:\Users\ana> Get-PSProvider

Name                 Capabilities                                      Drives
----                 ------------                                      ------
Registry             ShouldProcess                                     {HKLM, HKCU}
Alias                ShouldProcess                                     {Alias}
Environment          ShouldProcess                                     {Env}
FileSystem           Filter, ShouldProcess, Credentials                {C, Temp}
Function             ShouldProcess                                     {Function}
Variable             ShouldProcess                                     {Variable}
Name
O nome do provedor. FileSystem é o disco; Environment é o ambiente; Registry é o Registro do Windows.
Capabilities
O que aquele provedor sabe fazer. ShouldProcess quer dizer que ele respeita -WhatIf e -Confirm. O FileSystem ainda aceita filtro e credenciais.
Drives
As portas que ele oferece agora. O FileSystem no laboratório tinha C e Temp; o Registro tinha HKLM e HKCU.

A lista é a do laboratório no momento da coleta. No seu computador pode aparecer algum provedor a mais, se um módulo tiver sido carregado.

2. As portas: Get-PSDrive

O Get-PSDrive lista os drives. Pedimos só três colunas — nome, provedor e raiz — para a tabela caber:

PS C:\Users\ana> Get-PSDrive | Format-Table Name, Provider, Root -AutoSize

Name     Provider                                  Root
----     --------                                  ----
Alias    Microsoft.PowerShell.Core\Alias           
C        Microsoft.PowerShell.Core\FileSystem      C:\
Cert     Microsoft.PowerShell.Security\Certificate \
Env      Microsoft.PowerShell.Core\Environment     
Function Microsoft.PowerShell.Core\Function        
HKCU     Microsoft.PowerShell.Core\Registry        HKEY_CURRENT_USER
HKLM     Microsoft.PowerShell.Core\Registry        HKEY_LOCAL_MACHINE
Temp     Microsoft.PowerShell.Core\FileSystem      C:\Users\ana\AppData\Local\Temp\
Variable Microsoft.PowerShell.Core\Variable        
WSMan    Microsoft.WSMan.Management\WSMan

Tem mais portas aqui do que na lista de provedores: Cert (certificados) e WSMan (administração remota) aparecem quando os módulos deles já estão carregados. Os dois, junto com HKCU e HKLM, são só Windows.

C e Temp
Pastas de verdade. A raiz de C é C:\; a de Temp é a pasta temporária da Ana.
Env
As variáveis de ambiente. A raiz vem em branco na tabela: o "conteúdo" são os nomes das variáveis, não um caminho de disco.
HKCU e HKLM
O Registro do usuário atual (HKEY_CURRENT_USER) e o da máquina (HKEY_LOCAL_MACHINE).
Alias, Function, Variable
Apelidos, funções e variáveis da sessão atual.

3. Variáveis de ambiente: Env:

Ambiente, aqui, são as configurações que o Windows (e os programas) expõem com um nome: o tipo de sistema, o usuário logado, a pasta do Windows. Você lê pelo nome, como quem puxa uma ficha do fichário — não despeja o fichário inteiro na mesa.

Não liste o drive Env: aberto (nada de Get-ChildItem Env: nem dir Env:). Essa listagem mistura variáveis úteis com dados da sessão que não devem ir para um guia nem para um script compartilhado. Peça só o nome que você precisa.

No laboratório pedimos três nomes, e só esses três:

PS C:\Users\ana> Get-Item Env:OS, Env:USERNAME, Env:windir

Name                           Value
----                           -----
OS                             Windows_NT
USERNAME                       ana
windir                         C:\Windows
Get-Item Env:OS, Env:USERNAME, Env:windir
Três fichas, pelos nomes completos. A vírgula monta a lista.
OS
O tipo do sistema. No Windows vem Windows_NT.
USERNAME
O usuário logado. No guia usamos a usuária fictícia ana; no seu computador aparece o seu nome.
windir
A pasta do Windows, em geral C:\Windows.

Há um atalho ainda menor: $env:NOME devolve só o valor, sem a tabelinha.

PS C:\Users\ana> $env:OS
Windows_NT

Missão: confira se a variável de ambiente PATH existe, com Test-Path Env:PATH (deve ser True). Não liste o drive Env: inteiro.

# teste só Env:PATH

Test-Path Env:PATH

4. O Registro do usuário: HKCU:

só Windows O Registro é o "armário de configurações" do Windows. O drive HKCU: (Hive Key Current User, a chave do usuário atual) deixa você navegar como se fosse pasta, só lendo. Não vamos criar, alterar nem apagar chave nenhuma nesta aula.

A listagem da raiz mostra as pastas padrão de um usuário do Windows. São nomes de sistema, não arquivos pessoais:

PS C:\Users\ana> Get-ChildItem HKCU:\ -Name
AppEvents
Console
Control Panel
Environment
EUDC
Keyboard Layout
Network
Printers
SOFTWARE
System
Volatile Environment

Uma chave útil para este guia está em Control Panel\International: o idioma e o formato curto de data. Pedimos só esses dois nomes com Get-ItemProperty ("obtenha as propriedades do item"):

PS C:\Users\ana> Get-ItemProperty 'HKCU:\Control Panel\International' -Name LocaleName, sShortDate

LocaleName   : pt-BR
sShortDate   : dd/MM/yyyy
PSPath       : Microsoft.PowerShell.Core\Registry::HKEY_CURRENT_USER\Control Panel\International
PSParentPath : Microsoft.PowerShell.Core\Registry::HKEY_CURRENT_USER\Control Panel
PSChildName  : International
PSDrive      : HKCU
PSProvider   : Microsoft.PowerShell.Core\Registry

LocaleName veio pt-BR e sShortDate veio dd/MM/yyyy — é por isso que o Get-Date -Format "dd/MM/yyyy" da primeira aula combina com o que o Windows já usa. As linhas PSPath, PSParentPath, PSChildName, PSDrive e PSProvider são a ficha técnica que o PowerShell acrescenta: de onde veio o item, em qual drive e por qual provedor.

O HKLM: (a máquina inteira) e qualquer alteração no Registro ficam para o Nível 3, e mesmo lá só entram com chave de teste e autorização explícita. Aqui, só leitura em HKCU:.

Quando dá errado

O drive não existe

Pedimos a listagem de Z:, um drive que não estava no computador do laboratório:

PS C:\Users\ana> Get-ChildItem Z:\
Get-ChildItem: Cannot find drive. A drive with the name 'Z' does not exist.

A mensagem veio em inglês: Cannot find drive. A drive with the name 'Z' does not exist — "não é possível encontrar o drive; um drive com o nome Z não existe". O PowerShell procurou a porta Z: e não havia plaquinha com esse nome.

Como resolver: confira os drives com Get-PSDrive. Se Z: é um pendrive ou um disco de rede, ele só aparece quando estiver conectado. Não é um erro de grafia do Get-ChildItem: o comando existe; a porta é que não está lá.

Formas diferentes de ler um provedor

FormaQuando usar
$env:PATHAtalho que devolve só o valor da variável de ambiente PATH.
Get-Item Env:PATHA mesma variável, como item do drive Env: (nome e valor). Peça sempre um nome.
Get-ChildItem Env:PATHTambém lê só esse item. Nunca liste o drive Env: sem um nome.
Get-ChildItem HKCU:\ -Namesó Windows Lista só os nomes das chaves na raiz do Registro do usuário, pelo drive HKCU:.
Get-ChildItem Registry::HKEY_CURRENT_USER -Namesó Windows O mesmo lugar, pelo caminho completo do provedor, sem o atalho HKCU:.

Resumo

  • Provedores são os "prédios" (FileSystem, Environment, Registry…). Drives são as portas (C:, Env:, HKCU:).
  • Os mesmos comandos de pasta servem nesses drives: Get-ChildItem, Get-Item, Test-Path.
  • Em Env:, peça pelo nome (Get-Item Env:OS ou $env:OS). Não liste o drive aberto.
  • HKCU:, HKLM:, Cert: e WSMan: são só do Windows. Nesta aula, o Registro é só leitura.
  • Drive inexistente (Z:) gera erro em inglês: Cannot find drive. Confira com Get-PSDrive.

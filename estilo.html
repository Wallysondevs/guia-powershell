Estilo e Verbos Aprovados

Um script bem escrito é lido muito mais vezes do que é escrito: por você daqui a seis meses e por colegas. O PowerShell tem convenções fortes: nomes no formato Verbo-Substantivo, verbos de uma lista oficial e nomes completos nos scripts. Seguindo isso, qualquer pessoa entende o seu código.

Você vai aprender
  • O padrão Verbo-Substantivo e a lista de verbos aprovados (Get-Verb).
  • Por que evitar apelidos (ls, %, ?) em scripts.
  • Boas práticas para parâmetros e nomes de variáveis.
  • Recuo, chaves e comentários.
  • A ferramenta PSScriptAnalyzer, que revisa o estilo para você.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: as placas de trânsito

Placas de trânsito são iguais em todo o país: você entende uma placa de "Pare" em qualquer cidade. Os verbos aprovados são as placas do PowerShell: Get- sempre lê, Set- sempre altera, Remove- sempre apaga. Quem vê o nome já sabe o que esperar.

1. Verbo-Substantivo

BomRuimPor quê
Get-ClientePegarClienteSem hífen e com verbo fora da lista.
New-RelatorioCriar-RelatorioCriar não é aprovado; use New.
Remove-ArquivoTemporarioApagar-TempUse Remove e um substantivo claro, no singular.
Get-PedidoGet-PedidosO substantivo fica no singular, mesmo que devolva vários.

O verbo vem em inglês (da lista oficial); o substantivo pode ser em português.

3. Apelidos: no terminal sim, no script não

No terminal (rápido)No script (claro)
lsGet-ChildItem
gci . -rGet-ChildItem -Path . -Recurse
% { $_ * 2 }ForEach-Object { $_ * 2 }
? { $_.Length -gt 1KB }Where-Object { $_.Length -gt 1KB }
select -f 5Select-Object -First 5

Apelidos economizam teclas na hora, mas confundem quem lê e alguns não existem em todos os sistemas (no Linux, ls chama o programa do sistema, não o Get-ChildItem). No script, escreva nomes completos e parâmetros com nome.

5. Recuo, chaves e linhas longas

function Get-Desconto {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory)]
        [decimal]$Valor,

        [ValidateRange(0, 50)]
        [int]$Percentual = 10
    )

    if ($Valor -le 0) {
        throw "Valor precisa ser positivo: $Valor"
    }

    $parametros = @{
        Object          = "Desconto de $Percentual%"
        ForegroundColor = "Green"
    }
    Write-Host @parametros

    return $Valor * $Percentual / 100
}

6. Comentários que ajudam

Comente o porquê, não o óbvio. $i++ # soma 1 no i não ajuda; # a API devolve no máximo 100 itens por página ajuda. E coloque ajuda nas funções (veja Ajuda nas Suas Funções).

7. PSScriptAnalyzer: o revisor automático

O módulo PSScriptAnalyzer lê seus scripts e aponta problemas de estilo e erros comuns (apelidos, verbos fora da lista, variáveis não usadas, senhas em texto puro). Instale uma vez pela PowerShell Gallery e rode na pasta do projeto:

Install-PSResource PSScriptAnalyzer
Invoke-ScriptAnalyzer -Path .\meu-script.ps1

O resultado é uma tabela com a regra, a gravidade, a linha e a mensagem de cada problema. O editor VS Code com a extensão do PowerShell mostra os mesmos avisos enquanto você digita.

Resumo

  • Nomes Verbo-Substantivo, com verbos de Get-Verb e substantivo no singular.
  • No script: nomes completos e parâmetros com nome, sem apelidos.
  • Parâmetros em PascalCase, com tipos e validação.
  • Recuo de 4 espaços, splatting para linhas longas e comentários com o porquê.
  • O PSScriptAnalyzer revisa tudo isso por você.

Logs de Eventos (Get-WinEvent)

O Windows anota tudo o que acontece num diário chamado Log de Eventos: quando o computador ligou e desligou, erros de programas, atualizações instaladas. É o que o Visualizador de Eventos mostra. Com Get-WinEvent você lê esse diário e encontra a causa de problemas em segundos.

Você vai aprender
  • A listar os logs com Get-WinEvent -ListLog.
  • A ver os últimos eventos com -MaxEvents.
  • A filtrar por nível, data e Id com -FilterHashtable.
  • A achar quando o computador ligou e desligou.
  • A exportar o resultado para CSV.

só Windows As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: a caixa-preta

Avião tem caixa-preta; o Windows tem o Log de Eventos. Quando algo dá errado ("o computador reiniciou sozinho!"), é lá que você vai procurar.

1. Os logs disponíveis

PS> Get-WinEvent -ListLog Application, System | Select-Object LogName, RecordCount, IsEnabled

LogName     RecordCount IsEnabled
-------     ----------- ---------
Application        7850      True
System             9911      True
-ListLog
Lista os logs (aceita *). Os principais: Application (programas), System (o Windows) e Security (logins; precisa de administrador).
RecordCount
Quantos eventos o log guarda agora.

3. Filtrando do jeito rápido: -FilterHashtable

Só erros (nível 2) do log System nas últimas 24 horas:

PS> Get-WinEvent -FilterHashtable @{ LogName = 'System'; Level = 2; StartTime = (Get-Date).AddDays(-1) } -MaxEvents 10 -ErrorAction SilentlyContinue | Select-Object TimeCreated, Id, ProviderName

TimeCreated            Id ProviderName

LogName

Level

StartTime / EndTime

Id

-ErrorAction SilentlyContinue
Se nada for encontrado, o Get-WinEvent dá erro; aqui isso é normal.

Filtrar no -FilterHashtable é muito mais rápido que Get-WinEvent | Where-Object, porque o Windows já entrega só o que interessa.

5. Lendo a mensagem

PS> $ev = Get-WinEvent -LogName System -MaxEvents 1
PS> $ev.Message
(saída não mostrada: o texto de um evento pode trazer nomes de usuário, caminhos e outros dados pessoais)

6. Agrupando e exportando

PS> Get-WinEvent -LogName Application -MaxEvents 200 | Group-Object LevelDisplayName | Select-Object Name, Count

Name        Count
----        -----
               17
Aviso           1
Erro            3
Informações   179
PS> Get-WinEvent -FilterHashtable @{ LogName = 'Application'; Level = 2 } -MaxEvents 20 -ErrorAction SilentlyContinue | Select-Object TimeCreated, Id, ProviderName, Message | Export-Csv erros-app.csv -NoTypeInformation
AVISO: O parâmetro 'NoTypeInformation' está obsoleto. This parameter is obsolete and has no effect. The default behavior is to not include type information. Use -IncludeTypeInformation to include type information.
PS> Test-Path erros-app.csv
True
-NoTypeInformation agora é obsoleto No PowerShell 7.7 esse parâmetro não faz mais nada: o Export-Csv já não grava a linha de tipo (#TYPE ...). Ele só gera o AVISO que aparece na saída, e pode ser tirado do comando. Se o mesmo script também precisar rodar no Windows PowerShell 5.1, mantenha o parâmetro e ignore o aviso: lá ele ainda evita a linha de tipo.

Experimente: escreva, numa string, o comando que mostra os 3 últimos eventos do log System com TimeCreated e Id. O simulador do guia não imita esse comando; depois, rode-o de verdade no seu Windows.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = 'Get-WinEvent -LogName System -MaxEvents 3 | Select-Object TimeCreated, Id'
Write-Output $comando

Quando dá errado

"Nenhum evento foi encontrado que corresponda aos critérios de seleção especificados"

O filtro não achou nada. Isso é bom (nenhum erro!) ou o filtro está apertado demais. Use -ErrorAction SilentlyContinue em scripts.

Acesso negado ao log Security

O log de segurança exige PowerShell como administrador.

Get-EventLog não existe

Get-EventLog é do Windows PowerShell 5.1. No 7, use Get-WinEvent.

Resumo

  • Get-WinEvent lê os logs do Windows; use sempre -MaxEvents ou um filtro.
  • -FilterHashtable filtra por log, nível, data e Id de forma rápida.
  • 6005/6006/6008 contam a história de ligar e desligar.
  • Exporte com Export-Csv para analisar depois.

Tarefas Agendadas

Um script só ajuda de verdade quando roda sozinho: o backup toda noite, o relatório toda segunda, a limpeza ao ligar o computador. O Agendador de Tarefas do Windows faz isso, e o PowerShell cria e controla essas tarefas por comando.

Você vai aprender
  • A listar tarefas com Get-ScheduledTask.
  • A ver quando uma tarefa rodou e se deu certo.
  • A montar uma tarefa: ação, gatilho e registro.
  • A rodar, desativar e remover tarefas.

só Windows As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: o despertador

Uma tarefa agendada é um despertador com instrução: "às 8h, rode este script". Ela tem três partes: a ação (o que fazer), o gatilho (quando) e o registro (guardar no Agendador).

1. Listando tarefas

PS> Get-ScheduledTask | Measure-Object | Select-Object Count

Count
-----
  239
PS> Get-ScheduledTask -TaskPath '\Microsoft\Windows\Defrag\' | Select-Object TaskName, State

TaskName        State
--------        -----
ScheduledDefrag Ready
TaskPath
A "pasta" da tarefa no Agendador. As do Windows ficam em \Microsoft\Windows\...; as suas, normalmente em \.
State
Ready (pronta), Running (rodando), Disabled (desativada).

2. Quando rodou e como foi

PS> Get-ScheduledTask -TaskPath '\Microsoft\Windows\Defrag\' | Get-ScheduledTaskInfo | Select-Object TaskName, LastRunTime, LastTaskResult, NextRunTime

TaskName        LastRunTime         LastTaskResult NextRunTime
--------        -----------         -------------- -----------
ScheduledDefrag 20/11/2026 23:19:19     2147943467
LastTaskResult
0 é sucesso. Outros números são códigos de erro.
NextRunTime
A próxima execução programada.

Na coleta, o LastTaskResult da desfragmentação saiu 2147943467. Números grandes assim são códigos de erro do Windows escritos em decimal. Em hexadecimal fica mais fácil pesquisar: '{0:X}' -f 2147943467 dá 8007042B, o erro 1067, "o processo terminou inesperadamente". É comum quando o computador desliga ou entra em suspensão no meio da tarefa. O NextRunTime vazio quer dizer que a tarefa não tem um próximo horário marcado: a desfragmentação roda na manutenção automática do Windows.

3. Criando uma tarefa: as três partes

Exemplo: rodar C:\Scripts\backup.ps1 todo dia às 20h.

$acao = New-ScheduledTaskAction -Execute "pwsh.exe" -Argument '-NoProfile -File "C:\Scripts\backup.ps1"'
$quando = New-ScheduledTaskTrigger -Daily -At "20:00"
Register-ScheduledTask -TaskName "Backup diário" -Action $acao -Trigger $quando -Description "Backup dos documentos"
New-ScheduledTaskAction
O que fazer: chamar o pwsh.exe com o script.
New-ScheduledTaskTrigger
Quando: -Daily -At, -Weekly -DaysOfWeek Monday -At, -AtLogOn, -AtStartup, -Once -At.
Register-ScheduledTask
Grava a tarefa no Agendador, rodando como você, só quando você está logado.

Para criar as partes sem registrar nada, você pode montar e inspecionar:

PS> $acao = New-ScheduledTaskAction -Execute "pwsh.exe" -Argument '-NoProfile -File "C:\Scripts\backup.ps1"'
PS> $quando = New-ScheduledTaskTrigger -Daily -At "20:00"
PS> $acao | Select-Object Execute, Arguments

Execute  Arguments
-------  ---------
pwsh.exe -NoProfile -File "C:\Scripts\backup.ps1"
PS> $quando | Select-Object StartBoundary, DaysInterval

StartBoundary        DaysInterval
-------------        ------------
2026-11-21T23:00:00Z            1

Repare no StartBoundary: ele saiu 2026-11-21T23:00:00Z. O Z no fim quer dizer UTC, o horário de referência mundial. As 20h do horário de Brasília (UTC-3) são 23h em UTC. A tarefa roda às 20h do seu relógio; só a forma de guardar o horário é que muda.

4. Controlando a tarefa

Start-ScheduledTask -TaskName "Backup diário"      # roda agora, para testar
Disable-ScheduledTask -TaskName "Backup diário"    # pausa
Enable-ScheduledTask -TaskName "Backup diário"     # reativa
Unregister-ScheduledTask -TaskName "Backup diário" -Confirm:$false   # remove
Dicas para scripts agendados Use caminhos completos (o script não roda "na pasta certa"), grave um log do que aconteceu e teste com Start-ScheduledTask antes de confiar. Para rodar mesmo sem ninguém logado, a tarefa precisa de uma conta com senha (-User e -Password) ou da conta SYSTEM, o que exige administrador.

Experimente: escreva, numa string, o comando que monta (sem registrar) um gatilho diário às 20h. O simulador do guia não imita esse comando; depois, rode-o de verdade no seu Windows. Lembre que o StartBoundary aparece em UTC.

# Escreva o comando numa string. Não chame o cmdlet.
$comando = ''
Write-Output $comando

# Escreva o comando numa string. Não chame o cmdlet.
$comando = 'New-ScheduledTaskTrigger -Daily -At "20:00"'
Write-Output $comando

Quando dá errado

LastTaskResult diferente de 0

O script deu erro. Rode o mesmo comando da ação no terminal para ver a mensagem, e confira caminhos relativos e a política de execução (use -ExecutionPolicy Bypass no argumento se necessário).

"Acesso negado" ao registrar

Tarefas que rodam como SYSTEM, com privilégios elevados ou para outros usuários exigem PowerShell como administrador.

A tarefa roda mas abre uma janela

Acrescente -WindowStyle Hidden nos argumentos do pwsh.exe.

Resumo

  • Tarefas agendadas rodam scripts sozinhas.
  • Monte com ação + gatilho e grave com Register-ScheduledTask.
  • Get-ScheduledTaskInfo mostra se deu certo (LastTaskResult = 0).
  • Use caminhos completos e grave logs nos scripts agendados.

Projeto: Consultando uma API (CEP)

Neste projeto você cria a função Get-Endereco, que recebe um ou vários CEPs e devolve o endereço de cada um, consultando o serviço gratuito ViaCEP. É o tipo de ferramenta que resolve um problema real: completar uma planilha de clientes com rua, bairro e cidade.

Você vai aprender
  • A validar a entrada com regex antes de chamar a API.
  • A consultar a API com Invoke-RestMethod e montar um objeto limpo.
  • A tratar CEP inexistente e falha de rede.
  • A receber vários CEPs pelo pipeline.
  • A evitar consultas repetidas com um cache em hashtable e exportar para CSV.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

2. Validando e tratando erros

O ViaCEP responde de jeitos diferentes para cada problema: um CEP com formato errado dá erro HTTP 400, e um CEP que não existe volta com o campo erro. A função precisa cuidar dos dois:

PS> function Get-Endereco { param([string]$Cep)
>>     $limpo = $Cep -replace '\D', ''
>>     if ($limpo -notmatch '^\d{8}$') { return [pscustomobject]@{ CEP = $Cep; Status = "Formato inválido" } }
>>     try { $r = Invoke-RestMethod "https://viacep.com.br/ws/$limpo/json/" -TimeoutSec 10 }
>>     catch { return [pscustomobject]@{ CEP = $Cep; Status = "Falha na consulta" } }
>>     if ($r.erro) { return [pscustomobject]@{ CEP = $Cep; Status = "Não encontrado" } }
>>     [pscustomobject]@{ CEP = $r.cep; Status = "OK"; Rua = $r.logradouro; Bairro = $r.bairro; Cidade = $r.localidade; UF = $r.uf }
>> }
PS> (Get-Endereco "123").Status
Formato inválido
PS> (Get-Endereco "99999-999").Status
Não encontrado
PS> (Get-Endereco "20040020").Cidade
Rio de Janeiro
-notmatch '^\d{8}$'
Se não sobrarem exatamente 8 dígitos, nem chama a API.
-TimeoutSec 10
Desiste depois de 10 segundos sem resposta.
catch { ... }
Sem internet, ou a API fora do ar: devolve um objeto com o status, em vez de parar tudo.
$r.erro
CEP com formato certo mas que não existe.

Devolver sempre um objeto (com Status) em vez de mostrar erros deixa o resultado fácil de filtrar depois.

3. Vários CEPs pelo pipeline e cache

PS> $Cache = @{}
PS> function Get-Endereco {
>>     param([Parameter(ValueFromPipeline)][string]$Cep)
>>     process {
>>         $limpo = $Cep -replace '\D', ''
>>         if ($Cache.ContainsKey($limpo)) { return $Cache[$limpo] }
>>         if ($limpo -notmatch '^\d{8}$') { return [pscustomobject]@{ CEP = $Cep; Status = "Formato inválido"; Cidade = $null; UF = $null } }
>>         try { $r = Invoke-RestMethod "https://viacep.com.br/ws/$limpo/json/" -TimeoutSec 10 }
>>         catch { return [pscustomobject]@{ CEP = $Cep; Status = "Falha na consulta"; Cidade = $null; UF = $null } }
>>         $obj = if ($r.erro) { [pscustomobject]@{ CEP = $Cep; Status = "Não encontrado"; Cidade = $null; UF = $null } }
>>                else { [pscustomobject]@{ CEP = $r.cep; Status = "OK"; Cidade = $r.localidade; UF = $r.uf } }
>>         $Cache[$limpo] = $obj
>>         $obj
>>     }
>> }
PS> "01310-100", "20040-020", "70040-010", "abc", "01310100" | Get-Endereco | Format-Table -AutoSize

CEP       Status           Cidade         UF
---       ------           ------         --
01310-100 OK               São Paulo      SP
20040-020 OK               Rio de Janeiro RJ
70040-010 OK               Brasília       DF
abc       Formato inválido                
01310-100 OK               São Paulo      SP
PS> $Cache.Count
3

O CEP 01310100 apareceu duas vezes, mas só foi consultado uma: a segunda resposta veio do cache. O "abc" nem foi para o cache.

4. Exportando

PS> "01310-100", "20040-020", "70040-010" | Get-Endereco | Where-Object Status -eq "OK" | Export-Csv enderecos.csv -Delimiter ';'
PS> Get-Content enderecos.csv
"CEP";"Status";"Cidade";"UF"
"01310-100";"OK";"São Paulo";"SP"
"20040-020";"OK";"Rio de Janeiro";"RJ"
"70040-010";"OK";"Brasília";"DF"

Para completar uma planilha de clientes: Import-Csv clientes.csv -Delimiter ';' | ForEach-Object { $_.CEP } | Get-Endereco.

Experimente: complete a validação: se o CEP limpo não tiver exatamente 8 dígitos, mostre Formato inválido.

function Test-Cep { param([string]$Cep)
    $limpo = $Cep -replace '\D', ''
    "OK"
}
Test-Cep "123"

function Test-Cep { param([string]$Cep)
    $limpo = $Cep -replace '\D', ''
    if ($limpo -notmatch '^\d{8}$') { return "Formato inválido" }
    "OK"
}
Test-Cep "123"

Resumo

  • Valide a entrada antes de chamar a API.
  • Devolva sempre um objeto com Status, mesmo quando der errado.
  • ValueFromPipeline + process { } processam vários CEPs.
  • Um cache em hashtable evita consultas repetidas; Export-Csv fecha o trabalho.

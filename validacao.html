Validando Parâmetros

Em vez de encher a função de if para conferir os valores, você pode colocar a regra no próprio parâmetro. O PowerShell confere antes de rodar a função e recusa o que não serve, com uma mensagem clara.

Você vai aprender
  • A aceitar só alguns valores com [ValidateSet()] (e ganhar Tab de brinde).
  • A limitar números com [ValidateRange()].
  • A limitar o tamanho de um texto com [ValidateLength()].
  • A exigir um formato com [ValidatePattern()].
  • A recusar vazio com [ValidateNotNullOrEmpty()] e a criar sua regra com [ValidateScript()].

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional. Os quadros marcados Saída no Windows (PowerShell 7.7) foram colhidos num Windows 10 em português, com o nome do computador e o da usuária trocados por exemplos (NOTEBOOK e ana).

A ideia: o porteiro

O porteiro do prédio confere o documento antes de deixar entrar. Se não serve, a pessoa nem chega ao elevador. Os atributos Validate são porteiros dos parâmetros: a função só roda se todos os valores passarem.

1. [ValidateSet()]: só da lista

PS> function Set-Tamanho {
>>   param([ValidateSet("P", "M", "G")][string]$Tamanho)
>>   "Camiseta tamanho $Tamanho"
>> }
PS> Set-Tamanho M
Camiseta tamanho M

PS> Set-Tamanho GG
Set-Tamanho: Não é possível validar o argumento no parâmetro 'Tamanho'. The argument "GG" does not belong to the set "P;M;G" specified by the ValidateSet attribute. Supply an argument that is in the set and then try the command again.
[ValidateSet("P", "M", "G")]
Só aceita um desses valores (sem diferenciar maiúsculas).
Set-Tamanho GG
Recusado antes de a função rodar. A mensagem de erro diz o parâmetro (Tamanho) e lista os valores que servem: P;M;G.

De brinde: no console, Set-Tamanho + Tab passa pelos valores P, M e G.

2. [ValidateRange()]: números num intervalo

PS> function Set-Nota { param([ValidateRange(0, 10)][int]$Nota) "Nota $Nota registrada" }
PS> Set-Nota 8
Nota 8 registrada

PS> Set-Nota 11
Set-Nota: Não é possível validar o argumento no parâmetro 'Nota'. The 11 argument is greater than the maximum allowed range of 10. Supply an argument that is less than or equal to 10 and then try the command again.

O 11 é recusado: a mensagem diz que ele é maior que o máximo permitido, 10.

3. [ValidateLength()] e [ValidatePattern()]

PS> function New-Login {
>>   param(
>>     [ValidateLength(3, 12)]
>>     [ValidatePattern("^[a-z0-9]+$")]
>>     [string]$Login
>>   )
>>   "Login $Login criado"
>> }
PS> New-Login ana2026
Login ana2026 criado

PS> New-Login an
New-Login: Não é possível validar o argumento no parâmetro 'Login'. The character length (2) of the argument is too short. Specify an argument with a length that is greater than or equal to "3", and then try the command again.
PS> New-Login "Ana Souza"
New-Login: Não é possível validar o argumento no parâmetro 'Login'. The argument "Ana Souza" does not match the "^[a-z0-9]+$" pattern. Supply an argument that matches "^[a-z0-9]+$" and try the command again.

O an é recusado por ser curto demais (2 caracteres, o mínimo é 3). O "Ana Souza" tem tamanho bom, mas é recusado pelo formato: tem maiúscula e espaço.

[ValidateLength(3, 12)]
Entre 3 e 12 caracteres.
[ValidatePattern("^[a-z0-9]+$")]
Só letras minúsculas e números, do começo ao fim (aula Expressões Regulares).

Experimente: aceite só os sabores uva, laranja e limao com [ValidateSet()]. A chamada Get-Suco uva deve mostrar Sabor: uva.

function Get-Suco {
    param([string]$Sabor)
    "Sabor: $Sabor"
}
Get-Suco uva

function Get-Suco {
    param([ValidateSet("uva", "laranja", "limao")][string]$Sabor)
    "Sabor: $Sabor"
}
Get-Suco uva

4. Vazio não: [ValidateNotNullOrEmpty()]

PS> function Send-Recado { param([ValidateNotNullOrEmpty()][string]$Texto) "Enviado: $Texto" }
PS> Send-Recado "Chego às 8"
Enviado: Chego às 8

PS> Send-Recado ""
Send-Recado: Não é possível validar o argumento no parâmetro 'Texto'. The argument is null or empty. Provide an argument that is not null or empty, and then try the command again.

O texto vazio é recusado com um erro dizendo que o argumento é nulo ou vazio.

5. Sua regra: [ValidateScript()]

Para regras que nenhum atributo pronto cobre, escreva um bloco que devolve True ou False. Dentro dele, $_ é o valor recebido:

PS> function Set-Par { param([ValidateScript({ $_ % 2 -eq 0 })][int]$Numero) "Par: $Numero" }
PS> Set-Par 4
Par: 4

PS> Set-Par 5
Set-Par: Não é possível validar o argumento no parâmetro 'Numero'. The " $_ % 2 -eq 0 " validation script for the argument with value "5" did not return a result of True. Determine why the validation script failed, and then try the command again.

Com o 5, a mensagem de erro mostra o próprio bloco que falhou, o que não é muito amigável. No PowerShell 7 dá para trocar por uma mensagem sua com ErrorMessage, onde {0} vira o valor recebido:

PS> function Set-Par2 { param([ValidateScript({ $_ % 2 -eq 0 }, ErrorMessage = "{0} não é par")][int]$Numero) "Par: $Numero" }
PS> Set-Par2 7
Set-Par2: Não é possível validar o argumento no parâmetro 'Numero'. 7 não é par

Agora o erro termina com a sua frase: 7 não é par.

Referência rápida

AtributoAceita só
[ValidateSet("a", "b")]Valores da lista.
[ValidateRange(1, 10)]Números de 1 a 10.
[ValidateLength(3, 12)]Textos de 3 a 12 letras.
[ValidatePattern("^\d+$")]Textos que casam com a regex.
[ValidateNotNullOrEmpty()]Qualquer coisa, menos vazio.
[ValidateScript({ ... })]O que o bloco aprovar.

Resumo

  • Atributos Validate conferem os valores antes da função rodar.
  • ValidateSet (lista), ValidateRange (números), ValidateLength (tamanho), ValidatePattern (formato).
  • ValidateNotNullOrEmpty recusa vazio; ValidateScript aplica sua regra.
  • A mensagem de erro já diz o que estava errado.

try, catch e finally

Com try e catch você avisa o PowerShell: "tente fazer isto; se der errado, faça aquilo em vez de mostrar o erro em vermelho". E o finally roda no fim, dando certo ou errado.

Você vai aprender
  • A estrutura try { } catch { } finally { }.
  • A usar $_ dentro do catch para ler o erro.
  • A ter um catch diferente para cada tipo de erro.
  • O que o finally garante.
  • Por que alguns erros "passam reto" pelo catch.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: a rede do trapezista

O trapezista tenta o salto (try). Se escorregar, cai na rede (catch) em vez de no chão. E, dando certo ou errado, no fim ele agradece ao público (finally).

1. O básico

PS> try {
>>   $r = 10 / 0
>>   "Esta linha não roda"
>> }
>> catch {
>>   "Deu erro, mas eu tratei."
>> }
Deu erro, mas eu tratei.
try { ... }
O código que pode dar erro.
catch { ... }
Roda só se algo no try der um erro que encerra. O resto do try, depois do erro, é pulado.

2. Lendo o erro com $_

Dentro do catch, a variável $_ é o erro que aconteceu:

PS> try { [int]"dez" }
>> catch { "Não consegui converter. Motivo: $($_.Exception.Message)" }
Não consegui converter. Motivo: Cannot convert value "dez" to type "System.Int32". Error: "The input string 'dez' was not in a correct format."

PS> try { 1 / 0 } catch { $_.Exception.GetType().Name }
RuntimeException

Experimente: o código divide por zero sem proteção. Coloque a conta dentro de um try e, no catch, mostre Problema: seguido da mensagem do erro.

$total = 100
$pessoas = 0
$total / $pessoas

$total = 100
$pessoas = 0
try { $total / $pessoas } catch { "Problema: $($_.Exception.Message)" }

3. finally: sempre roda

PS> function Dividir { param([int]$a, [int]$b)
>>   try { $a / $b }
>>   catch { "Erro: não dá para dividir por zero." }
>>   finally { "--- conta encerrada ---" }
>> }
PS> Dividir 10 2
5
--- conta encerrada ---
PS> Dividir 10 0
Erro: não dá para dividir por zero.
--- conta encerrada ---

Use o finally para arrumar a casa: fechar uma conexão, apagar um arquivo temporário, mostrar uma mensagem de fim.

4. Um catch para cada tipo

Você pode escrever o tipo da exceção depois do catch. O primeiro que combinar é o que roda:

PS> function Testar { param($valor)
>>   try { 100 / [int]$valor }
>>   catch [System.DivideByZeroException] { "Zero não vale." }
>>   catch [System.Management.Automation.RuntimeException] { "Isso não é número." }
>>   catch { "Outro erro qualquer." }
>> }
PS> Testar 4
25
PS> Testar 0
Zero não vale.
PS> Testar "abc"
Isso não é número.

O PowerShell embrulha a divisão por zero numa exceção que "contém" a DivideByZeroException, por isso o primeiro catch pega. Deixe sempre um catch sem tipo por último, para o que você não previu.

5. Erros que passam reto

O catch só pega erros que encerram. Muitos cmdlets, quando falham num item, dão um erro que não encerra: o erro aparece em vermelho e o catch nem fica sabendo. A solução é pedir -ErrorAction Stop ao comando, que transforma o erro em um que encerra. Isso está na aula -ErrorAction.

try { Get-Item "nao-existe.txt" } catch { "Peguei!" }
try { Get-Item "nao-existe.txt" -ErrorAction Stop } catch { "Peguei!" }

No primeiro, o erro do Get-Item aparece normalmente e o catch não roda. No segundo, com -ErrorAction Stop, aparece só Peguei!.

Quando dá errado

Esperar que o resto do try rode depois do erro

Quando um erro acontece no meio do try, o PowerShell pula direto para o catch. As linhas que vinham depois do erro, dentro do try, não rodam. Se uma linha precisa rodar sempre, coloque no finally ou depois do bloco todo.

catch vazio

Um catch { } vazio engole o erro em silêncio, e você nunca vai saber que algo deu errado. No mínimo, mostre a mensagem: catch { Write-Warning $_.Exception.Message }.

Referência rápida

Você digitaO que faz
try { } catch { }Tenta; se der erro que encerra, roda o catch.
$_ (no catch)O erro capturado.
$_.Exception.MessageO texto do erro.
catch [Tipo] { }Pega só aquele tipo de exceção.
finally { }Roda sempre, com ou sem erro.
-ErrorAction StopFaz o erro de um cmdlet poder ser pego pelo catch.

Exercícios

1. A variável do catch

Complete para mostrar a mensagem do erro:

catch { $.Exception.Message }

2. Qual bloco roda sempre, com ou sem erro?

3. Se a 1ª linha de um try der erro, a 2ª linha do try...

Missão final: complete o código: tente converter $entrada com [int]; se der erro, mostre Valor inválido: abc; e, no finally, mostre Fim da leitura.

$entrada = "abc"
[int]$entrada

$entrada = "abc"
try { [int]$entrada }
catch { "Valor inválido: $entrada" }
finally { "Fim da leitura" }

Resumo

  • try tenta, catch trata, finally sempre roda.
  • No catch, $_ é o erro e $_.Exception.Message é o texto dele.
  • Dá para ter um catch por tipo de exceção; deixe um genérico no fim.
  • O catch só pega erros que encerram: use -ErrorAction Stop nos cmdlets.

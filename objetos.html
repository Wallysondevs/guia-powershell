Tudo É Objeto

No cmd e no Bash, o que um comando devolve é texto: linhas na tela. No PowerShell é diferente: o que vem é um objeto, uma "ficha" com campos que você pode ler um por um. Esta é a ideia mais importante do Nível 2, e o resto do nível se apoia nela.

Você vai aprender
  • O que é um objeto: uma ficha com propriedades (dados) e métodos (ações).
  • A ler uma propriedade com o ponto: $texto.Length.
  • A chamar um método com parênteses: $texto.ToUpper().
  • A descobrir o tipo de qualquer coisa com .GetType().
  • Por que "objeto em vez de texto" deixa o trabalho mais fácil.

As saídas desta aula foram colhidas no PowerShell 7.7 rodando no Linux, com o idioma em português (pt-BR), num console de 80 colunas. Os comandos funcionam do mesmo jeito no PowerShell 7 do Windows; a aula só mostra saídas que não dependem do sistema operacional.

A ideia: a ficha do cadastro

Pense na ficha de cadastro de uma loja. Ela tem campos: nome, cidade, idade. Você não precisa ler a ficha inteira e "procurar" a idade no meio do texto: basta olhar o campo idade. Os objetos do PowerShell são assim. Cada campo é uma propriedade, e algumas fichas também sabem fazer coisas, os métodos.

1. Até um texto é um objeto

Um texto simples já é um objeto. Ele tem a propriedade Length (o tamanho) e métodos como ToUpper() (tudo em maiúsculas):

PS> $nome = "Ana Souza"
PS> $nome.Length
9
PS> $nome.ToUpper()
ANA SOUZA
PS> $nome.Replace("Souza", "Lima")
Ana Lima
$nome.Length
Uma propriedade: um dado que o objeto já tem. Sem parênteses.
$nome.ToUpper()
Um método: uma ação que o objeto sabe fazer. Sempre com parênteses, mesmo vazios.
.Replace("Souza", "Lima")
Um método que recebe valores entre os parênteses: o que trocar e pelo quê.
O texto original não mudou: $nome.ToUpper() devolve um texto novo. $nome continua Ana Souza.

Experimente: mostre quantas letras tem a palavra guardada em $palavra, usando a propriedade Length.

$palavra = "PowerShell"

$palavra = "PowerShell"
$palavra.Length

2. Qual é o tipo? .GetType()

Todo objeto tem um tipo: o "modelo de ficha" de onde ele saiu. O método GetType() mostra qual é. A coluna Name é o nome curto do tipo:

PS> "Ana".GetType().Name
String
PS> (42).GetType().Name
Int32
PS> (3.5).GetType().Name
Double
PS> $true.GetType().Name
Boolean
PS> (Get-Date).GetType().Name
DateTime
String
Texto.
Int32
Número inteiro (o [int]).
Double
Número com casas decimais.
Boolean
Verdadeiro ou falso.
DateTime
Data e hora: o que o Get-Date devolve.
(42).GetType()
Os parênteses em volta do número são necessários: sem eles, o PowerShell leria 42.GetType como um número mal escrito.

3. Uma data é uma ficha cheia de campos

O Get-Date devolve um objeto DateTime. Em vez de recortar o texto da data, você pede o campo que quer:

PS> $d = Get-Date -Year 2026 -Month 3 -Day 15 -Hour 9 -Minute 30 -Second 0
PS> $d.Day
15
PS> $d.Month
3
PS> $d.Year
2026
PS> $d.DayOfWeek
Sunday
PS> $d.AddDays(10).ToString("dd/MM/yyyy")
25/03/2026
$d.Day, $d.Month, $d.Year
Propriedades: o dia, o mês e o ano, cada um num campo.
$d.DayOfWeek
O dia da semana. Repare que vem em inglês (Sunday): é um valor do .NET, não um texto traduzido.
.AddDays(10)
Um método que devolve uma nova data, 10 dias depois.
.ToString("dd/MM/yyyy")
Transforma a data em texto, no formato que você escolher.

4. Objeto × texto: por que isso importa

No mundo do texto, para pegar "o terceiro pedaço" de uma linha você precisa recortar letras e torcer para o formato não mudar. Com objetos, você pede o campo pelo nome. Compare:

PS> $linha = "Ana;Recife;30"
PS> $linha.Split(";")[2]
30
PS> $pessoa = [pscustomobject]@{ Nome = "Ana"; Cidade = "Recife"; Idade = 30 }
PS> $pessoa.Idade
30
PS> $pessoa

Nome Cidade Idade
---- ------ -----
Ana  Recife    30
$linha.Split(";")[2]
Jeito "texto": cortar no ; e pegar a terceira parte (a contagem começa no 0). Funciona, mas quebra se a ordem mudar.
[pscustomobject]@{ ... }
Cria um objeto seu, com os campos que você quiser. Você vai ver isso com calma na aula Seus Objetos.
$pessoa.Idade
Jeito "objeto": o campo tem nome. Não importa a ordem.
$pessoa
Quando um objeto vai para a tela, o PowerShell monta uma tabela com os campos.

Esse é o motivo de existir o pipeline do PowerShell: os comandos passam fichas inteiras de um para o outro, e não linhas de texto.

Quando dá errado

Propriedade que não existe: nada aparece 
PS> $nome = "Ana"
PS> $nome.Tamanho
PS> $nome.Length
3

O PowerShell não reclama de uma propriedade que não existe: ele devolve $null (nada) e a tela fica em branco. Se uma propriedade "não mostrou nada", confira o nome. A aula Get-Member mostra como ver a lista certa.

Método que não existe: aí sim é erro 
PS> $nome.Maiusculas()
InvalidOperation: Method invocation failed because [System.String] does not contain a method named 'Maiusculas'.
InvalidOperation
A categoria do erro: uma operação que não dá para fazer.
does not contain a method named 'Maiusculas'
O texto (String) não tem nenhum método com esse nome. O certo é ToUpper().
Esquecer os parênteses do método 
PS> $nome.ToUpper

OverloadDefinitions
-------------------
string ToUpper()
string ToUpper(cultureinfo culture)

Sem os parênteses, o PowerShell não roda o método: ele mostra a "assinatura" dele (o que o método recebe e o que devolve). Não é erro, mas também não é o que você queria. Coloque os parênteses: $nome.ToUpper().

Referência rápida

Você digitaO que faz
$obj.PropriedadeLê um campo do objeto.
$obj.Metodo()Pede ao objeto para fazer algo (sempre com parênteses).
$obj.Metodo(valor)Método que recebe valores.
$obj.GetType().NameMostra o tipo do objeto.
(42).GetType()Número precisa de parênteses antes do ponto.

Resumo

  • No PowerShell, o que os comandos devolvem são objetos, não linhas de texto.
  • Propriedade = dado: $obj.Length. Método = ação, com parênteses: $obj.ToUpper().
  • .GetType().Name mostra o tipo: String, Int32, Double, Boolean, DateTime…
  • Propriedade inexistente devolve $null (tela vazia). Método inexistente dá erro.
  • Por ter campos com nome, um objeto não depende de recortar texto.

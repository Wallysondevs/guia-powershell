PowerShell Comparações (-eq, -ne, -gt, -lt)

A nota é maior que 7? O estoque é menor que 5? O nome é igual a "Ana"? Antes de decidir, o script compara. No PowerShell, as comparações usam palavrinhas com tracinho, como -eq e -gt.

Você vai aprender
  • Os operadores -eq, -ne, -gt, -ge, -lt e -le.
  • Por que o PowerShell usa letras (-gt) em vez de >.
  • Que -eq não diferencia maiúsculas, e como diferenciar com -ceq.
  • Que, com uma lista à esquerda, a comparação filtra a lista.
  • O erro real de digitar o operador errado.

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows em português.

A ideia: a balança

Comparar é pôr dois valores numa balança e perguntar: são iguais? Este é maior? A resposta é sempre True (verdadeiro) ou False (falso). É essa resposta que o if usa para decidir (aula if).

1. Números

PS C:\Users\ana> 5 -eq 5
True
PS C:\Users\ana> 5 -ne 3
True
PS C:\Users\ana> 5 -gt 3
True
PS C:\Users\ana> 5 -ge 5
True
PS C:\Users\ana> 5 -lt 10
True
PS C:\Users\ana> 5 -le 4
False
OperadorQuer dizer
-eqigual (equal)
-nediferente (not equal)
-gtmaior que (greater than)
-gemaior ou igual (greater or equal)
-ltmenor que (less than)
-lemenor ou igual (less or equal)
Por que não > e =? No PowerShell, > já tem outro trabalho: mandar a saída para um arquivo. E = guarda valor numa variável. Por isso as comparações usam letras com tracinho.

Experimente: com 16 anos já pode votar. Troque -gt por -ge (maior ou igual).

$idade = 16
if ($idade -gt 16) { "Pode votar" } else { "Ainda não" }

$idade = 16
if ($idade -ge 16) { "Pode votar" } else { "Ainda não" }

2. Texto: -eq não diferencia maiúsculas

PS C:\Users\ana> "Ana" -eq "ana"
True
PS C:\Users\ana> "Ana" -ne "Beto"
True
PS C:\Users\ana> "Ana" -ceq "ana"
False
PS C:\Users\ana> "Ana" -ieq "ANA"
True

Por padrão, "Ana" e "ana" são iguais. Para diferenciar maiúsculas, ponha um c (case-sensitive): -ceq, -cne, -cgt… O i (-ieq) deixa explícito que não diferencia, igual ao normal.

3. Com lista, a comparação filtra

PS C:\Users\ana> 1, 2, 3, 2, 5 -eq 2
2
2
PS C:\Users\ana> 1, 2, 3, 2, 5 -gt 2
3
5

Quando há uma lista à esquerda, o resultado não é True/False: é a lista dos itens que passaram no teste. Para perguntar "a lista tem esse item?", use -contains (aula -contains e -in).

Quando dá errado

Digitou o operador errado 
PS C:\Users\ana> 5 -eg 5
ParserError:
Line |
   1 |  5 -eg 5
     |    ~~~
     | Unexpected token '-eg' in expression or statement.
ParserError
Erro de "leitura": o PowerShell nem chegou a rodar o comando, porque não entendeu como ele foi escrito.
Line | 1 … ~~~
A linha com o problema; os ~~~ sublinham o pedaço errado.
Unexpected token '-eg'
"Pedaço inesperado: -eg." Não existe -eg; era -eq (com Q).

Repare que essa mensagem veio em inglês, mesmo com o Windows em português. No PowerShell 7.7, os erros de sintaxe (do jeito de escrever) saem em inglês; os erros de comando (como "O termo … não é reconhecido") saem em português.

Como resolver: 5 -eq 5.

Usou = para comparar

if ($nota = 10) não compara: guarda 10 em $nota, e o if sempre entra. Veja a explicação completa na aula if. Use -eq.

Exercícios

1. Diferente

Complete para perguntar se $a é diferente de 3:

$a 3

2. Menor ou igual

Complete para "$preco menor ou igual a 50":

$preco 50

3. O que "Ana" -eq "ANA" mostra?

4. O que 1, 5, 8 -gt 4 mostra?

Missão final: mostre Estoque baixo quando $estoque for menor que 10.

$estoque = 4

$estoque = 4
if ($estoque -lt 10) { "Estoque baixo" }

Resumo

  • -eq -ne -gt -ge -lt -le respondem True ou False.
  • Com texto, -eq não diferencia maiúsculas; -ceq diferencia.
  • Com uma lista à esquerda, o operador filtra.
  • Erro de sintaxe (ParserError) sai em inglês no 7.7.

Variáveis de Ambiente ($env:)

O Windows guarda algumas informações em variáveis de ambiente: o nome do usuário, a pasta temporária, as pastas onde procurar programas (o famoso PATH). Todo programa pode ler essas variáveis, e o PowerShell lê e altera com o prefixo $env:.

Você vai aprender
  • A ler variáveis com $env:NOME.
  • A listar todas com Get-ChildItem Env:.
  • A criar e mudar variáveis só nesta sessão.
  • A gravar de forma permanente para o seu usuário.
  • A acrescentar uma pasta ao PATH com segurança.

As saídas desta aula foram colhidas no PowerShell 7.7 de um Windows 10 em português (pt-BR), numa pasta de testes dentro do TEMP. O nome do computador e o da usuária foram trocados por exemplos (NOTEBOOK e ana), e listas que mostrariam os programas instalados foram reduzidas aos itens do próprio Windows.

A ideia: o quadro de avisos

As variáveis de ambiente são um quadro de avisos que o Windows pendura para todos os programas lerem: "o usuário é a Ana", "a pasta temporária fica ali", "procure programas nestas pastas".

1. Lendo

PS> $env:USERNAME
ana
PS> $env:COMPUTERNAME
NOTEBOOK
PS> $env:OS
Windows_NT
PS> Test-Path $env:TEMP
True
$env:NOME
Lê a variável de ambiente NOME. Maiúsculas e minúsculas tanto faz.
$env:TEMP
Pasta temporária do usuário.

2. Listando todas

Env: é uma "unidade" como C:, com uma variável em cada item:

PS> Get-ChildItem Env: | Select-Object -First 5 Name

Name
----
ALLUSERSPROFILE
APPDATA
CommonProgramFiles
CommonProgramFiles(x86)
CommonProgramW6432
PS> (Get-ChildItem Env:).Count
46

3. O PATH

O PATH é a lista de pastas onde o Windows procura programas quando você digita um nome como notepad ou git. As pastas são separadas por ponto e vírgula:

PS> ($env:PATH -split ';').Count
12
PS> $env:PATH -split ';' | Where-Object { $_ -like '*PowerShell*' }
C:\Users\ana\AppData\Local\Microsoft\WindowsApps\Microsoft.PowerShell_8wekyb3d8bbwe
C:\Windows\System32\WindowsPowerShell\v1.0\

4. Mudando só nesta sessão

PS> $env:MEU_AMBIENTE = "teste"
PS> $env:MEU_AMBIENTE
teste
PS> pwsh -NoProfile -Command '"O filho vê: $env:MEU_AMBIENTE"'
O filho vê: teste
PS> Remove-Item Env:MEU_AMBIENTE
PS> $null -eq $env:MEU_AMBIENTE
True
$env:X = "..."
Cria ou muda a variável nesta janela e nos programas abertos a partir dela.
Remove-Item Env:X
Apaga a variável (também funciona $env:X = $null).

Ao fechar a janela, a mudança some.

5. Gravando de forma permanente

Para valer em todas as janelas novas, grave no escopo do usuário:

[Environment]::SetEnvironmentVariable("EDITOR", "code", "User")
[Environment]::GetEnvironmentVariable("EDITOR", "User")
"User"
Grava para o seu usuário (não precisa de administrador).
"Machine"
Grava para o computador todo (precisa de administrador).
"Process"
Igual a $env:, só esta sessão.

Janelas que já estavam abertas não veem a mudança: abra uma nova.

6. Acrescentando uma pasta ao PATH

$pasta = "$HOME\bin"
$atual = [Environment]::GetEnvironmentVariable("Path", "User")
if (($atual -split ';') -notcontains $pasta) {
    [Environment]::SetEnvironmentVariable("Path", "$atual;$pasta", "User")
}
Não sobrescreva o PATH Nunca faça SetEnvironmentVariable("Path", "C:\minha-pasta", "User"): isso apaga todas as outras pastas. Sempre leia o valor atual e acrescente.

Experimente: crie a variável de ambiente MEU_AMBIENTE com o valor teste e mostre o valor.




$env:MEU_AMBIENTE = "teste"
$env:MEU_AMBIENTE










Quando dá errado




A variável está vazia


$env:NOME_ERRADO não dá erro: devolve vazio. Confira o nome com Get-ChildItem Env:.







Mudei o PATH e o comando continua "não reconhecido"


A janela atual guardou o PATH antigo. Abra uma janela nova (ou atualize: $env:PATH = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")).







Variável com espaço ou parênteses no nome


Use chaves: ${env:ProgramFiles(x86)}.
